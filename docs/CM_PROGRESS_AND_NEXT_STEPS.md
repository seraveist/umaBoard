## 1. 현재 완성된 사용자 흐름

1. **육성 전 준비**에서 육성마 의상·각질·레이스 조건·SSR 최대6장·시나리오를 설정한다.
2. **1차 마신표**를 생성해 스킬별 기여와 준비할 후보를 확인한다.
3. **육성 후 추천**으로 전환해 같은 목록에 실제 습득·구매 가능 여부·힌트를 기록한다.
4. 실제 스탯5종·남은SP·할인 특성·적성을 입력하고 추가 구매 조합을 추천받는다.
5. 게임에서 구매한 뒤 습득 기록을 직접 갱신하고 필요하면 다시 추천한다.
   마신표와 최종 결과는 각각 JSON으로 내보낼 수 있다.

추천 실행 자체는 습득 상태를 변경하지 않는다. 단계 이동·검색·탭 전환은 같은
체크리스트를 사용하며, 레이스·편성 변경은 새로운 마신표 생성을 요구한다.

## 2. 누적 구현·수정 내역

### 2.1 육성 전 준비와 1차 마신표

- 시나리오 기본 상한, 최상 컨디션, 적성A와 보유 의상의 개화·고유기 레벨을
  기준으로 계산한다. 시나리오 기본 상한에 계승 상승분을 미리 더하지 않는다.
- 레어·일반·회복·계승을 1차 목록에서 비교한다. 진화 분기는 내부 후보로 보존하고 최종 추천에서 비교한다.
  육성 전SP 입력과 필요 스태미나 안내는 두지 않는다.
- 레어는 선택한 육성마·편성·시나리오의 획득 경로를 사용한다. 일반 인자 후보는
  인자 적격 조건과 현재 확보 가능한 계열을 구분해 구성한다.
- 계승은 각질 적합성·중복 계열·강화형을 반영해 양의 기여를 가진 Top10을
  기본 표시한다. 전체 계승 후보에서 순수 회복·비활성 소유 도우미와 Top10 밖 실제 확보도
  기록하고 최종 계산한다. 확보는 전체 목록에서 최대6개다.
- 기본 비교는 공통9개 전개·144표본·0.01초 간격의 전개 평균 마신이다. 자기 횟수·HP·보유 조건과
  지능/추첨 실패를 반영하고, 게이트·인기는 실제 값 또는 명시된 균등 가정을 사용한다.
  회복은 직접 마신이0이어도 일반 후보에서 유지한다.

### 2.2 스킬 목록·정렬·아이콘

- 1차 목록은 **레어 → 일반** 순서로 표시한다. 진화 분기는 최종 결과의 별도 영역에 표시한다.
- 하위 단계 들여쓰기는 PC16px·좁은 화면8px이다. 검색·카테고리 필터에서도
  원래 계열 깊이와 정렬을 유지한다.
- 아이콘 카테고리 탭, 이름 검색, 스크롤 목록과 마우스·키보드·터치 상세 설명을 제공한다.
- 스킬명 우측에 레어·진화 배지만 표시하고 일반 배지는 숨긴다.
  하단에는 각성·서포트 힌트/이벤트·시나리오·계승 등 현재 설정의 가능한 경로를 표시한다.
  추정 경로는 실제 획득 사실과 구분한다.
- 전체2,236개 스킬의 아이콘 연결을 점검했고 로컬 PNG128개를 사용한다.
  진화에 레어/일반 아이콘을 잘못 빌려 쓰던 연결과 누락 이미지를 수정했다.
  이미지별 출처·해시를 보존한다. [아이콘 QA](SKILL_ICON_QA.md)

### 2.3 습득 연동·힌트·일괄 처리

- 획득 상태는 **습득 / 미획득 / 획득 / 할인 Lv1~Lv5**다.
  획득은 아직 구매하지 않았고 힌트 할인이 없는 상태다.
- 상위 습득 시 검증된 모든 하위를 자동 습득한다.
  하위를 미획득으로 바꾸면 연결된 상위·진화를 해제한다.
- 같은 원본 레어에서 나온 진화는 한쪽 습득 시 반대쪽을 미획득으로 바꾸고
  공통 하위의 습득은 유지한다. 힌트 지정만으로 구매를 처리하지 않는다.
- 전체 미획득·전체 할인Lv5는 현재 검색/탭과 관계없이 전체 목록에 적용한다.
  계승 일괄 설정은 기존 확보를 우선하고 최대6개를 유지한다.

### 2.4 실제 육성 결과와 최종 추천

- 실제 스탯은 게임 표시값1~3000을 그대로 입력한다.1200 초과 보정은 모델에서 처리한다.
  SP는 **현재 남은SP**이며, 실제 적성을 반영하고 시나리오 상한으로 입력값을 자르지 않는다.
- 할인 특성은 **없음0% / 공부가4% / 수완가10%** 중 하나다.
  힌트 할인율0/10/20/30/35/40%에 특성을 합산한 뒤 각 구매 단계에서 내림한다.
- 미습득 하위 단계만 추가 비용에 포함한다. 이미 습득한 단계·공유 단계는
  중복 청구하지 않고 진화 자체의 별도SP를 만들지 않는다.
- 원본 레어와 하위 단계의 실제 힌트를 사용한다. 진화에 별도 힌트를 받지 않으며, 원본이 습득이면 추가0 SP다. 과거 이벤트의 최대 힌트를 자동 적용하지 않는다.
- 현재 습득 효과를 기준으로 조합을 함께 시뮬레이션한다.
  하위와 상위 효과를 중복 적용하거나, 이미 습득한 진화의 분기를 바꾸지 않는다.
- 모든 표본에서 최속 스퍼트HP 조건을 충족하는 조합을 우선하고, 기준 대비 부진 구간 성능 유지·평균 마신을 비교한다.
  최소 추가 기여는 진단값이다. 이벤트 경로의 전역 선택 가능성을 검사하고, 제거 기여는 실제 습득 하위를 복원한다.
  입력한 가중 전개가 있으면 입력 가중 평균으로 비교한다. 기본 전개는 실제 빈도가 아니다.
  출력에 추가 구매 목록·단계 비용·사용/잔여SP·평균 마신·HP 검사 결과를 제공한다.
- 구매·각성/시나리오 진화를 공동 탐색한다. 기본9표본/0.05초, 목표240개와 예산 연동 확장,
  회복/진화 보호, 폭6·평가1400개 및 제한 교환을 사용한다. 모든 시나리오0/1/2개 조합을 비교한다.
  조건에서 보조 묶음을 자동 유도하고 최종144표본/0.01초에서 삭제·추가/승급 검사도 수행한다.
  누락 없는 후보9개 이하 풀은 최종 해상도로 전수 비교하고 큰 풀은 전역 최적해를 보장하지 않는다.
- v6의7000 SP 재검증:6990 SP 사용·10 SP 잔여,39.69395마신·HP128/128 충족.
- v8의 검토 이벤트 첫 선택을 고정한 가정 입력은6990 SP 사용·10 SP 잔여,
  144표본36.79461마신·HP144/144다. 검토되지 않은 레어2종 경로는partial이며 실제 육성 재현이 아니다.
- 역사적 v7은6996 SP 사용·4 SP 잔여,144표본35.87460마신·HP144/144다. 같은 선택288표본은
  35.93567마신이며 과거 선택의v7 재평가는33.98824마신이다. 과거 계승6개를 그대로
  확보한 재추천은288표본35.02380마신·최소33.72955다. 이 입력의 이벤트 분기 충돌은v8에서
  차단한다. 불가능했던 입력과 새 가정 입력을 실전 성능 향상으로 비교하지 않는다. 상세는v8 QA 참조.
- 큰 풀은 최종과 같은144표본/0.05초 재선별·조정 후0.01초에서 비교한다. 이득이 있는
  변경을 묶은 제안도 전체 주행으로 검증한다. 두7000SP 조건은 최종 이웃 검사1회에서 종료했다.
  같은 조합256표본에서는39.66185마신·HP256/256 충족이다.
  이전 조합을 새 모델로 고정 재평가한39.26692마신·HP253/256과 구분한다.

### 2.5 진화·시나리오 검증

### 2.7 PC·모바일 UI와 저장

- 육성 전 준비와 육성 후 추천을 별도 단계 화면으로 구성했다.
  준비 단계의 육성마·레이스·서포트 계층, 기본 색·버튼·입력·아이콘을 정리했다.

  성공한 추천은 입력을 요약으로 접고 결과를 표시한다. 수정·재추천·중지는 가능하다.

- 스킬명·뱃지·가격·획득 상태, 코스 거리·경기장·조건의 수직 정렬과 간격을 조정했다.

- 반복 안내·저장 성공 문구·긴 계산 설명·빈 안내 공간을 제거했다.
  필요한 오류·진행·한도·재추천 상태만 짧게 표시한다.
- 브라우저 저장 공간에 편성·보유 의상·계획별 습득/힌트·실제 입력을 저장한다.
  예전 수완가 체크값도 새 할인 선택으로 복원한다.
- 효과/가격 정정 시에도 신원이 같은 스킬의 **기록과 입력만 이관**하고 계산은 새로 한다.

- 실제 모바일 하드웨어, iOS Safari·Android Chrome 등 다른 엔진의 최종 검수는 남아 있다.
- v6의 새 입력/전체 계승 전환은 정적 계약·계산/저장 자동 검사와 빌드를 통과했다.
  브라우저 도구가 현재 주소를 확인하지 못해 이번 변경의 실제 화면 검증은 완료하지 못했다.

### 유지하기로 한 계산 범위

- 진화 해금 달성은 실제 획득 기록이 전제다. 미관측 상대 조건은 공통 순위 전개·경계값으로
  비교하며 실제 빈도 추정으로 취급하지 않는다. 자기 발동 조건은 실제로 판정한다.
  실제 스탯/보유 스킬로
  진화 해금을 새로 판정하는 기능은 현재 범위에 포함하지 않는다.
- 상대 디버프·승률·횡방향 블로킹/시야 이득은 계산하지 않는다.
  순수 시야·레인의0마신은 실전 가치가 없다는 뜻이 아니다.
- HP 부족 시 스퍼트 시점/속도를 공개 거리 예산으로 계산하고 실제 회복 후 재계획한다.
  상대 소비·블로킹·내리막 등 게임 전체 주행을 재현한 모델은 아니다.
- 전개 스퍼트의 추가 속도 상한은 공개 무제한 근사다. 실제 게임 수식 전체가 검증된 상태는 아니다.
- 일부 추월·추가 발동·팬 수·팀/시나리오 성과는 공개 모델의 근사/충족 가정을 사용한다.
- 최신 종료 스킬 `極上の感謝を！`, `名にし負う夢`는 기존 공개 시뮬레이터의
  조건 충족1.2배 근사를 유지한다. 실제 달성 조건과 게임 내부 보너스 상한은 추가 검증이 필요하다.
- 일반 육성 경로가 없는 히어로/카니발 이벤트 전용10개 레코드는 CM 후보에서 제외한다.
- 비용 미검증3종 `逃亡禁止令`, `砂上の舞姫`, `油断大敵`은 모두 제외 범위인 디버프다.
- 일부 신규 항목의 정확한 인게임 표시 순서, 코스 좌표·일부 메타데이터, 전체 획득
  경로의 완전성은 추가 검토가 필요하다. 데이터 수록 수가 게임 전체 보장을 뜻하지 않는다.

## 6. 후속 작업자가 지킬 기준

- 이 문서와 현재 두 계약을 먼저 읽고, 관련 QA의 날짜·데이터·모델 버전을 확인한다.
- 원본 스킬ID·효과 원문·가격 증거와 실제 구매 단계를 구분한다. 원본 파일과 불변 번들을 직접 편집하지 않는다.
- 수식이나 후보가 바뀌면 모델/데이터 버전을 기록하고 마신표·추천을 새로 계산한다.
  실제 습득 기록·힌트·입력은 신원 검증을 거쳐 보존한다.
- 소스 미지원/가격 미검증을 무료·무조건 획득·확정 효과로 바꾸지 않는다.
  검증한 기본 효과만 사용할 때는 근거와 제한을 내보내기에 남긴다.
- 계승6개, 시나리오 진화2개, 진화 분기 상호 배제, 하위 비용 중복 방지와 기존 저장 복원을 회귀 검사한다.
- 정책 설명과 구현 용어는 문서/내보내기에 두고 기본 화면의 긴 안내를 다시 늘리지 않는다.

## 7. 로컬 실행·검증

저장소 루트에서 실행한다. Python3.12 이상과 검증용 Node.js24를 기준으로 한다.

```powershell
py -X utf8 scripts/build_pages.py --output dist --fetch-portraits
py -X utf8 -m http.server 8000 --directory dist
```

`http://localhost:8000/`에서 연다. 같은 `dist`를 서빙하는 서버는 재빌드한 파일을
계속 제공하므로 일반적인 수정마다 재시작할 필요는 없다. 브라우저를 강력 새로고침한 뒤
모델/데이터가 바뀌었다면 마신표와 추천을 다시 생성한다. 기록 보존을 위해 저장 공간을 임의로 삭제하지 않는다.

```powershell
py -X utf8 -m unittest discover -s tests -v
node --test tests/*.test.mjs
py -X utf8 scripts/validate_data.py
```

현재 고정 원본에 큐레이션/어댑터 변경을 다시 적용할 때만 다음을 사용한다.
최신 원본을 새로 확인하는 일반 동기화와 구분한다.

```powershell
py -X utf8 scripts/sync_data.py --rebuild-active
```
