### 가격·계승·진화

- 효과 변환 관계는 `skill-transforms.mjs`에서 데이터로 관리한다. 기존 진화 규칙과 검토된
  강화 계승 관계를 같은 방식으로 순회한다. 미확인 구매 단계를 무료로 만드는 처리는 없다.
- 에피파네이아 `901411→91101411`, 스테이 골드 `901351→91101351`은 기본 계승의
  검증된 200SP 단계를 공유한다. 힌트0~5와 할인 특성0/4/10%를 같은 가격 계산에 넣는다.
  기본형을 이미 구매했다면 효과 변경의 추가SP는0이다. 실제 강화 조건 충족은 사용자의
  획득 기록이 전제이며 자동으로 부모·해방 조건을 충족했다고 주장하지 않는다.
- 기본형과 강화형을 각각 기록할 수 있고 같은 계승 한 슬롯으로 센다. 두 효과를 동시에
  적용하지 않는다. 기본형 습득 이력은 존재 조건과 이미 지불한 비용 판정에 남는다.
- 실제 ID와 무관한 합성 변환 관계로도 가격·중복·소유 조건을 검증했다.

### 발동 조건과 전개

- 기본9개는 거리 구간별 순위1~9를 돌며 비교하는 **가상 검증 전개**다. 실측 출현 빈도를
  뜻하지 않는다. 같은 표본의 스킬들이 동시에 서로 다른 현재 순위를 가질 수 없다.
- 순위 상승 횟수와 순위 구간 연속 유지 시간은 같은 순위 이력에서 계산한다. 실제 입력한
  상대 이벤트 값은 우선한다. 순위 상승으로 추정하는 추월 이벤트는 완전한 추월 모드가 아니다.
- 그 밖의 미관측 숫자 조건은 원본 조건의 경계값을 모은 공통 스트레스 값으로 비교한다.
  Boolean 조건은0/1이다. 이는 차이·블로킹·팀·걸림 사이의 물리적 연동을 복원한 것이 아니다.
  같은 필드의 상반된 조건을 각각 충족시키던 문제를 줄이는 검증 설계다.
- `raceContext.scenarios`로 이름·비음수 가중치·전개별 조건을 최대32개 입력할 수 있고
  `scenarioSource`로 근거를 남긴다. 가중치는 전개별 평균에 적용한다. 표본이 홀수이거나
  전개별 반복수가 달라도 우연한 표본 개수를 확률로 사용하지 않는다. 가중치0은 제외한다.
- 지능 판정·스킬 자체 추첨·게이트·인기·시작 지연은 기존 분리된 재현 표본을 유지한다.
  실제 빈도가 없는 기본 인기는 균등 사전가정임을 계속 표시한다.
- 최종 추천은 적은 표본을 요청해도 모든 선언 전개를 최소 한 번 방문한다. 1차 계산의
  작은 개발용 표본은 `scenarioCoverage.complete`로 미완전성을 확인할 수 있다.

성능 개선은 무작위 위치를 다시 뽑거나 표본 수를 숨겨 줄이지 않는다. 이미 모든 표본의HP를
충족한 조합이 있을 때, 경쟁 조합이 한 표본에서HP를 실패하면 HP 우선 기준에서 절대로
앞설 수 없으므로 나머지 표본 계산만 중단한다. 이 조기 제외는 `search.hpPrunedPlans`에
기록한다. 선택된 최종 조합의 수치는 항상 전체 표본으로 계산한다. 진행·취소 확인도 정밀
비교 중 더 자주 양보한다. CI의 확대 검증 제한 시간은10분에서30분으로 조정했다.

큰 후보군의 최종 진입은 `9표본/0.05초 탐색 → 144표본/0.05초 재선별·조정 →
144표본/0.01초 최종 비교` 순서다. 중간 단계는 탐색 상위뿐 아니라 계승 조합·시나리오
진화 조합·예산 구간의 대표를 보존한다. 두 뒤 단계는 동일한 발동·전개 표본을 쓰고 적분
간격을 바꾼다. 이득이 있던 여러 변경의 묶음도 전체 주행으로 확인하며, 개별 마신을 합산해
채택하지 않는다. 탐색·최종 표본 수 차이 때문에 큰 풀의 선택이 과도하게 반복 수정되던
문제를 완화하는 공통 절차다. 소규모 전수 비교는 이 후보 축소를 거치지 않는다.

### 왕수·군림 등 늦은 가속

`발동`과 `유효 가속`을 별도로 기록한다. 가속 효과가 남아 있는 매 시점에 그 효과의
가속 성분을 제외하면 속도 증가분이 줄어드는지 확인한다. 종반 전에 발동해도 지속 시간이
종반까지 남으면 유효할 수 있고, 지속 시간이 먼저 끝나거나 이미 목표속도에 도달하면
발동했어도 유효 가속으로 세지 않는다. 전개 스퍼트 전용 가속도 해당 상태에서만 집계한다.

최종 조합에서는 그 스킬 전체 효과를 제거한 동일 전개 주행과 비교해 추가 마신을 계산한다.
이 값은 다른 스킬과의 중첩·주력 가속 불발·발동 이력·회복 조건의 영향을 함께 포함한다.
각 제거 기여를 더해 조합 마신을 재구성할 수는 없다. 제거 비교는 게임에서 이전 하위 효과로
자동 되돌아가는 대체 구매의 가치와도 구분한다.

따라서 왕수의 코스별 잔여 거리·최종 코너·각질·순위 조건과 종반 시작 위치가 일치하면
초기에 유효할 수 있고, 늦은 코스나 이미 충분한 가속 조합에서는 추가 가치가 작아질 수 있다.
특정 코스를 수동으로 금지하거나 발동률에 임의의 감점 계수를 곱하지 않는다.

원본 수치와 당시 진단은 [v6 대회 자료 검증](CM_EVENT_EVIDENCE_QA.md)과 JSON을 보존했다.

현재 실행 스크립트는 [validate_cm_v7.mjs](../scripts/validate_cm_v7.mjs), 수치 기록은
[cm-v7-20261118.json](validation/cm-v7-20261118.json)이다.

```powershell
node scripts/validate_cm_v7.mjs
node --test tests/*.test.mjs
python -X utf8 -m unittest discover -s tests -v
python -X utf8 scripts/validate_data.py
python -X utf8 scripts/build_pages.py
```

통합 테스트 직후 동일 입력·모델의 `.cache/cm-7000-validation.json`을 재사용하려면
`--reuse-plan`을 사용할 수 있다. `--context-only`는 중간 결과만 `.cache/`에 저장하며,
`--reuse-context`는 그 중간 결과를 재사용한다. 최종 문서용 JSON은 전체 절차가 성공한 뒤 작성한다.
