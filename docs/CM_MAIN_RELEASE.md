# CM v1.6.3 출시 기준

마신표 v15, 목표 가속 v5와 최종 구매 v19는 순위·경합·인기 조건을 같은 레이스 전개에서 비교한다. 육성 전 목표 가속의 기준은 본체 고유기다. 육성 후 구매의 기준은 본체와 실제 습득 기록이며, 확보한 목표 가속과 PDM 전략 스킬의 직접 효과도 조합 전체와 함께 평가한다. 선택한 보호 조건에 필요한 SP가 부족하면 유지 설정을 표시한다.

- 출시 시점의 JP 원본과 저장 키는 [출시 manifest](validation/cm-launch-manifest-20261119.json)에 기록했다. 데어링 택트의 7개 스킬과 190+190 SP 구매 단계를 재생한다. 기존 main의 체크리스트와 호환성이 확인된 기능 브랜치의 기록은 실제 입력만 복원하고 결과를 다시 계산한다.
- CI는 출시 입력으로 수치 회귀를 재현하고 현재 JP 데이터의 무결성·마신표·구매 단계를 별도로 확인한다. Pages는 CI가 통과한 main 커밋으로 빌드한다. 공개된 커밋과 데이터 버전은 사이트의 `release.json`에서 조회할 수 있다.
- 실제 Chrome의 390px 화면에서 저장된 체크리스트, 7,000 SP 입력, 마신표, 목표 가속, 추천 취소와 재추천, 구매 SP 합계, JSON 내보내기를 확인한다. 코드가 바뀐 실행의 전체 입력과 데이터 갱신 실행의 작은 입력은 측정 파일의 `small`로 구분한다. 시간과 화면 캡처는 CI의 `cm-mobile-release-check` 산출물에 남는다.
- 다음 우선순위는 탐색 시간 단축이다. 성능 전후에 같은 입력·레퍼런스·전개·144표본·시간 간격을 사용한다. 마신표 생성과 육성 후 추천 시간을 따로 측정하고, 구매 가능성·예산·HP·위험 우선순위와 완전 평가한 조합 대비 0.1마신 허용 범위를 다시 비교한다. 장비와 브라우저가 다르면 별도 결과로 기록한다.

## v1.6.4 첫 추천 속도 개선

v1.6.3과 같은 입력·후보·탐색 한도·144표본·0.01초를 사용한다. 한 추천 안에서 같은 조합의 구매 가능 여부와 가격을 재사용한다. 주행에서는 종반에만 성립하는 조건과 순위 변화가 필요한 조건의 최초 가능 지점까지 검사를 미룬다. 실제 발동은 기존 조건과 좌표로 확인한다. 현재 주행에 적용된 효과는 발동·만료 시에 원래 순서로 합산한다.

브라우저 검사의 `metrics.json`에 첫 추천 전체 시간과 준비, 예비 탐색, 정밀 탐색용 시작 조합 구성, 최종 후보 평가, 조합 교체·재검토, 결과 진단에 걸린 시간이 기록된다. 각 단계의 단위는 밀리초다. 첫 추천의 기준 측정은 [v1.6.3 Chrome 실행](https://github.com/seraveist/umaBoard/actions/runs/44449459707/job/135309555883)이다. 같은 입력에 6,984 SP, +34.892635마신, HP 충족 144/144를 재현하는지 검사한다. [v1.6.4 계산 계약](validation/cm-optimization-v1-6-4-release-20261119.json)

## v1.6.5 첫 추천과 SP·힌트 변경 후 재추천

한 육성 기록에서 보유 SP나 힌트를 고치면 이미 비교한 조합의 주행 점수를 재사용한다. 현재 입력으로 후보, 선행 스킬 비용, 구매 가능 여부와 최종 선택을 다시 계산한다. 실스탯, 적성, 전개, 기습득 스킬 등 주행 조건이 달라지면 새로 평가한다. 첫 추천에서는 표본별 발동 구간을 공유하고, 비교 대상 주행은 먼저 완주한 시점의 마신 계산에 필요한 위치만 보관한다.

모바일 Chrome 검사는 7,000 SP 첫 추천에 이어 6,900 SP와 힌트 Lv2를 입력한다. 같은 변경 기록과 직전 추천을 새 워커에 전달해 구매 목록, 전개별 결과, HP, 0.1마신 압축과 탐색 판정을 대조한다. 최초·재추천·새 워커의 단계별 소요 시간은 해당 CI 실행의 `cm-mobile-release-check/metrics.json`에서 확인한다. [계산 계약](validation/cm-optimization-v1-6-5-release-20261119.json)

## v1.6.6 정밀 탐색 시작 조합의 주행 중복 제거

v1.6.5 모바일 검사에서 SP·힌트 변경 후 재추천은 95.7초, 같은 입력을 새로 계산하면 179.9초였다. 첫 추천의 정밀 시작 조합 구성은 83.8초였다. [v1.6.5 브라우저 측정](https://github.com/seraveist/umaBoard/actions/runs/44461331137/job/135348556884)

v1.6.6은 이 단계에서 같은 전개·난수 표본·시간 간격을 사용하는 두 조합을 비교한다. 발동 가능한 스킬 목록과 해당 스킬이 참조하는 기습득 여부, 보유 수, 계승 수가 같으면 주행 관측값을 공유한다. 강제 발동 스킬을 포함해 대상 선택이 달라질 수 있는 조합은 직접 계산한다. 비교가 끝나면 최대 8,192건의 표본 캐시를 해제한다. 브라우저 측정의 `firstCache.seedDrawHits`는 첫 추천에서 생략한 중복 주행 횟수다. [계산 계약](validation/cm-optimization-v1-6-6-release-20261119.json)

## v1.6.7 실사용 대기 시간

같은 기기에서 같은 설정으로 마신표를 다시 만들면 마지막으로 완성한 마신표와 목표 가속 조합을 불러온다. 현재 획득한 계승기는 복원 시 다시 반영한다. 앱 빌드, JP 데이터, 시나리오 상한, 표시 데이터와 레이스 입력을 비교하며, 저장소를 사용할 수 없으면 일반 계산으로 진행한다.

후보가 많은 SP 탐색에서는 예비 구매 목록을 먼저 표시한다. 예비 조합도 최종 표본 수와 시간 간격으로 평가하며, 정밀 탐색에서 조합이 달라질 수 있다. 최종 선택이 끝나면 확정 구매 목록을 즉시 표시하고 스킬별 기여도를 계산한다. 기여도 계산까지 끝난 결과를 JSON으로 저장할 수 있다. 브라우저 검사는 첫 마신표·재방문 복원·예비 목록·확정 목록·상세 완료까지의 시간을 각각 기록한다. [계산 계약](validation/cm-optimization-v1-6-7-release-20261123.json)
