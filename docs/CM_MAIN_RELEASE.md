# CM v1.6.3 출시 기준

마신표 v15, 목표 가속 v5와 최종 구매 v19는 순위·경합·인기 조건을 같은 레이스 전개에서 비교한다. 육성 전 목표 가속의 기준은 본체 고유기다. 육성 후 구매의 기준은 본체와 실제 습득 기록이며, 확보한 목표 가속과 PDM 전략 스킬의 직접 효과도 조합 전체와 함께 평가한다. 선택한 보호 조건에 필요한 SP가 부족하면 유지 설정을 표시한다.

- 출시 시점의 JP 원본과 저장 키는 [출시 manifest](validation/cm-launch-manifest-20261119.json)에 기록했다. 데어링 택트의 7개 스킬과 190+190 SP 구매 단계를 재생한다. 기존 main의 체크리스트와 호환성이 확인된 기능 브랜치의 기록은 실제 입력만 복원하고 결과를 다시 계산한다.
- CI는 출시 입력으로 수치 회귀를 재현하고 현재 JP 데이터의 무결성·마신표·구매 단계를 별도로 확인한다. Pages는 CI가 통과한 main 커밋으로 빌드한다. 공개된 커밋과 데이터 버전은 사이트의 `release.json`에서 조회할 수 있다.
- 실제 Chrome의 390px 화면에서 저장된 체크리스트, 7,000 SP 입력, 마신표, 목표 가속, 추천 취소와 재추천, 구매 SP 합계, JSON 내보내기를 확인한다. 코드가 바뀐 실행의 전체 입력과 데이터 갱신 실행의 작은 입력은 측정 파일의 `small`로 구분한다. 시간과 화면 캡처는 CI의 `cm-mobile-release-check` 산출물에 남는다.
- 다음 우선순위는 탐색 시간 단축이다. 성능 전후에 같은 입력·레퍼런스·전개·144표본·시간 간격을 사용한다. 마신표 생성과 육성 후 추천 시간을 따로 측정하고, 구매 가능성·예산·HP·위험 우선순위와 완전 평가한 조합 대비 0.1마신 허용 범위를 다시 비교한다. 장비와 브라우저가 다르면 별도 결과로 기록한다.

## v1.6.4 첫 추천 속도 개선

v1.6.3과 같은 입력·후보·탐색 한도·144표본·0.01초를 사용한다. 한 추천 안에서 같은 조합의 구매 가능 여부와 가격을 재사용한다. 주행에서는 종반에만 성립하는 조건과 순위 변화가 필요한 조건의 최초 가능 지점까지 검사를 미룬다. 실제 발동은 기존 조건과 좌표로 확인한다. 현재 주행에 적용된 효과는 발동·만료 시에 원래 순서로 합산한다.

브라우저 검사의 `metrics.json`에 첫 추천 전체 시간과 준비, 예비 탐색, 정밀 탐색용 시작 조합 구성, 최종 후보 평가, 조합 교체·재검토, 결과 진단에 걸린 시간이 기록된다. 각 단계의 단위는 밀리초다. 첫 추천의 기준 측정은 [v1.6.3 Chrome 실행](https://github.com/seraveist/umaBoard/actions/runs/44449459707/job/135309555883)이다. 같은 입력에 6,984 SP, +34.892635마신, HP 충족 144/144를 재현하는지 검사한다. [v1.6.4 계산 계약](validation/cm-optimization-v1-6-4-release-20261119.json)

## v1.6.5 첫 추천과 SP·힌트 변경 후 재추천

한 육성 기록에서 보유 SP나 힌트를 고치면 이미 비교한 조합의 주행 점수를 재사용한다. 현재 입력으로 후보, 선행 스킬 비용, 구매 가능 여부와 최종 선택을 다시 계산한다. 실스탯, 적성, 전개, 기습득 스킬 등 주행 조건이 달라지면 새로 평가한다. 첫 추천에서는 표본별 발동 구간을 공유하고, 비교 대상 주행은 먼저 완주한 시점의 마신 계산에 필요한 위치만 보관한다.

모바일 Chrome 검사는 7,000 SP 첫 추천에 이어 6,900 SP와 힌트 Lv2를 입력한다. 같은 변경 기록과 직전 추천을 새 워커에 전달해 구매 목록, 전개별 결과, HP, 0.1마신 압축과 탐색 판정을 대조한다. 최초·재추천·새 워커의 단계별 소요 시간은 해당 CI 실행의 `cm-mobile-release-check/metrics.json`에서 확인한다. [계산 계약](validation/cm-optimization-v1-6-5-release-20261119.json)

## v1.6.7 실사용 대기 시간

같은 기기에서 같은 설정으로 마신표를 다시 만들면 마지막으로 완성한 마신표와 목표 가속 조합을 불러온다. 현재 획득한 계승기는 복원 시 다시 반영한다. 앱 빌드, JP 데이터, 시나리오 상한, 표시 데이터와 레이스 입력을 비교하며, 저장소를 사용할 수 없으면 일반 계산으로 진행한다.

후보가 많은 SP 탐색에서는 예비 구매 목록을 먼저 표시한다. 예비 조합도 최종 표본 수와 시간 간격으로 한 번 평가하고 최종 비교에 포함한다. HP·부진 구간·마신·비용 순으로 비교하는 과정에서 추천이 달라질 수 있다. 최종 선택이 끝나면 확정 구매 목록을 즉시 표시하고 스킬별 기여도를 계산한다. 기여도 계산까지 끝난 결과를 JSON으로 저장할 수 있다. 브라우저 검사는 첫 마신표·재방문 복원·예비 목록·확정 목록·상세 완료까지의 시간을 각각 기록한다. [계산 계약](validation/cm-optimization-v1-6-7-release-20261123.json)

## v1.6.9 기능 브랜치 검증

기본 마신표는 본체와 사용자가 지정한 기준 스킬로 계산한다. 중반 스킬 발동 횟수 1~3회를 요구하는 단일 발동식은 해당 기준에 발동원이 부족할 때 편성 예시를 추가한다. 덱과 육성마에서 함께 확보할 수 있는 중반 스킬을 고르고, 양쪽에 같은 발동원을 넣어 대상 스킬 하나의 추가 이득을 측정한다. 지능 추첨, 발동 위치, 순위·경합 조건은 각 표본에서 판정한다. 교토 잔디 2,200m 선행에서 尻尾の滝登り는 기본 0마신, 중반 발동원 3개 편성 시 +1.235마신(115/144회 발동)이었다. ラッキーセブン은 일반 표본에서 +0.026마신이었다.

같은 육성에서 SP만 직전 일반 탐색 예산의 ±5% 안에서 바꾸면 확보한 구매안을 재사용한다. 증액 시 중반 발동원 수를 반영해 추가 스킬을 고르고, 감액 시 기존 스킬을 뺐을 때의 실측 기여로 후보를 좁힌다. 최초 최대 8개 구매안을 정밀 비교하고, 남은 SP로 한 스킬을 더 살 수 있으면 최대 8개를 추가 비교한다. 예산·획득 제한과 HP·부진 구간 기준을 확인한다. 증액 후 같은 구매안만 남거나, 추가 비교 범위가 크거나, 힌트·스탯이 바뀌면 일반 탐색을 사용한다. 구매 목록이 확정된 뒤에는 기여도 계산 중에 SP를 다시 입력해도 같은 세션에서 기준 조합을 재사용한다.

| 보유 SP | 사용 SP | 평균 마신 | 구매 목록 확정 | 기여도 포함 완료 |
| ---: | ---: | ---: | ---: | ---: |
| 7,000 | 6,984 | +34.893 | 151.5초 | 185.0초 |
| 7,200 | 7,194 | +36.257 | 6.7초 | 51.1초 |
| 6,800 | 6,768 | +34.312 | 8.3초 | 40.3초 |

같은 육성 기록에서 7,000 → 7,200 → 6,800 SP 순으로 실행한 Node 단일 측정이다. 세 조합 모두 HP 144/144와 부진 구간 기준을 충족했다. 이전 버전에서 각 예산을 별도로 일반 탐색한 결과는 7,200 SP에서 +35.636마신, 6,800 SP에서 +34.112마신이었다. 0.1마신 압축은 정밀 비교한 후보 중 같은 HP·위험 등급 안에서 적용한다. 최초 추천과 기여도 분석은 여전히 시간이 걸린다. 모바일 렌더링과 다른 코스에서의 속도·구매 품질은 별도 검증 대상이다. ## v1.6.10 첫 SP 추천의 병렬 평가

일반 탐색에서 필수 스킬 묶음에 후보 하나씩을 추가하는 정밀 비교를 두 모듈 워커에 분배한다. 단말이 논리 프로세서 2개 이상을 보고하고, 구매 가능하며 첫 정밀 표본이 캐시에 없는 서로 다른 조합이 32개 이상일 때 사용한다. 32개는 작은 입력에서 워커 시작·전송 비용을 피하기 위한 실행 기준이다. 두 작업이 모두 끝나면 원래 후보 순서로 점수를 반영한다. 표본 승격, 시작 조합 구성, 구매 가격, HP·위험 우선순위와 최종 144표본 평가는 v1.6.9 규칙을 따른다.

모듈 워커를 시작하거나 결과를 수신하지 못하면 진행한 워커를 종료하고 단일 계산으로 복귀한다. 취소하거나 새 요청을 시작하면 이전 요청의 결과를 버린다. 재추천은 이미 계산한 스킬 점수를 우선 사용한다.

| 스태미나 | 단일 구매 확정 | 병렬 구매 확정 | 단일 상세 완료 | 병렬 상세 완료 | 사용 SP | 평균 마신 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1,850 | 157.7초 | 126.1초 | 190.9초 | 159.8초 | 6,984 | +34.893 |
| 1,250 | 257.1초 | 225.4초 | 332.2초 | 298.7초 | 6,984 | +28.557 |

교토 잔디 2,200m 선행, 7,000 SP, 후보 210개의 Node 단일 측정이다. 두 조건 모두 HP 144/144와 부진 구간 기준을 충족했다. 실행 캐시 카운터 하나를 제외한 전체 추천 결과가 단일·병렬 간 일치했다. 모바일 브라우저의 소요 시간은 메인 병합 검사의 측정 대상이다. [전체 추천 해시·단계별 시간·실행 조건](validation/cm-v1-6-10-parallel-20261123.json)

## v1.6.11 구매 조합 재검토

스태미나 1,250에서도 첫 기준 조합은 HP를 충족했다. v1.6.10에서 시간을 많이 쓴 부분은 변경 후보를 36표본으로 선별하는 과정(214회, 27.9초)과 남은 후보를 144표본으로 검토하는 과정(98회, 46.7초)이었다.

v1.6.11은 같은 구매안에서 독립적으로 평가할 수 있는 변경 후보를 두 워커에 분배한다. 같은 조합은 같은 워커로 보내 9·36표본에서 이미 계산한 주행을 정밀 비교에 재사용한다. 각 단계에서 결과를 원래 후보 순서로 적용한다. 기본 설정에서는 새 워커를 시작할 때 미계산 조합이 32개 필요하고, 이미 사용 중인 워커로 144표본을 계산할 때는 8개부터 분배한다. HP를 충족한 기준 조합과 비교할 때는 후보의 첫 HP 실패에서 정밀 주행을 중단한다. 워커 오류가 생기면 해당 묶음을 단일 계산으로 다시 평가한다.

## v1.6.12 정밀 평가와 시작 조합 구성

기존 정밀 평가 시간에는 개별 후보의 주행과, 마신 또는 SP 효율 순으로 스킬을 추가하며 시작 조합을 고르는 주행이 함께 들어 있었다. 스태미나 1,250에서 v1.6.11을 다시 측정하니 각각 17.1초와 31.9초였다.

`尻尾の滝登り`처럼 모든 발동 경로에서 현재 횟수 조건을 통과할 수 없는 스킬은 다음 스킬 발동까지 판정을 미룬다. 횟수에 무관한 대체 조건은 계속 확인하고, 선행 조건은 달성 시점에 기록한다. `もう一踏ん張り`와 `星の煌き`처럼 전력질주 중 무작위 지점을 요구하는 조건은 전력질주가 실제 시작된 뒤 해당 표본에서 추첨한 거리까지 기다린다. 두 경우 모두 발동 여부는 기존 판정식이 결정한다. 종반에도 기본 속도가 목표에 도달하고 다음 조건 판단까지 구간이 비면, 원래 프레임 간격과 연산 순서로 위치·전력질주 추가 속도·HP를 갱신한다. 경사, 스퍼트 시작, 효과 만료, HP 고갈, 결승 보간은 기존 프레임 처리로 돌아간다.
