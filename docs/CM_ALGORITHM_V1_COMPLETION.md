# 최적화 알고리즘 v1 — 계산 모델 v11

확정일: **2026-11-18 Asia/Seoul** · 작업 브랜치 `feat/cm-first-chart`

**현재 v11을 마신표·육성 후 스킬 추천 알고리즘의 1차 완성본으로 확정한다.**
후속 사용자 결정에 따라 공개 명칭을 **최적화 알고리즘 v1**으로 정한다.
기존 결과·저장/캐시 호환용 계산 모델 식별자 `v11`은 유지한다.
사용자 결정에 따라 작은 탐색 차이를 없애기 위한 추가 수치 조정은 이번 완료 범위에서 종료한다.
검증된 기능과 알려진 한계를 함께 고정하고, 이후에는 실제 입력의 구조적 오류나 의미 있는 회귀를 우선 처리한다.

완료 범위는 명시된 조건에서의 자기 성능 비교·구매 조합 탐색이다.
실전 승률, 실제 상대 전개 빈도, 모든 게임 수식, 큰 후보군의 확정 최적성을 인증하는 상태로 설명하지 않는다.

## 2. 완료한 계산 흐름

1. **육성 전 마신표:** 육성마·서포트·시나리오·레이스 조건에서 획득 가능한 스킬을 수집하고,
   기준 능력치로 속도·가속·회복과 자기 성능 효과를 비교한다. 단독 기여와 최종 조합 기여는 구분한다.
2. **후보와 기록 보존:** 능력치 조건을 후보 획득 가능성과 분리한다. 현재 비활성인 후보와
   능력치에 따라 분기가 바뀌는 원본도 보존하고, 실제 능력치로 다시 판정한다. 힌트·습득 이력도 이어간다.
3. **실제 구매 가격:** 실제 힌트·할인 특성·이미 구매한 하위를 반영한다. 공동 구매 단계는 한 번만 청구하고,
   검증되지 않은 비용을 무료로 간주하지 않는다.
4. **공동 추천:** 습득 효과를 기준으로 구매·진화 조합 전체를 재주행한다. HP 충족과 기존 조합 대비
   부진 구간 보호를 우선하고 평균 기여를 비교한다. 개별 마신을 단순히 더하지 않는다.
5. **획득·진화 제약:** 검토된 이벤트 선택지의 동시 획득 가능성, 진화 분기, 시나리오 진화 최대2개,
   계승 최대6개와 기본/강화형의 중복 효과를 검사한다.
6. **상태와 결과 전달:** 기록·입력·모델·데이터·표본 기준을 보존한다. 추천 실행 자체가 실제 습득을
   처리하지 않으며, 입력 변경 후에는 이전 결과를 최신 계산으로 오인하지 않도록 한다.

계산 계약은 [1차 마신표](CM_FIRST_CHART.md), [육성 후 추천](CM_POST_TRAINING.md)을 따른다.

## 4. 수용하고 보존하는 한계

- **제한 탐색:** 한신1600·500SP에서480SP 추천보다499SP 조합이 약0.00622마신 좋았다.
  같은 입력에서의 누락 사실과 다른 시드·표본·간격의 비교를 보존한다. 이 값은 전체 오차 상한이나 운영 임계값이 아니다.
- **근소한 차이:** 난수 표본·시간 간격·물리 근사에 따라 작은 순위가 바뀔 수 있다.
  여유 SP가 있으면 극소한 양의 조합 기여도 구매할 수 있으며, 이를 큰 실전 우위로 설명하지 않는다.
- **조건부 가속:** 왕수의 불가능 조건은 차단하지만, 군림은 델마의 제한 후보군에서 여전히 선택될 수 있다.
  실제 전개 빈도를 측정하지 않았으므로 실전 과대평가가 완전히 해소됐다고 선언하지 않는다.
- **전개·물리:** 기본 전개는 실측 빈도가 아니다. 전력 스퍼트 상한, 일부 가변 효과량과 공개 추첨 방식의 근사·출처 차이는 남는다.
- **데이터 범위:** 전체 획득 경로와 게임 수식의 완전성을 보장하지 않는다. 미지원 효과·비용·코스는 기존 제외/표시 정책을 유지한다.
- **범위 밖:** 실제 상대 주행·디버프·승률, 자동 진화 해금 달성 검사와 실측 분포 보정은 이번 완료 범위에 포함하지 않는다.

한계를 숨기는 보정 계수·스킬별 감점·코스별 금지를 추가하지 않는다.
작은 후보군의 정확 탐색 확대와 근소한 차이의 안정성 강화는 후순위 품질 개선 후보로 남긴다.
이번 완성을 위해 반드시 해결해야 하는 작업으로 취급하지 않는다.

## 5. 출력·문서 정합성 점검

현재 결과는 실측 확률이 아니라 공통 전개와 비교 표본임을 설명한다.
전수 비교 결과는 기록 후보·현재 표본 조건의 범위로 제한하고, 제한 탐색은 범위 내 추천으로 표시한다.
HP 충족은 비교 표본 수와 함께 보여 주고 미충족 상태를 구분한다.

정리 과정에서 운영 수식 대신 문서의 낡은 설명을 바로잡았다.
코너2회 추첨은 중복을 허용하며, 정밀 탐색은 비교한 완성 조합을 상위6개로 줄이지 않는다.
실제 기록 후보 전체의 정밀 기여로 초기 조합을 다시 구성하는 현재 절차를 계산 계약에 반영했다.
v2 당시의 “1차 마신표 완료” 문서는 역사적 기록으로 표시하고 현재 완료 기준과 연결했다.

## 6. 후속 변경을 시작할 조건

실제 입력에서 다음이 재현되면 해당 범위를 다시 조사한다.

1. 획득 가능한 후보 누락, 실제 습득·힌트 기록 손실.
2. 검증된 가격과 다른 청구, 하위·공유 단계 중복 청구, 기구매 비용 재청구.
3. 원본 조건상 불가능한 발동·획득·진화·계승 조합의 허용.
4. 같은 입력에서 유효한 기존 조합보다 의미 있게 열등한 추천이나 조건 충족 실패가 재현됨.
5. 새 게임 자료가 기존 조건·효과·가격·코스 데이터와 명백히 다름.

중요도는 목적 위반, 실제 영향, 다른 시드·표본·간격의 안정성을 함께 보고 판단한다.
새로운 고정 마신 문턱은 두지 않는다. 이미 수용한 작은 차이의 재발견만으로 미세 조정을 반복하지 않는다.
계산 의미가 바뀌면 새 모델·데이터 기준에서 관련 검증을 하고 이전 완성본 기록은 보존한다.

## 7. 동일 완성본 확인

프론트엔드 연결 검수 이후 현재 트리의 계산 유지 여부는 다음 명령으로 확인한다.

```powershell
node scripts/check_cm_algorithm_v1.mjs
```

이는 원래 운영 커밋과 동일한 계산 의존 모듈30개·입력4개·기존 증거10개를 검사한다.
새 [v1 계산 기준](validation/cm-optimization-v1-release-20261118.json)은 이전 완료 기준 파일의 해시도 보존한다.
화면·내보내기 연결 수정은 [프론트엔드 검수](CM_OPTIMIZATION_V1_FRONTEND_QA.md)에 별도로 기록한다.
과거 전체 assets 해시 검사는 당시 UI까지 같은 트리를 확인하기 위한 명령으로 남긴다.
현재 UI 수정본에 적용하면 전체 assets 차이를 보고하며, 그 기준을 덮어쓰지 않는다.

```powershell
node scripts/check_cm_algorithm_baseline.mjs
```

이 명령은 운영 파일 묶음·모델·데이터와 입력4개·검증 자료10개의 동일성을 확인한다.
전체 레이스를 다시 계산하거나 게임 정확도를 새로 인증하는 검사가 아니다.
해시가 달라진 후속 작업 트리를 이 과거 완성본과 같다고 표시하려고 기준 파일을 덮어쓰지 않는다.

일반 회귀와 배포용 빌드는 기존 명령을 사용한다.

```powershell
node --test tests/*.test.mjs
python -m unittest discover -s tests -v
python scripts/validate_data.py
python scripts/build_pages.py
```

이번 확정은 작업 브랜치의 알고리즘·검증 기준 완료다. main 병합과 Pages 배포는 별도 단계로 관리한다.
