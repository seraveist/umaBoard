# CM 육성 후 최종 추천 계약 — 2026-11-18

육성 전 1차 마신표와 획득 체크리스트 다음에 실제 육성 결과를 입력하고,
남은 SP 안에서 추가로 배울 스킬 조합을 추천한다. 1차 마신표의 완료 기준과
후보·정렬·습득 연동은 [기존 계약](CM_FIRST_CHART.md)을 유지한다.

## 사용 흐름

1. **육성 전 준비**에서 설정과 1차 마신표를 완성하고 **육성 후 추천**으로 전환한다.
2. 같은 체크리스트에서 게임에서 습득한 스킬은 `습득`, 구매 가능한 미습득 스킬은 `획득` 또는
   `할인 Lv1~5`로 기록한다. 획득은 할인 없는 미습득 상태다.
3. 위의 공통 **실제 육성 결과**에 실제 능력치5종, **현재 남아 있는 SP**를 입력한다.
   할인 특성은 없음·공부가·수완가에서 선택하고, 필요한 적성 설정을 변경한다.
4. 최종 추천에서 추가 구매 목록, 사용/남는 SP, 현재 습득 대비 평균 마신,
   회복을 포함한 최속 스퍼트 HP 충족 여부와 구매 단계별 비용을 확인한다.
   추가 구매 다음에 각성 스킬 진화, 시나리오 스킬 진화, 최종 적용 스킬 전체를 표시한다.
5. 게임에서 실제 구매한 뒤 체크리스트를 갱신한다. 추천 자체는 습득 기록을
   변경하지 않으며, 수정한 상태로 다시 추천할 수 있다. JSON 저장을 지원한다.

단계를 오가도 체크리스트·검색·입력값·유효한 최종 추천은 유지한다. 휴대폰에서는
공통 입력 아래의 **스킬 기록 / 추천 결과**를 전환한다. 추천 완료 후 입력은
요약으로 접고 결과를 표시한다. 입력은 언제든 다시 펼칠 수 있고 접혀 있어도
재추천·중지할 수 있다. 입력 오류는 자동으로 펼쳐 안내한다. 레이스·편성을
수정하면 다시 1차 마신표를 완성해야 한다. [UI 검증](CM_UI_REFRESH_QA.md)을 따른다.
추가 반응형 동작은 [모바일 작업 검증](CM_MOBILE_WORKFLOW_QA.md)을 따른다.

스탯은 게임에 표시된 원래 수치1~3000을 입력한다. 초과1200 보정은 기존 물리
모델이 적용하므로 사용자가 미리 보정하지 않는다. SP는0~100000 정수다.
거리·마장·각질 적성은 각각S~G이며 기본A다. 컨디션은 기존CM 기준 최상이다.
실제 수치를 시나리오 기본 상한으로 채우거나 잘라내지 않는다.

## 후보와 가격

- 현재 체크리스트와 전체 계승 후보의 실제 기록을 사용한다. Top10은 기본 표시이며
  최종 후보 제한이 아니다. 순수 회복·고정 조건상 비활성 계승도 확보 기록을 보존하고,
  보유 개수 조건에 참여한다. 전체 필터를 통틀어 확보한 계승 최대6개를 유지한다.
- `owned`는 이미 지불한 습득 기록, `unavailable`은 직접 구매 후보 제외,
  `0`~`5`는 미습득 구매 후보의 실제 힌트다. 진화는 원본 레어의 기록으로 자동 후보가 된다.
  과거에 실제 습득한 진화 기록은 보존하고, 숨겨진 진화의 과거 힌트는 재사용하지 않는다.
- 각 검증된 구매 단계의 기본가에 기존 정수 내림 할인 함수와 해당 단계의
  힌트 할인율0/10/20/30/35/40%를 적용한다. 육성 전 정책의 일반Lv5,
  이벤트 대성공 최대 힌트를 적용하지 않는다.
- 할인 특성은 없음0%·공부가(勉強家)4%·수완가(切れ者)10% 중 하나다. 기본가의
  해당 비율을 힌트 할인율에 합산한 뒤 단계별로 정수 내림하며 서로 중첩하지 않는다.
  예: 기본200 SP / 할인Lv5는 없음120 SP, 공부가112 SP, 수완가100 SP다.
  이미 습득한 단계와 진화 자체에 비용을 새로 만들지 않는다. 기존 저장값에는
  `discountTrait`가 없으면 기존 수완가true를 수완가로, false/누락을 없음으로
  복원한다. 새 명시 선택이 우선하며 선택은 저장·복원·JSON 기준에 포함한다.
  효과10%는 [GameWith](https://gamewith.jp/uma-musume/article/show/261138),
  힌트와의 합산은 [독립 계산 설명](https://note.com/huge_gnu1789/n/n9bb277333a1c)으로
  확인했다. 공부가4%와 힌트Lv5 합계44%의200→112 SP 예시는
  [공개 계산 예시](https://note.com/neko_chomei/n/ne24b7a222685), 수완가 획득 시 대체는
  [특성 정리](https://note.com/herohero_3/n/nbdb862bdc513)로 교차 확인했다.
  기존 힌트 할인표와 단계별 내림 정책을 유지한다.
- 상위를 구매하려면 필요한 미습득 하위 단계를 포함한다. 별도 힌트를 기록하지
  않은 선행 단계는Lv0으로 계산한다. 이미 습득한 단계는 추가SP에서 제외하며,
  같은 단계가 여러 경로에 등장해도 한 번만 합산한다.
- 진화는 원본 레어 구매 비용을 사용한다. 원본이 이미 습득이면 진화 추가SP는0이다.
  원본 레어와 하위 일반의 실제 힌트를 각각 적용한다. 진화 행에 별도 힌트를 입력하지 않는다.
  진화 후보 조정에서 해금 조건 미충족 후보를 해제할 수 있다. 각성 분기는 원본당 하나,
  시나리오 진화는 별도 최대2개이며 같은 원본을 두 종류로 동시에 진화할 수 없다.
- 비용이 미검증인 후보는 무료로 가정하지 않고 이름과 제외 사유를 표시한다.
  실제 체크 기록을 사용하므로 과거 이벤트 선택지의 최대 보상 묶음을 추정하지 않는다.

## 조합 계산

현재 추천 모델은 `cm-post-training-v15`이며 공개 명칭은 최적화 알고리즘 v1(개정5)이다. 본체 고유기와 현재 습득 효과를 기준으로
실제 조합을 함께 시뮬레이션한다. 단독 마신값을 단순 합산하지 않는다.
v11은 [원래 알고리즘 1차 완성본](CM_ALGORITHM_V1_COMPLETION.md)의 고정 기준으로 보존한다.
개정2의 구매 조합 탐색에 개정4의0.1마신 허용 범위·성능 분포별 대표·동일 표본 재사용을 적용한다. 개정5는 마신표와 같은 직전 프레임의 발동·회복 기록을 사용한다. 서포트 이벤트 74장의 선택지를 검사하며, 다른 경로에서 확보한 레어는 그 경로로 충족할 수 있다. 미습득 전체 Lv5를 눌러도 이미 구매한 단계는 남은 SP에서 다시 청구하지 않는다.
구매한 하위를 유지하는 이력과 실제 적용되는 상위 효과를 구분하므로
레어/일반 또는 진화/원본 효과를 중복 적용하지 않는다. 이미 습득한 진화를
다른 분기로 바꾸는 추천도 허용하지 않는다. 검증된 시나리오 진화 개수 제한을 적용한다.

모든 표본에서 최속 스퍼트HP 조건을 충족하는 조합을 우선한다. 모두 미충족이면
전개별 가중 표본 충족률, 평균HP 부족량을 먼저 비교한다. 그 다음 기존 습득 조합보다
부진 구간의 완주 시간이 악화되지 않는 조합을 우선하고, 가중 평균 마신·부진 구간
완주 시간·비용 순으로 비교한다. 개정4의 최종 선택은 완전 평가한 최선과 HP·위험 우선순위가 같고,
평균 기여가0.1마신 이내인 조합 중 SP를 가장 적게 쓰는 조합이다. 고정된 최선을 기준으로 하므로
허용 손실을 반복해서 누적하지 않는다. 부진 구간은 가중 완주 시간 분포에서 가장 느린25%의
평균이며 경계 표본은 필요한 비중만 포함한다. 후보와 기준의 전체 주행 시간을 각각
비교하므로 추가 기여가0인 유리한 전개 하나가 유효한 가속 전체를 배제하지 않는다.
`riskPolicy:{tailMass:.25,maxTailDelay:0}`는 명시적인 위험 선호 설정이며 실전 확률이나
이름별 보정 계수가 아니다. 기본/명시 가중 입력 모두 같은 목적 함수를 사용한다.
전개별 최소 기여는 진단값으로 보존한다. 기본9개 전개는 실측 확률이 아니다.
회복기는 단독 마신이0이어도 탐색에 포함한다. 남은HP로 스퍼트 시작/속도를 계산하고,
실제 회복 뒤 다시 계획한다. HP 고갈은 실제 주행속도와 마지막 스퍼트 조건에 영향을 준다.
회복 횟수·HP·보유/계승 개수·발동 이력·추첨·지능 판정은 1차와 같은 공통 모델을 쓴다.
v9의 이동 전후 조건 판정과 원본 구간에서의 무작위 추첨·기회 만료도 같은 평가기를 거친다.
1차 표시 여부로 최종 후보를 다시 제한하지 않는다. [수정·재검증](CM_ALGORITHMS_V9_QA.md) 참조.
시나리오 기본 능력치로 발동할 수 없는 스킬도 획득 경로가 맞으면 체크리스트에 보존한다.
실제 능력치를 입력할 때 원본 조건을 다시 해석하며, 비활성인 습득 스킬과 실제 힌트도 유지한다.
능력치에 따라 지원 가능한 효과 분기가 바뀌면 같은 원본을 다시 해석한다.
현재 미지원 분기는 비교값을 비워 두며0점으로 꾸미지 않는다. [v11 후보 보존 검증](CM_ALGORITHMS_V11_QA.md) 참조.
미입력 게이트는CM9 균등 추출, 인기는 균등 사전가정이다. 실제 알려진 값은 입력할 수 있다.

구매와 각성·시나리오 진화를 같은 조합으로 탐색한다. 원본 레어만 먼저 구매 최적화한 뒤
진화를 붙이는 순차 결정은 하지 않는다. 모든 진화 후보를 보존하고, 시나리오의 가능한
0/1/2개 조합을 별도로 모두 비교한다. 유효하고 유리한 후보가 부족하면 0~1개도 허용한다.

먼저 동시에 적용할 수 없는 후보를 서로 모든 쌍이 충돌하는 그룹으로 나눈다. 그룹 간 충돌도 따로 검사한다.
전수 탐색 사전 조사의 최대8192작업 안에 합법·예산 내 정규화 조합이512개 이하로 확인되면,
후보 수가9개를 넘어도 구매 상태를 모두 열거한다. 개정4는 이 완성 조합을36→72→144표본으로
선별하며, 전개별 기여·HP와 연계 구조를 보존하는 대표를 남긴다. 부분 조합의 가격·합법성만으로
잘라내지 않으며, 조사 한도를 넘으면 부분 결과를 최적해로 사용하지 않고 제한 탐색으로 전환한다.

제한 탐색의 후보 비교는 기본9표본/0.05초로 모든 전개를 최소 한 번 방문한다.
기본 후보 목표240개를 마신·효율 순으로 섞고 고예산에서는 예산에 맞게 늘리며, 회복·진화 후보도 보존한다.
전체 후보로 구성하는 두 완성 조합을 먼저 확보한 다음 조건에서 유도한 보유ID·회복/발동/계승 개수의
보조 조합과 시나리오0/1/2개 팩, 폭6 탐색·1대1 교환을 비교한다.
초기 거친 평가 한도는 `max(1400,1+3×후보 수)`로 공유한다. 최소 작업량은 전체 단독 후보와 두 완성 조합의 구성에 필요한 한도다.
이 한도는 시간 상한이 아니며, 비싼 주행을 하지 않는 구매·획득 판정과 정밀 단계는 별도로 기록한다.

상위 조합과 계승·시나리오·예산 구간별 대표 조합은 예비36표본/0.01초에서 선별한 뒤
최종144표본/0.01초에서 재평가한다. 실제 기록 후보 전체를36표본에서 비교하고 앞·뒤 평균이 불안정하면72·144표본으로 늘려 순서를 정한다.
기여순·기여/비용순 두 조합의 누적 구성은36표본에서 수행한다. 추가할 때마다 조합 전체를 재주행한다.
기본 습득 조합·구성 끝점과 각 연계 구조의 대표를 최종 평가에 남긴다.
개별 기여가 작다는 이유로 원본 후보나 회복·발동 횟수·보유 참조를 제거하지 않는다.
최종 후보 중 최선이 전부HP를 충족하면 삭제·추가/승급·시나리오 변경을 예비 비교한 뒤 대표를 정밀 확대한다.
모두HP 미충족이면 직접 이웃을 전체 표본에서 비교한다. 원본 후보는 삭제하지 않는다.
이후 새 조합의 직접 변경과 SP 확보/추가 구매는 같은 거친 작업 예산으로 선별하고 상위 폭6개만 정밀 비교한다.
최대12회 반복하되 매번 전체 후보의 정밀 이웃 검사를 되풀이하지 않는다.
단독으로 유리한 변경을 묶은 제안도 전체 조합을 정밀 재주행해 검증한다.
같은 HP/위험 우선순위·같은 연계 구조에서 비용도 줄지 않는0.1미만의 후속 개선은,
여러 개선을 묶은 제안을 검증한 후 추가 반복을 종료할 수 있다.
상위를 제거하거나 하향할 때는 이미 습득한 하위 효과를 복원한다.

단일 변경에서 더 좋아지지 않으면 **단독으로 나빠지는 제거/하향 교체도 SP 확보 제안으로 유지**한다.
제거/하향 뒤 추가 구매, 여러 계열의 SP 환급을 묶은 구매를 구성하고 별도 거친 평가 한도 최대512개를
모든 최종 반복에서 공유한다. 환급당 손실·기여·비용 순서는 제안을 구성하는 순서이며 결과 점수의 가중치가 아니다.
거친 비교의 상위 폭6 제안을 최종144표본/0.01초의 조합 전체 주행으로 다시 검증한다.
개별 효과나 개별 변경의 기여를 합산해 최종 결과로 사용하지 않는다.

기본 압축 모드는 전역 최적성·오차를 보증하지 않으므로 `globalOptimal`·`closureComplete`를 `false`로 남긴다.
`search.approximation`은 완전 평가한 최선과 선택 결과의 차이이며 전역 오차 한도가 아니다.
`gainTolerance:0`은 압축을 끈 기존 정밀 경로다. 이때 `search.closureComplete`는
`closureScope`에 명시한 최초 정밀 검사와 선별한 후속 제안 안의 종료 여부다.
거친 조사 한도를 소진한 채 끝나면 완료로 표시하지 않으며, `closureTermination`에 중단 원인을 남긴다.
거친 조사 한도 소진은 `exchangeScreeningComplete`로도 표시한다.
제한 탐색은 모든 복합 교체를 검사한 것이 아니며 `globalOptimal:false`를 유지한다.
전수 조사 완료 여부와 상태/작업 수, 초기·복합 거친 평가 수, 정밀 평가 수와 후속 정밀 검사 상한도 `search`에 남긴다.
이미 전체 표본HP를 충족한 조합이 있으면 한 표본에서HP를 실패한 경쟁 조합은 확실히
열등하므로 나머지 표본을 생략할 수 있다. 이 횟수는 `search.hpPrunedPlans`에 남긴다.
최종 선택은 전체 표본으로 계산한다. 허용 범위 안에서 더 싼 조합을 고르면 남은SP로 가능한 구매를 다시 확인한다.
이 복원 검사는 최대12회와 기존 공유 정밀 평가 한도 안에서 실행하고, 고정된 완전 평가 최선에 대한 허용 범위를 유지한다.
동일 표본의 주행 관측은 재사용하고 새 표본만 실행해 합산한다. HP·발동 조건·추첨 값은 바꾸지 않는다. 확률 임계값에 따른 임의 생략은 하지 않는다.
이전 결과와의 호환을 위해 제거한 중간 정밀도의 반복/검사 횟수는0으로 남긴다.

### 획득 가능성과 조합 기여

검토된 활성 서포트·시나리오 이벤트마다 선택지를 하나만 고를 수 있는 공통 제약을
구성한다. 각 레어의 여러 획득 경로 중 하나라도 가능한 선택 배정이 있으면 허용한다.
같은 선택의 공통/분기 보상은 함께 허용하며, 본체 각성·실제 별도 힌트 경로도 반영한다.
진화는 원본 레어의 획득 경로를 요구한다. 스킬 이름별 금지 쌍을 만들지 않는다.
미습득 힌트와 습득을 포함한 전체 기록이 불가능하면 계산 전에 차단하고 충돌한
스킬을 안내한다. 실제 받은 보상을 사용자가 고치며 추천이 임의로 기록을 삭제하지 않는다.
이벤트 자료가 없는 대체 경로는 불가능으로 단정하지 않고 `unmodeledGoldIds`와
`coverage:'partial'`로 남긴다. 검토 범위의 동시 획득 가능성이지 육성 성공 보장이 아니다.
API의 `acquisitionChoices`로 실제 이벤트 선택을 지정할 수 있다.

최종 적용 스킬의 추가 기여는 같은 표본의 제거 비교다. 상위 효과를 제거할 때 실제로
습득한 하위 효과를 복원한다. 미습득 하위를 무료로 복원하지 않으며, 소유 조건의 이력과
활성 효과를 구분한다. `restoredIds`에 기준을 남긴다. 이 기여들은 상호 작용을 포함하므로
합계를 최종 조합 마신으로 해석하지 않는다. [v8 검증 기록](CM_ALGORITHMS_V8_QA.md)을 참조한다.
반별 차이는 오차의 보장 범위나 신뢰구간이 아니다.
강화 계승은 검증된 변환 관계를 따라 기본 계승의 구매 단계를 공유한다. 이미 산 기본형은
추가 비용0이며 두 효과를 중복 적용하지 않는다. 기본형·강화형은 같은 계승 슬롯이다.
모든 최종 적용 스킬에 대해 같은 전개에서 해당 효과를 제거한 추가 기여를 계산한다.
주력 가속의 성공/불발에 따라 보조 가속의 가치가 달라진다. 또한 같은 선택을 전개 스퍼트
추가 가속 근사를 끈 모델과 비교해 민감도를 기록한다. 이 차이는 오차 보장 범위가 아니다.
[v7 검증 문서](CM_ALGORITHMS_V7_QA.md)에 같은7000 SP 조건의 재검증과 한계를 기록했다.

## 상태·내보내기

실제 입력은 기존 저장소의 같은계획 `postTraining.values`에 저장한다.
기존 설정·보유 의상·습득 기록을 덮어쓰지 않는다. 새로고침 후 1차 마신표를
복원하면 같은 계획의 실제 입력도 복원되며 최종 추천은 명시적으로 재실행한다.

스탯/SP/적성/획득 상태를 수정하면 진행 중인 최종 계산을 중지하고 이전 결과를
표시상 구분하며 내보내기를 비활성화한다. 레이스/육성 설정 변경은 1차 마신표
재생성을 요구한다. 각 단계는 별도의Worker와 요청ID로 오래된 응답을 무시한다.
추천 실패·취소에도 입력과 습득 기록은 유지한다.

획득 경로·진화 제한만 수정하고 스킬 효과·가격·연결·의상·코스 데이터가 동일한
데이터 버전은 발행기가 저장 호환 목록으로 명시한다. 같은 편성·경기 설정의
기존 습득 기록과 실제 입력을 복사해 이어 쓰며, 이전 저장 계획도 유지한다.
후보는 새 마신표에서 다시 생성하고 추천은 다시 실행한다. 효과·가격 정정 버전도
스킬ID·희귀도·계승 여부·연결 및 편성/코스 신원이 같으면 별도의
`checklist_record_versions`로 실제 기록과 입력만 이어받는다. 기존 ID·신원을 유지하는
추가 데이터도 같은 이관을 허용하며, 여러 과거 호환 버전 중 가장 최근 저장을 선택한다. 이전 계산값은 재사용하지
않으며 신원이 달라진 데이터는 자동 이관하지 않는다. 같은 설정의 이관 전/후 버전은
저장12개 제한에서 한 슬롯으로 세어 다른 편성의 기록을 밀어내지 않는다.

최종 JSON에는 실제 데이터·계산 모델 버전, 실제 설정, 전체 습득 상태,
본체/이미 습득/실제 적용ID, 추천 구매 목록과 단계별 비용, 사용/잔여SP,
