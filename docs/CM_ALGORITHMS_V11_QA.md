## 후보 수집과 발동 판정을 분리

기존에는 시나리오의 기본 능력치로 후보를 수집했기 때문에 조건에 못 미친 일반 스킬이 사라졌다.
후속 추천이 실제 능력치를 받아도 이미 빠진 원본과 힌트 기록은 돌아오지 않았다.
진화에만 있던 능력치 조건 유보 규칙을 다음 공통 규칙으로 통합했다.

1. 후보 수집은 **능력치5종을 미정으로 둔 고정 문맥**을 사용한다.
   실제 획득 경로와 고정 코스·각질 조건은 계속 검사한다. 일반 인자·자체/서포트 레어·진화·구매 하위 연결에 같은 문맥을 쓴다.
2. 1차 기여 계산은 기존 시나리오 능력치로 원본 조건을 그대로 해석한다.
   현재 비활성이라는 이유로 체크리스트와 기록을 삭제하지 않는다.
3. 능력치에 따라 현재 미지원 효과 분기에서 지원 가능한 분기로 바뀔 수도 있다.
   이런 원본의 메타데이터도 유지하되 현재 미지원 비교는 `null`이며0마신으로 취급하지 않는다.
4. 실제 능력치를 입력하면 최종 추천의 기존 공통 해석기로 다시 컴파일한다.
   미달이면 발동하지 않고, 조건을 충족하면 실제 조합 평가에 들어간다.
   비활성이어도 습득 이력은 유지하며 이미 지불한 단계의 비용을 다시 청구하지 않는다.

구현: [activation.mjs](../assets/activation.mjs), [cm-chart.mjs](../assets/cm-chart.mjs).
최종 추천의 재해석·가격·획득 제약은 기존 [cm-final-plan.mjs](../assets/cm-final-plan.mjs)를 그대로 사용한다.
시나리오8이나 스킬`204142`를 운영 코드에 별도로 추가하는 처리는 없다.

## 같은 반례의 수정 전후

파인 모션`102201`·선행·교토3000`10810`·시나리오8·200SP·스킬`204142` 힌트Lv2라는
기존 감사의 축소 구매 입력을 유지했다. 수정 후 후보는 정상 마신표 생성 결과에서 가져왔으며,
능력치 프로필을 바꾸거나 후보 행을 수동으로 끼워 넣지 않았다.

| 실제 스태미나 | v10 기여 | v11 기여 | v11 사용SP | 양쪽 HP 충족 비율 |
| --- | ---: | ---: | ---: | ---: |
| 1199 | 0 | 0 | 0 | 0 / 0 |
| 1200 | 0 | 2.359053 | 144 | 0 / 0 |
| 1800 | 0 | **0.148144** | 144 | 1 / 1 |
| 2400 | 0 | **0.103963** | 144 | 1 / 1 |

1199에서는 힌트를 유지하지만 구매하지 않는다. 1200은 발동 경계 확인이며 두 조합 모두 HP 부족이므로
큰 마신을 안전한 구매 성능으로 제시하지 않는다. 1800·2400은 양쪽 HP 조건을 만족한다.
각 결과는 전체 후보군의 보편적인 손실량이 아니라 같은 유한 입력의 인과 비교다.

대표 실제 스킬을 시나리오10개×코스3개에 대입한30행 모두 후보와 힌트를 보존한다.
기존 누락3행이 복원됐고 기존 포함27행도 유지됐다. 실제 능력치가 조건 미달인 습득 기록도
`owned`와 필수 보유 효과 목록에 남고, 사용SP는0이었다.

자료: [후보30행·구매4개·비활성 습득 대조](validation/cm-v11-candidates-20261118.json).

## 특정 스킬에 한정하지 않는 회귀 검사

[후보 보존 테스트](../tests/cm-candidate-retention.test.mjs)는 다음 성질을 검사한다.

- 능력치5종×비교연산6종×발동/선행 조건2곳×일반/레어2종 = **120개 조합**에서
  기본 능력치로 비활성인 후보가 남고, 실제 능력치를 바꾸면 조건이 다시 적용된다. 힌트·습득 기록도 유지한다.
- 인자만 가능한 일반 스킬도 남는다. 반면 잘못된 각질·노면·거리 조건이나 획득 경로 없는 레어는 들어오지 않는다.
- 미지원 효과가 있는 낮은 능력치 분기는 미지원으로 표시하고, 높은 실제 능력치에서 지원되는 대체 분기를 정상 구매한다.
- 비활성인 하위 습득 단계는 유지하고, 실제 능력치 상승 후 상위 구매의 미지불 비용만 적용한다.
- 실제 데이터·정상 마신표 생성→체크리스트→최종 추천 경로로1199/1800 경계와 비활성 습득을 확인한다.

120개 조합은 새 테스트6개 중 하나에 들어 있는 매개변수 검사이며, 전체 테스트 수에120개를 더해 부르지 않는다.

## 전력 스퍼트 무작위 조건의 작은 시점 차이

`run_at_full_speed_random`은 이동 후 위치 대신 공통 이동 시작 위치를 사용하도록 바꿨다.
이동 전 위치가 아직 없는 초기 상태에는 현재 위치를 사용한다.
다른 지형 조건의 이동 후 참조나 기본 물리 구간은 바꾸지 않았다.
기준은 공개 역분석 구현인 [고정 umasim SkillChecker](https://github.com/mee1080/umasim/blob/e9bb2939ba117ea93e556790c353ed3edec27eab/race/src/commonMain/kotlin/io/github/mee1080/umasim/race/calc2/SkillChecker.kt)이며 공식 게임 사양이라고 단정하지 않는다.

1750m 문턱을1749.9→1750.1m로 지나는 프레임은 발동하지 않고 다음 프레임에서 검사한다.
기존 감사의 실제11스킬×3코스=33개를 같은144표본·0.01초로 다시 계산했다.
기존에 준비한 시작 위치 참조 비교기의 기여·HP 결과와33개 모두 정확히 일치했다.
큰 차이는 아니며 왕수·군림의 높은 평가를 설명하는 직접 원인도 아니다.

자료: [33개 시점 대조](validation/cm-v11-clock-20261118.json).

## 조합·조건부 가속의 동일 입력 재검증

기존 감사의 니가타2000 외측·주쿄2000·한신2000과 후보10개·예산500/800SP 입력을 유지한다.
다른 부분집합 열거기로 코스별1,024개를 검사하고, 예산별 유효 조합134/291개와 추천을 비교한다.
왕수·군림 금/백4종의 별도 단독 비교도 같은3코스와 두 스퍼트 방식으로24개를 재검사한다.
열거는 조합 선택의 검사이며 운영 물리와 평가 목적을 공유한다. 독립적인 실전 확률 검증이 아니다.

| 주쿄2000 | 800 | 2.936158 | 0 |

추천6개 모두 열거 결과와 일치했고 v10과 선택ID·기여가 같았다.
왕수·군림의24개 단독 비교도 기여·HP 충족 비율·발동/유효 가속 표본 비율이 v10과 정확히 같았다.
이번 보완으로 조건부 가속 평가를 임의로 끌어내리거나 기존 추천을 맞추는 조정을 하지 않았다.

자료: [추천6개·유효 조합 열거](validation/cm-v11-bounded-20261118.json),
[왕수·군림24개 통제 비교](validation/cm-v11-conditional-20261118.json).

전체 회귀 검사의 기존228행·실제 기록 후보220개·7000SP 사례도 통과했다.
수정 후6990SP를 사용해 **35.519746마신**, 표본 HP 충족 비율1이었다.
기존 독립 반례 조합을 현재 물리와 같은 목적에서 다시 평가해 새 추천이 뒤지지 않는다는 검사도 통과했다.
정밀 후보220개를 모두 검사했지만 여전히 제한 탐색이므로 전역 최적 보장으로 해석하지 않는다.

## 확인한 한계와 사용 시 유의점

수정 범위는 후보 보존·기록 전달·실제 능력치 재해석과 작은 시점 정합성이다.
가정된 전개 분포를 실측 확률로 바꾸지 않았고 수백 후보의 제한 탐색을 전역 최적이라고 보장하지 않는다.
기존 공개 추첨 방식의 출처 차이·효과량 및 전력 스퍼트 근사도 남아 있다.

기존 마신표는 다시 생성해야 새 후보가 표시된다. 저장된 힌트·습득 기록은 같은ID로 이어서 사용한다.
이전 버전에서 이미 저장 내용 자체가 삭제된 기록은 근거 없이 만들어 복구하지 않는다.

## 재현과 전체 검사

[v11 재검증 도구](../scripts/validate_cm_v11.mjs)는 v10 고정 모듈을 별도 캐시에 복원한다.
코드 해시·데이터·모델 버전을 기록하고 과거 감사 입력 및 결과와 대조한다.

```powershell
node --test tests/*.test.mjs
python -m unittest discover -s tests -v
python scripts/validate_data.py
python scripts/build_pages.py
node scripts/validate_cm_v11.mjs --candidates --clock --conditional
node scripts/validate_cm_v11.mjs --bounded
```

Node 전체 **295개 통과·실패0**, Python 전체 **51개 통과·실패0**이었다.
새 테스트6개에는 위120개 매개변수 조합과 실제 데이터 경로 검사가 포함된다.
활성 데이터 검증·Pages 빌드·브라우저 모듈54개의 문법 검사와 새 검증 도구의 문법 검사도 통과했다.
데이터 검증의 기존 경고5개는 변경되지 않았다. 결과·대규모 입력·선택·검사 메타데이터는
[전체 검사 기록](validation/cm-v11-checks-20261118.json)에 보존했다.
