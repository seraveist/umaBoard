# 스킬 최적화 엔진 목표 계약

2026-10-08 개편 기준. 제품 정의와 정책은 [PROJECT_PLAN.md](PROJECT_PLAN.md)를 따른다.
아래 엔터티는 논리 계약이다. 실제 Worker는 `SkillOptimizer`와 `PurchaseModel`을 사용한다.
입력은 기존 setup + `spBudget`, 선택지 고정은 `eventChoices`다. 출력에 `budget`, `prices`, `finalPlan`,
`lockedIds`, `excludedIds`, `optimization`, `totalGain`이 추가된다. 물리 모델은 `solo-comparison-v2`를 유지한다.
실제 수식·지원 상태·표본·HP 피드백 제한은 [ENGINE_VALIDATION.md](ENGINE_VALIDATION.md)에 기록한다.

## 입력

| 입력 | 내용 |
| --- | --- |
| `RaceContext` | JP, 데이터/모델 버전, 코스·마장·날씨·계절·시간·각질·적성·의욕 |
| `TargetParameters` | 사용자가 입력한 예상 능력치 5종, 예상 획득 총 SP |
| `CharacterContext` | 육성마 의상 ID, 개화, 현재 공개 각성 MAX, 고유기 최종 레벨 |
| `ScenarioContext` | 시나리오 ID, 검증된 스킬 경로·진화·선택 제한 |
| `DeckConstraints` | 직접/자동 모드, 선택·고정 카드, 보유 SSR, 렌탈 후보·최대 1장, 선택적인 타입 장수 |
| `SelectionState` | 선택 ID, 구매 고정 ID, 제외 ID, 고정 이벤트 묶음 |
| `EvaluationPolicy` | 발동 표본·상대 조건 가정, HP 기준, 최대/안전, 비용 정책 버전 |

예상 능력치·획득 SP는 입력 상수이며 편성으로 예측하거나 수정하지 않는다.
서포트 레벨·성능해방·훈련 효과와 실제 부모 개체는 입력하지 않는다.
각성 MAX는 출시된 6·7단계를 포함하되 해당 의상에서 현재 공개된 단계만 뜻한다.
본체의 이미 보유한 고유기는 구매 고정과 구분하여 기본 효과로 적용한다.
복합 효과는 같은 스킬 ID를 한 번만 선택하고 계승 수·비용도 한 번만 센다.

## 데이터 연결

| 자료 | 역할 |
| --- | --- |
| `SkillMaster` / `SkillInvocation` / `SkillEffect` | 이름·효과·조건·시간·지원 상태 |
| `SkillRelation` | 전체 DB 기준 상하위 단계·원본/진화·분기·교체·선행 비용 관계 |
| `AcquisitionRoute` | 본체·시나리오·서포트 힌트·이벤트·계승 경로 |
| `SupportEventBundle` | 카드·이벤트·선택지별 동시 보상, 경로 배타, 대성공 최대 힌트, 검증 근거 |
| `SkillCostStage` / `CostPolicy` | 단계별 원가·힌트 정책·할인·선행 비용·불명확 비용 |
| `PurchaseOrder` | 실제 인게임 기본 순서에 대응하는 검증된 정렬 키·적용 버전 |
| `CharacterMaster` / `SupportMaster` | 의상·개화·카드 ID·타입·희귀도·제공 경로 |
| `CourseMaster` / `ScenarioMaster` | 지형·구간·진화/획득 제한 |
| `DataVersion` | 출처 commit/blob·보완 규칙·스키마 버전 |

이벤트 완주·성공 확률은 무시하고 선택한 묶음의 대성공을 가정한다.
서로 양립 불가능한 선택지의 보상은 합치지 않는다. 한 묶음에 금색이 여러 개 있으면 함께 후보에 넣는다.
배타는 획득 경로에 적용하며 다른 본체·카드 경로까지 전역적으로 금지하지 않는다.
일반 흰 스킬은 스킬 ID 그대로 인자 후보로 사용한다. 인자 마스터·별수·부모 검색을 필수 의존성으로 두지 않는다.
후보 구성 이후에도 진화 원본과 하위 단계의 관계·비용 그래프를 잃지 않는다.
비용·이벤트 묶음·기본 구매 순서가 미검증이면 상태와 누락 근거를 반환한다.

## 처리 단계

1. 입력과 고정 조건·예산·편성·관계 충돌을 검사한다.
2. 레이스·의상·시나리오·편성·이벤트별 습득 후보와 계승·흰 인자 보완 후보를 만든다.
3. 고정 구매·제외 조건에 따라 최종 효과 집합과 구매 비용을 정규화한다.
4. 같은 기준 주행과 발동 표본에서 조합 전체의 마신·가속·HP를 평가한다.
5. 추천 요청이면 예산과 제한을 만족하는 조합을 탐색한다. 편성 추천 요청에서만 카드 후보도 탐색한다.
6. 최종 구매·경로·SP·이벤트·인자 준비·구매 순서와 탐색 범위를 반환한다.

원본 금색/진화, 금색/하위 흰색, ○/◎를 다른 비교 대안으로 유지하되 효과는 중첩 적용하지 않는다.
일반 흰 스킬 Lv5 할인, 선택 이벤트 금색의 대성공 최대 힌트, 단계별 내림·선행 비용을 적용한다.
추가 할인은 초기 표준 가격에 포함하지 않는다. 본체·시나리오 금색 및 계승형은 Lv0 표준 가격을 명시적인 계획 가정으로 적용한다.
비용 누락을 0으로 처리하지 않고 예산 충족 여부의 불확실성을 전파한다.

## 목표 인터페이스

```js
buildCandidates(context, deck, eventBundles)
resolveAcquisition(skillIds, context, deck, eventBundles)
priceSelection(skillIds, acquisition, costPolicy)
evaluateSelection(selection, context, activationPolicy)
optimizeSkills(context, deck, selectionConstraints, searchPolicy)
recommendDecks(context, deckConstraints, selectionConstraints, searchPolicy)
buildFinalPlan(evaluatedSelection, purchaseOrder)
```

후보/경로/가격과 주행 평가를 분리한다. 토글은 선택 초안·경로·SP·제약만 갱신한다.
무거운 계산은 버튼으로 Worker에 전달하며 한 요청의 입력 snapshot을 고정한다.
계산 중 추가 변경은 다음 요청까지 보존한다. 마지막 계산과 선택 초안의 버전을 구분한다.
미적용 선택이 남으면 마지막 계산 결과를 최종 확정 계획으로 출력하지 않는다.

`evaluateSelection`은 체크 상태를 자동 변경하지 않는다.
`optimizeSkills`는 사용자의 구매 고정·제외·이벤트 조건을 유지하고 다른 항목만 변경한다.
속도 목록이 고정된 요청에서는 그 기준으로 가속·회복을 평가한다.
`recommendDecks`만 카드 변경을 허용하며 모든 후보의 입력 능력치·총 SP는 같다.
자동 추천 스킬을 다음 요청의 사용자 구매 고정으로 승격하지 않는다.

## 출력

- 입력·데이터·모델·가격 정책 버전, 적용된 선택 snapshot.
- 최종 효과·구매 항목, 고정·제외 상태와 미충족 조건.
- 단계별 구매 비용, 사용·잔여 SP, 비용 완전성·예산 초과 상태.
- 스킬별 추가/제외 마신, 유효 구간, 상대 조건 가정·계산 지원 여부.
- 종반 가속 조합, 진입·목표속도·도달시간·그래프·발동 표본 비교.
- HP 성공/실패 대조와 최속 스퍼트 유지 조건. 실제 레이스 완주 보장은 출력하지 않는다.
- 일반/계승 습득 경로, 선택 이벤트 묶음·대성공 힌트, 인자 준비할 흰 스킬·계승 제공 육성마.
- 자동 편성의 카드·렌탈·타입 제한 충족과 비교안. 육성 스탯·SP 예측이나 훈련 성능 점수는 없다.
- 검증된 인게임 기본 순서의 구매 목록과 정렬 검증 상태.
- 탐색 후보·평가 수·후보 축소·근사 여부. 전역 최적성은 검증된 범위에서만 표현한다.

효과는 하나의 집합으로 계산하며 개별 마신 합산으로 조합 이득을 만들지 않는다.
마신은 동일 시점 거리 차이 / 2.5m, 같은 발동 표본을 맞춘 대조 주행이다.
최대/안전도 입력 SP 안에서 추천한다. 안전은 정의된 표본의 최저 이득이며 실전 모든 상황의 하한이 아니다.
미지원은 0마신이 아니다. 마신표 양수 필터와 회복 HP 기준, 계승 각 탭 TOP 10·전체 6개를 적용한다.
조합 선행조건·본체 고유기·구매 선행 비용은 표시 필터와 별도로 정확히 보존한다.
최종 구매 목록·비용·효과는 같은 실제 선택을 가리켜야 한다.

## 검증 기준

- 동일 입력·가격 정책·발동 표본은 같은 구매 조합과 평가값을 반환한다.
- 경로가 있어도 자동 구매 필수로 고정하지 않는다. 구매 고정은 명시적인 사용자 조건이다.
- 예산 초과·미검증 가격·선택 충돌을 자동 해제나 0 비용으로 숨기지 않는다.
- 금색·진화·○/◎·선행 비용·복합·계승 수를 중복 계산하지 않는다.
- 선택 이벤트의 동시 보상은 허용하고 배타 보상은 차단한다. 대체 획득 경로는 보존한다.
- 서포트/이벤트 변경은 경로·가격·후보를 다시 구성하되 사용자 의도를 일관되게 유지한다.
- 속도 선택만으로 고정 코스 구간이 바뀌지 않는다. 접속·이후 목표속도와 가속의 중복은 조합에 따라 변한다.
- 초반 전용 가속의 전체 이득을 종반 가속 기여로 사용하지 않는다.
- HP는 선택된 속도·가속·회복 효과로 다시 검토하고 강제 최속 주행 모델의 한계를 유지한다.
- 렌탈 최대 1장·6장 편성·타입 제한·고정 카드와 검증된 게임 편성 제한을 만족한다.
- 최종 목록은 같은 구매 집합·비용의 검증된 게임 기본 순서이며 마신 순위와 혼동하지 않는다.
- 근사 탐색·상대 조건 성공 가정·미지원 효과·미검증 정렬을 결과에서 구분한다.
