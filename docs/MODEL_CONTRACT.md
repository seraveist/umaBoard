# 실제 엔진 연결 계약

완성 엔진의 목표 계약입니다. 현재 `PreparationEngine`은 `solo-comparison-v1`의 제한된 비교 구현으로,
아래 메서드 이름과 출력 전체를 그대로 완성했다고 선언하지 않습니다.
현재 적용된 수식·지원 상태·표본·탐색 범위와 HP 피드백 제한은 [검증 명세](ENGINE_VALIDATION.md)를 따릅니다.

## 입력

`RaceContext`: 서버(JP), 데이터/게임 버전, 코스 ID, 거리, 노면, 마장 상태,
계절, 날씨, 시간, 각질, 목표 능력치 5종, 적성, 의욕.

`TrainingContext`: 육성 우마무스메/의상 ID, 개화, 각성(MAX 고정), 시나리오 ID,
서포트 ID 6개. 각성 조건·서포트 레벨·성능 해방은 입력에 포함하지 않습니다.
각성 MAX는 해당 의상에 현재 해방 가능한 모든 단계를 뜻합니다. 출시된 6·7단계도 포함하되,
사전 수록된 미래 스킬은 해방일부터 포함합니다. 최대 단계를 전역 상수 5나 7로 제한하지 않습니다.
고유기의 육성 중 레벨 상승 조건을 달성했다고 가정하고 개화에 따른 최종 레벨을 적용합니다.

`SkillSelection`: 실제 효과를 적용할 속도·가속·회복 스킬 ID와 인자로 준비할 스킬 ID.
흰 인자 탭의 추천·선택·계산 단위도 SkillMaster의 스킬 ID입니다. 별도의 인자 ID는 사용하지 않습니다.
원본 금스킬과 진화형은 하나의 습득 항목으로 처리합니다. 진화 분기도 동시에 선택하지 않습니다.
속도와 가속이 함께 있는 복합 효과는 동일 스킬 ID로 관리하고 효과를 한 번만 적용합니다.
SP 예산·잔여량·힌트 할인은 입력하거나 계산하지 않습니다.

`ActivationAssumptions`: 가능한 동시 발동 조건, 발동 위치/표본, 상대 의존 조건 가정,
순위 조건 가정, 회복 성공/실패. ‘최고/최저’는 이 가정 집합 안에서의 범위입니다.

## DB 연결

효과 데이터와 획득 경로를 분리합니다.

- `SkillMaster`: ID, 표시명, 유형, 효과량/지속시간, 발동 조건, 하위 스킬 ID,
  고유기 레벨 반영, 원본/계승형/진화형 구분, 모델 지원 여부.
- `AccelerationComparisonCost`: 가속 조합 비교에만 쓰는 할인 없는 기준 SP.
  효율 추천과 같은 이득의 조합을 비교할 때만 사용하며 화면에는 표시하지 않습니다.
- `AcquisitionRoute`: 스킬 ID, 캐릭터/서포트/시나리오 ID, 각성·힌트·이벤트·계승 등 경로,
  선택지/이벤트 조건, 진화 조건·진화 제한. 흰 인자 준비 후보는 일반 흰 스킬에서 파생합니다.
- `CourseMaster`: ID, 방향, 거리, 코너·직선·경사·구간 경계.
- `DataVersion`: 출처, 취득일, 일본 서버 적용 버전.

편성한 서포트의 힌트·이벤트 스킬은 모두 습득 가능한 후보에 포함합니다.
이벤트 완주·선택·성공 조건은 원본 데이터에 남겨도 후보 구성·추천·효과 계산에는 사용하지 않습니다.
체크한 스킬은 습득한 상태로 가정합니다. 레이스 중 발동 조건은 계속 계산합니다.
일반 흰 스킬은 인자로 준비할 수 있는 기본 후보로 취급합니다. 그중 레이스 조건에 유효하고
현재 본체·서포트·시나리오에 일반 획득 경로가 없는 스킬을 추가·제외 마신으로 정렬하여 Top 10을 추천합니다.
금색·진화·고유·계승 고유는 흰 스킬 후보와 구분합니다. 상위·하위 및 교체 관계는 SkillRelation으로 처리합니다.
FactorMaster·FactorSkillLink나 인자 ID 매핑은 필수 의존성이 아닙니다. 인자 생성 확률·계승 확률·별수·기간,
실제 부모 개체·프렌드 검색은 입력하지 않습니다. 인자 자료를 확보해도 추천의 필수 관문으로 사용하지 않습니다.
지원하지 않는 효과·조건은 0마신이 아닌 ‘계산 미지원’으로 반환합니다.

## 엔진 인터페이스

예시 화면 `FixtureEngine`의 다음 기능을 실제 엔진에서 구현하는 것이 목표입니다.

```js
available()                    // 현재 편성의 경로가 있는 후보 + 계승 추천 후보
record(skillId)                // 효과와 경로가 연결된 스킬
factors()                      // 인자로 준비할 일반 흰 스킬 후보; 반환/선택 ID는 스킬 ID
simulate(speedIds, accelIds, activationCase, healIds)
gain(speedIds, accelIds, activationCase)
marginal(skillId, type, selection, activationCase)
recommend(selection, activationCase, objective)
analyze(selection, activationCase, objective)
```

실제 구현에서는 스킬 ID 집합을 단일 효과 집합으로 정규화하고, 회복·지구력 상태도
주행 속도와 스퍼트 결정에 피드백해야 합니다. fixture의 타입별 집합은 화면 검증용입니다.

## 출력

- 편성 내 스킬: 효과 지원 상태, 유효 구간, 획득 경로, 추가·제외 마신.
- 가속: 현재 속도/목표속도/차이, 첫 목표 도달 시각, 유효 시간,
  개별 추가 이득, 조합별 이득, 유리·대표·불리 가정 비교.
- 추천 기준은 최대·효율·안전입니다.
  최대는 대표 발동에서 최고 이득을, 안전은 불리한 발동에서 최고 이득을 선택합니다.
  같은 최고 이득의 조합이 여러 개이면 내부 기준 SP가 가장 적은 조합을 선택합니다.
  효율은 최대 추가 이득 90% 이상 중 내부 기준 SP가 가장 적은 조합을 선택합니다.
  90%는 초기 정책이며 실제 통계와 검증 후 조정 가능합니다.
  스킬별 SP·SP 대비 마신·조합 SP·전체 SP와 할인 정보는 화면에 출력하지 않습니다.
- 흰 인자: 일반 경로 없는 후보 Top 10, 준비/습득 가정 선택,
  선택 유지 항목. 후보 사전 필터와 계산 캐시로 연산량을 줄입니다.
- 스태미나: 고갈 시점, 최속 스퍼트 시작, 결승선 유지, 결승 잔량, 회복 성공/실패.

마신 환산은 같은 시점의 거리 차이 / 2.5m입니다. 비교 주행과 대조 주행의 난수·발동 표본을 맞춥니다.
개별 마신의 합으로 조합 이득을 만들지 않습니다.

## 검증 기준

- 고정 코스 조건은 속도 선택만으로 발동 구간이 바뀌지 않습니다.
- 속도기 선택이 바뀌어도 접속에 관여하지 않으면 진입속도는 유지될 수 있습니다.
- 현재속도 증가와 목표속도 증가는 다른 효과로 처리합니다.
- 가속 발동 때 이미 목표속도에 도달했으면 해당 구간의 추가 가속 이득은 없습니다.
- 가속 필요성이 진입속도 하나에 의해 결정되지 않고 이후 목표속도 변화에도 반응합니다.
- 획득 경로·원본/진화형·복합 효과를 중복 계산하지 않습니다.
- 동일 입력·동일 발동 표본의 결과는 재현 가능합니다.
- 지원 범위의 수식과 효과를 검증한 뒤에만 실제 계산 모드로 전환합니다.
