# 최적화 알고리즘 v1 — 0.1마신 압축 개정4

작성일: **2026-11-19 Asia/Seoul** · 브랜치 `feat/cm-first-chart`

완성 조합의 대표 선별·정밀 평가·중복 주행을 줄인다. HP 충족률·부족량과 부진 구간 보호에는
이 허용오차를 적용하지 않는다. 최종 기여·HP·발동률은 기존144표본·0.01초 전체 주행 결과다.
0.1은 현재 선언한 평가 표본 안의 선택 기준이며 미평가 조합이나 모든 추첨을 포함하는 전역 오차 보증은 아니다.

공개 명칭은 `최적화 알고리즘 v1`, `revision:4`, 최종 추천은 `cm-post-training-v14`다.
마신표 `cm-first-chart-v11`·단독 비교 `solo-comparison-v5`와 활성 데이터는 유지한다.
직전 운영 기준은 `baa9d98`의 [0.01마신 개정3](CM_OPTIMIZATION_V1_TOLERANCE_QA.md)이다.
검증 배치는11월18일 시작해19일 완료했으며 새 원자료 이름의 `20261118`은 배치 시작일이다.
이전 감사·개정2·개정3의 원자료는 덮어쓰지 않는다.

## 구조 변경

### 동일 표본을 재주행하지 않는 확장 평가

기존 추첨의 표본 번호별 결과는 표본 수를 늘려도 같다.36표본에서72·144표본으로 늘릴 때
앞서 계산한 동일 주행을 다시 실행할 필요가 없다.
[평가기](../assets/race-evaluation.mjs)에 조합·시간 간격별 간결한 관측값을 보관하고,
새 표본만 주행한 뒤 기존과 같은 순서로 합산한다. HP·기여·완주 시간·발동/유효 가속 기록을 그대로 사용한다.
다른 조합이나 시간 간격은 구분하며, 최대65536관측값 예산 안에서 오래된 조합부터 제거한다.
HP 실패로 중단한 부분 관측을 완전한 점수로 반환하지 않는다. 같은 조합을 나중에 완전 평가할 수 있다.

이는 표본 수를 줄이는 근사가 아니라 중복 계산을 제거하는 변경이다.
운영 소스의 기존 공통 물리·조건 모듈28개와 입력4개는 같은 내용이다.
평가기 자체는 캐시를 추가했으므로 이전 파일과 바이트가 같다고 주장하지 않는다.
별도 검증은 Git에 보존한v13 평가기를 직접 읽어, 새 평가기의 캐시 비활성 경로와도 독립적으로 모든 반환 필드를 비교한다.

### 완성 조합의 성능 분포로 압축

이전에는 계승·진화·가속ID가 달라도 각각 별도 구조로 남겨 근접한 완성 조합도 잘 압축되지 않았다.
새 [압축 분류](../assets/cm-plan-compression.mjs)는 전체 조합을 비교할 때
실제 HP/위험 우선순위와 전개별 기여 분포를 사용한다.
평균과 각 전개의 기여가 모두0.1 이내이고 전개별 HP 충족률이 같은 조합만 같은 근접 구간으로 묶는다.
구간의 최고 기여와 최소 비용 대표를 보존한다. 첫 기준을 고정해 근접 관계를 이어 붙여 구간을 넓히지 않는다.

회복·패시브, 발동 개수 조건을 쓰는 스킬, 명시적 보유/사용 참조를 가진 스킬은 실제ID로 구분한다.
선택한 조합에 발동 개수 조건을 쓰는 소비자가 있으면 그 원본 조건의 개수·구간별 기여자도 구분한다.
사용하지 않는 소비자 때문에 모든 조합을 불필요하게 세분하지 않는다.
보유 참조는 상·하위 보유 관계를 포함한다. 모르는 개수 조건은 기여자ID를 보존한다.

계승·진화·가속도 원본 후보나 조건을 삭제하지 않는다. 전체 조합을 다음 단계로 보낼 대표만 고른다.
최종 주행은 선택한 실제ID·조건·확률·회복·획득·진화 제약을 그대로 사용한다.
이는 완성 조합 선별용 근사이며, 나중에 어떤 스킬을 추가해도 같은 결과라는 동등성 증명이 아니다.

### 불안정한 후보에 평가를 집중

모든 단독 후보를0.01초 간격36표본에서 비교한다. 앞·뒤 표본의 평균 차이가 허용 범위보다 크면
72표본으로 늘리고, 계속 크면144표본으로 늘린다. 모든 전개를 포함하는 표본 수를 사용한다.
이 차이는 계산량을 배분하는 기준이며 신뢰구간이나 실측 오차 한도가 아니다.
기여순·효율순의 두 완성 조합 끝점과 기본 습득 조합도 최종 평가에 남긴다.

HP를 전부 충족한 최종 조합이 있을 때는 직접 변경을 먼저 같은 미세 시간 간격의 표본에서 비교한다.
이 동일 표본 일부에서HP를 실패한 조합은 전체 표본HP 충족 목표를 이길 수 없으므로 정밀 확대를 생략할 수 있다.
다른 후보는 기여·표본 변동·연계 구조로 대표를 선별한다.
모두HP 미충족일 때의 직접 이웃은 기존처럼 전체 표본으로 비교해 미세한 HP 부족량도 보존한다.

개별 기여가0.1보다 작다고 스킬이나 변경을 버리지 않는다.
예비 비교에서 유리한 여러 변경을 묶은 제안도 별도로 전체144표본으로 평가한다.
정밀 평가에서 유리한 변경을 묶은 제안도 유지한다. 작은 변경의 누적 이득과 복합 연계를 전체 조합으로 검증한다.
결과 점수는 단독 기여 합계나 임의 계수로 만들지 않는다.

### 탐색 예산과 선택 기준

초기 조합 발굴은 기존 `max(1400,1+3×후보 수)` 거친 평가 범위를 유지한다.
완성 조합 이후 후속 교체 선별은 기본 최대512평가로 줄인다.
사용자가 더 작은 평가 한도를 지정하면 그 한도를 따른다. 이는 계산 자원 한도이며 스킬별 가중치가 아니다.
정밀 후보와 복합 제안은 전체 조합으로 평가한다.

완전 평가한 최선의 조합을 고정 기준으로 삼고, 같은 HP·위험 우선순위에서 평균 기여가0.1 이내인 조합 중
SP가 가장 적은 조합을 고른다. 각 단계에서0.1씩 손실을 누적하는 비교를 사용하지 않는다.
더 싼 조합을 고르면 남은SP로 기존 최선에는 넣을 수 없던 추가 구매가 가능해질 수 있다.
따라서 싼 조합을 확정하기 전에 그 조합에서 추가·승급·시나리오 및 원본 조건에서 유도한 연계 묶음을 다시 확인한다.
새로 관측한 최선도 같은 전체 정밀 평가 집합의 기준으로 삼아 허용 손실을 누적하지 않는다.
이 재검토는 모든 전개를 포함한9표본에서 예비 비교하고, 전체 상위권·전개별 최선·저비용 대표를36표본으로 늘린다.
그 다음 상위 폭의2배·전개별 최선·저비용 대표와 여러 유리한 변경을 합친 제안만144표본으로 확대한다.
예비 평가도 최대512개를 공유하되 전체 단독 후보 한 번의 방문은 보장한다. 한도 소진은 결과에 표시한다.
삭제와 기존 환급 탐색 전체를 되풀이하지 않는다. 같은 선택을 재방문하지 않고, 최대12회 및 기존 공유 정밀 작업 예산 안에서만 반복한다.
이 과정의 반복 수·중단 사유와 예산 소진도 결과에 남긴다.
최종 표본·시간 간격·평가 수·재사용 수·단독 후보의 표본 수 분포를 결과에 남긴다.
`gainTolerance:0`은 압축·예비 선별을 끈 기존 정밀 경로와1400 후속 작업 기본값을 사용한다.
제한 탐색의 전역 최적성·미측정 전개에 관한 기존 한계는 유지한다.

## 다른 표본·시간 간격에서의 민감도

고정된 이전·현재 추천을 마일 두 예산·습득 하위 변경 두 예산·7000SP에서 비교했다.
기본144표본/0.01초,144표본/0.005초,다른 시드288표본,기존 시드576표본의20대조다.
대안 설정에서 다시 최적화한 결과나 실전 확률 측정은 아니다.

**4대조에서0.1을 넘는 차이가 관찰됐다.** 마일700SP와 습득 하위 변경700SP의 경우,
다른 시드에서 약0.1168~0.1169,576표본에서 약0.1249~0.1250마신 낮았다.
따라서 허용오차0.1을 모든 표본·추첨에서 보장한다고 설명하지 않는다.
같은 조건 검증과 표본 민감도를 분리하며 이 값을0.1로 반올림하지 않는다.
7000SP의 개선은 네 설정 모두 유지됐고 차이는 약+0.3963~+0.4317마신이었다.
20대조 모두 표본HP 충족률1·부진 구간 보호를 유지했다.
