# UMA PLAN 기초 데이터 수집 명세

기준일: 2026-10-02 / 서버: 일본 / 상태: 수집 설계와 공개 파일 연결 검증 완료.
이 문서는 실제 게임 계산 엔진의 검증 완료를 의미하지 않는다.

## 1. 확정 범위

- 육성 전 스킬·계승기·흰 인자 준비를 지원한다. 육성 과정이나 실제 계승 개체는 입력하지 않는다.
- 육성 우마무스메는 의상별로 구분하고 현재 해방 가능한 각성 MAX로 고정한다. 출시된 6·7단계도 후보에 포함한다. 개화만 입력하며 육성 중 레벨 상승 조건을 달성한 고유기 최종 레벨을 적용한다.
- 서포트는 카드 ID와 힌트·이벤트 스킬만 사용한다. 카드 레벨·성능해방·육성 성능은 계산 입력이 아니다.
- 서포트 이벤트의 완주·선택·성공 조건은 원본에 남겨도 후보 구성과 계산에는 적용하지 않는다.
- 체크한 스킬은 습득한 것으로 가정한다. 레이스에서의 사전 조건과 발동 조건은 계산 대상이다.
- SP 예산·합계·잔여량·힌트 할인은 정규화·계산 입력에서 제외한다. 가속 조합 비교용 기준 비용만 내부적으로 유지한다.
- 본체 고유·일반 계승 고유·진화 계승 고유·일반 스킬·본체 진화·시나리오 진화를 구분한다.
- 진화 조건 달성을 기본 가정으로 평가한다. 실제로 존재하는 진화형과 진화 분기·교체 관계는 정확히 보존한다.
- 일반 흰 스킬은 인자로 준비할 수 있는 기본 후보다. 목표 레이스에 유효하고 현재 편성의 일반 획득 경로가 없는 스킬을 추천한다. 추천·선택·계산은 스킬 ID만 사용한다.
- 현재 보유·편성 상태와 마신 순위는 마스터에 저장하지 않는다. 효과와 경로를 저장하고 요청 시 계산한다.

## 4. 일본 서버와 ID 처리

1. 원본의 일본어 이름과 일본 서버 효과를 기준으로 사용한다. 한국어 이름·별칭은 표시용으로만 연결한다.
2. 주 수집원에서 loc.en, loc.ko 등의 서버별 조건·효과를 JP 계산에 덮어쓰지 않는다. 어댑터가 본문이 JP 기준임을 확인한 파일만 채택한다.
3. UmaServer와 SupportServer가 global이라고 해서 일본 서버에서 미출시인 것은 아니다. 해당 플래그는 글로벌 출시 여부에서 파생된 것으로 확인했다.
4. 수집원별 ID 네임스페이스와 게임 ID를 구분한다. 공통 ID는 문자열로 보관한다. 이름 일치나 숫자 접두사만으로 스킬 종류·진화 관계를 추정하지 않는다.
5. 서로 다른 자료의 ID가 다르면 별도의 SourceIdMap에 검증된 대응만 등록한다. 한국어 번역명으로 자동 병합하지 않는다.
6. 신규 데이터와 기존 데이터가 충돌하면 최신 날짜만 보고 덮어쓰지 않는다. 항목별 출처·버전·효과 비교와 수정 근거를 남긴다.

## 6. 스킬과 획득 경로 추출

- condition_groups를 분기별로 유지하고 effects 배열을 효과별로 분리한다. 사전 조건, 분기 우선순위, 쿨다운, time_scale, value_scale, additional_activation을 버리지 않는다.
- 원문 조건과 해석한 조건을 함께 저장한다. AND/OR, 순위율, 이전 발동, 회복 횟수, 체력 비율 등의 의미를 키워드로 단순 치환하지 않는다.
- char와 char_e를 의상별 가용 경로로 뒤집어 저장한다. 현재 각성 MAX 고정이므로 사용자 각성 상태에 따른 필터는 없다. 출시된 6·7단계도 포함하고 사전 수록된 미래 단계·진화형은 해방일부터 포함한다.
- sup_hint와 sup_e의 중첩 카드 ID 목록을 경로별로 펼친다. support_hints.json의 빈 SkillId와 능력치 보너스 항목은 스킬로 가져오지 않는다.
- 서포트 이벤트 조건으로 경로를 제한하지 않는다. 여러 경로가 같은 스킬을 제공하면 스킬은 하나, 경로는 여러 개로 유지한다.
- sce_e는 시나리오 획득 경로로, pre_evo와 evo는 원본·진화 연결로 저장한다. 시나리오 진화는 선택 시나리오와 원본 스킬 가용 여부가 맞을 때만 연결한다.
- 기본 SP는 가속 조합 비교에 필요한 스킬과 그 비용 관계만 정규화한다. 진화형의 0 비용이나 비용 미기재를 임의로 무료 습득으로 처리하지 않는다. 할인·SP 예산·전체 합계는 없다.

## 7. 일반 계승과 진화 계승

gene_version만 펼치면 일반 계승형을 모두 확보한다고 가정하지 않는다.
이번 데이터에서 아래 세 고유기는 gene_version이 진화 계승형을 제공하여 일반 계승형이 빠져 있었다.

| 본체 이름 | 일반 계승 ID | 진화 계승 ID |
| --- | --- | --- |
| 黄金を訪ねて | 901351 | 91101351 |
| 光れ！弾けろ！超新星爆発！ | 901411 | 91101411 |
| ずっとずっと輝いて | 911091 | 92111091 |

일반 계승과 진화 계승을 모두 보존하고, 계승형의 효과를 본체 효과에 일정 비율을 곱해 생성하지 않는다. 보조 수집원의 일반 계승형은 ID·효과 대응 확인 후 보완한다.

계승 진화의 보유 조건과 육성 시작 시 힌트 조건은 EvolutionRule에 별도 저장한다. 에피파네이아 공지에서는 해당 의상 보유와 시작 시 힌트 획득 조건을 확인했다. 현재 설계의 진화 조건 달성 가정은 유지하되 필요한 준비 조건을 숨기지 않고, 향후 보유 우마무스메 목록과 연결할 수 있게 한다. 실제 부모 개체나 친구 검색 데이터는 필요 없다.

## 8. 인자로 준비할 스킬 추천

이 탭은 인자 클래스나 부모 개체를 찾는 기능이 아니다. 일반 흰 스킬에서 육성 전에 인자로 준비할 스킬을 추천한다. 추천 항목 하나와 선택 ID 하나는 SkillMaster의 스킬 한 개를 뜻한다. 일반 흰 스킬은 인자로 준비 가능한 기본 후보로 취급하며 별도의 인자 마스터 매핑으로 후보를 제한하지 않는다.

1. 일본 서버에서 현재 사용 가능한 일반 흰 스킬을 SkillMaster에서 추출한다.
2. 선택한 코스·각질 조건에 맞지 않거나 유효 이득이 없는 스킬을 먼저 제외한다. 미지원 효과·조건은 계산 미지원으로 관리한다.
3. 육성 우마무스메·서포트·시나리오의 일반 획득 경로로 이미 얻을 수 있는 스킬을 제외한다. 상위·하위 및 교체 관계로 중복 추천하지 않는다.
4. 현재 선택한 속도·가속 조합에서 추가·제외 마신을 계산해 최대 10개를 출력한다.
5. 체크한 스킬은 습득 가정에 넣고 가속 추천과 스태미나 결과를 재계산한다. 순위가 바뀌어도 선택은 유지한다.

- 표시 내용은 스킬명, 속도/가속 구분, 마신 이득, 선택 토글이다. 탭의 의미는 ‘이 스킬을 인자로 준비하세요’다.
- 금색·진화·고유·계승 고유는 일반 흰 스킬 후보와 구분한다. 계승 고유는 속도/가속 탭의 기존 추천 경로를 사용한다.
- 인자 ID·그룹·별수·생성/계승 확률·기간·레이스 인자 클래스·부모 개체·프렌드 정보는 필요하지 않다. FactorMaster와 FactorSkillLink는 추천 엔진의 필수 테이블이 아니다.
- 기존 인자 원본 조사와 날짜·스킬 연결 검사는 참고 기록으로만 보존한다. 인자 자료 미확보 또는 인자 ID 대응 미확인을 추천 차단 사유로 사용하지 않는다.
- 일반 획득 경로가 새로 생긴 선택 스킬은 일반 목록으로 이동하며 효과를 중복 적용하지 않는다.
- 후보 사전 필터·계산 캐시를 사용한다. 스킬의 효과·조건 미지원은 계속 구분하지만 별도 인자 대응 미확인 때문에 후보를 버리지 않는다.

## 9. 코스·챔미·능력치 규칙

- 경기장+거리만으로 코스를 식별하지 않고 course_id와 내외·노면·방향을 확인한다.
- 코너·직선·경사 구간은 시작과 끝을 미터로 보관하고 경사 값의 단위를 명시한다. 마지막 코너·최종 직선·종반 경계는 원본 구조와 규칙에 따라 판단한다.
- 롱샹 2400m의 폴스 스트레이트는 단순히 최종 코너 이후라는 이유로 최종 직선으로 합치지 않는다.
- master.mdb만으로 상세 코스 지형을 모두 확보할 수 있다고 가정하지 않는다. 확인한 추출기는 별도의 CourseParamTable.json 코스 자산을 요구한다.
- races.json의 18인 등 육성 레이스 조건을 챔미 조건에 그대로 사용하지 않는다. 공식 챔미 프리셋의 출주 수·날씨 등을 별도로 저장한다.
- 목표 능력치 입력에는 표시 능력치와 적용 규칙 버전을 남긴다. 고유기 레벨·고능력치 보정·적성·의욕·코스 보정·스태미나 규칙은 버전별 계산 규칙으로 검증한다.
- 첫 검증 코스 후보: 롱샹 2400m(11203), 도쿄 2400m(10606), 나카야마 2500m(10506). 특정 챔미 개최 조건을 이 수집 명세에서 임의로 확정하지 않는다.

## 10. 데이터 검증과 적용 기준

| 구분 | 적용 전에 확인할 내용 |
| --- | --- |
| 형식 | 필수 필드, ID 중복, 알 수 없는 효과 코드·조건 변수, 값·단위·스키마 변화 |
| 연결 | 스킬·의상·카드·시나리오·원본/진화·계승 참조 누락 |
| 획득 | 자체·각성·서포트 힌트·서포트 이벤트·시나리오 경로의 누락과 중복 |
| 계승 | 일반 계승과 진화 계승이 모두 존재하는지, 잘못된 본체 효과 재사용 여부 |
| 인자로 준비할 스킬 | 일반 흰 스킬 분류, 현재 획득 경로 부재, 효과·조건 지원, 스킬 ID 중복 제거 |
| 코스 | 구간 범위·길이·순서, 거리·노면·방향·경기장 일치, 최종 직선 구분 |
| 계산 지원 | 정확 계산/가정 포함/근사/미지원 상태와 해당 효과·조건의 검증 근거 |
| 결과 | 단순 마신 합산 금지, 선택 변경에 따른 재계산, 동일 버전의 재현 가능성 |

DB에 존재하는 스킬과 계산 가능한 스킬은 구분한다. 상대 순위·몸싸움·추월·상대 스킬에 의존하는 조건은 전체 레이스 시뮬레이션 없이도 선택한 가정으로 비교할 수 있지만, 정확한 실전 발동 확률로 표시하지 않는다. 미지원은 0마신으로 반환하지 않는다.

## 11. 갱신 절차

1. 원본을 새 스냅샷에 저장한다. URL·커밋·실제 데이터 기준일·파일 SHA-256을 남긴다.
2. 이전 버전과 비교하여 신규/변경/삭제 스킬, 획득 경로, 코스, 조건 코드, 효과 코드를 분리한다.
3. 원본→정규화 변환과 연결 검사를 수행한다. 수동 수정은 별도 패치와 근거로 보존한다.
4. 계산 지원표와 대표 사례를 검증한다. 파일 날짜가 새롭다는 이유만으로 계산 가능으로 승격하지 않는다.
5. 검증된 데이터 묶음과 계산 규칙을 함께 배포한다. 실패 시 이전 검증 버전을 유지한다.
6. 데이터/엔진/가정 버전을 계산 캐시 키에 넣는다. 과거 결과를 새 버전 결과로 섞지 않는다.

운영 배치는 배포 후 신규 카드·캐릭터·밸런스·시나리오·챔미 공지 갱신에 맞춰 설계한다. 이 문서 작성으로 외부 사이트 반복 조회나 예약 작업을 시작하지 않는다.

## 12. 구현 순서와 남은 항목

1. 원본 다운로드·버전 기록과 JSON 형식 검사를 구현한다.
2. 스킬·효과·발동 조건·의상·서포트·획득 경로의 정규화 DB를 구성한다.
3. 본체·일반 계승·진화 계승·본체 진화·시나리오 진화 관계를 연결한다.
4. 일반 흰 스킬과 현재 편성의 획득 경로를 대조하여 인자로 준비할 후보를 구성한다. 별도 인자 원본 취득은 필수 단계가 아니다.
5. 코스와 공식 챔미 프리셋을 분리해 연결한다.
6. 한 코스·한 각질에서 스킬 후보와 흰 인자 후보를 검증한 뒤 실제 계산 엔진을 연결한다.

우선 보완할 항목은 일반 흰 스킬 분류와 상위·하위 관계, 계승 진화 준비 조건, 최신 시나리오 목록과 진화 선택 제한, 고유기 레벨·고능력치·스태미나 계산 규칙이다. 이 항목들이 미확인인 상태에서 전체 최신 일섭 대응을 선언하지 않는다.

## 13. 최신 소스 추가 점검 (2026-10-02)

9/30 신규 의상·서포트, 맥퀸 기존 스킬 조정, 10/1 히시 미라클 진화 추가가 주 수집원에 반영된 것을 확인했다. 추가 JP 공개 소스로 xancia/NewmaMusumeAPI와 Tsuyuchan-jp/umamusume-data를 확인했다. 최신 인자 목록은 참고로 확보했다. 현재 목표는 인자로 준비할 스킬을 안내하는 것이므로 인자 ID와 스킬 ID의 별도 매핑은 필수 요건에서 제외한다.

각성은 MAX로 고정하고 현재 해방 가능한 6·7단계까지 포함한다. 단계 데이터는 사용자 입력 대신 출시·해방 여부 검증에 사용한다. 일반 계승 3종은 xancia·umasim으로 보완할 수 있다. Tsuyuchan의 트레센켄 자료는 획득 경로·링크·선택 제한의 보완 후보이며 전체 시나리오 자료가 아니다.

alpha 상세 코스의 실제 파일 커밋은 2026-02-24이며 2026-10-02 현재 공개 파일과 검사한 138개 파일의 SHA-256이 일치한다. 140개 목록과의 차이는 롱샹 1000m·1400m이며, 두 코스는 U-tools의 상세 구간과 사용 레이스 목록도 비어 있다. 확인한 공개 챔미 개최 이력에도 없다. 롱샹 2400m는 상세 지형이 있고 2026년 9월 공식 챔미 개최가 확인된다. 1000m·1400m를 미수집된 필수 챔미 코스로 간주하지 않고, 목록에는 보존하되 검증된 실제 사용 조건·지형이 확보될 때까지 계산 선택에서 제외한다.

세부 채택 범위와 한계는 SOURCE_FRESHNESS_CHECK.md, 파일 해시·수록 수·최신 변경 대조 결과는 data/latest-source-audit.json을 따른다. 계산 규칙의 검증 상태와 최신 전체 커버리지 미확인 상태는 유지한다.

## 14. 최소 소스 동기화 설계 (2026-10-02)

정기 동기화의 주 소스는 UmaTools, 스킬·시나리오 보완은 umasim으로 정리한다. UmaTools의 skills_all.json, uma_data.json, support_hints.json과 umasim의 skill_data.txt, ramen_memo.md를 변경 해시 기준으로 확인한다. 카드 카탈로그는 support_hints.json에 포함되어 별도 support_card.json을 수집하지 않는다. xancia와 Tsuyuchan은 기존 조사 기록으로 보존하며 정기 수집 대상에서는 제외한다.

최소 운영안은 두 저장소를 매일 동기화하고 alpha 상세 코스 스냅샷을 별도로 관리한다. 전체 출처는 세 곳이다. 코스 원본 변경 감시까지 자동화하려면 alpha의 course_data.json도 세 번째 정기 대상으로 추가한다. umasim의 코스 자료는 누락 ID와 경사·runUp 좌표·직선 분류 차이가 있어 기존 alpha 자료를 바로 대체하지 않는다.

시나리오 메모는 자동 적용 가능한 완전한 DB가 아니므로 변경을 검토 신호로 사용한다. 공식 프리셋·예외 관계·출시 확인은 근거가 있는 자체 보완 JSON으로 관리하며 이 규칙 자료의 검증 작업은 남아 있다. 흰 인자 추천은 일반 흰 스킬 ID를 사용하므로 별도 인자 DB를 정기 수집하지 않는다.

한국 시간 자정 트리거는 schedule의 timezone: Asia/Seoul과 cron: '0 0 * * *'로 설계한다. UmaTools의 정기 수집은 오전 8시이므로 자체 동기화 성공과 현재 게임 데이터의 최신 반영은 구분한다. 상세 운영안·상위 갱신 지연·검증 실패 처리·필수 파일은 SOURCE_SYNC_DESIGN.md, 직접 비교 기록은 data/source-sync-audit.json을 따른다. 실제 수집 스크립트와 GitHub workflow는 아직 설치하지 않았다.
