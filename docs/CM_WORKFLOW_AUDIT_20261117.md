# 인게임 육성·챔피언스 미팅 기준 전체 흐름 점검

> 아래는 수정 전 점검 기록이다. 5개 항목의 구현·수정 후 검증은 [보완 결과](CM_WORKFLOW_FIXES_20261117.md)를 따른다. 기존 반례와 수치는 당시 증거로 보존한다.

점검일: 2026-11-17 (Asia/Seoul). 기능 기준: main `79fd514`, 데이터 `59fd2b3c2fd1…`.
대상: 공개 CM 화면과 `cm-first-chart-v5` → `cm-target-acceleration-v3` → `cm-post-training-v8`.

전체 단계 분리는 유지할 만하다. 실제 SP·구매·진화를 함께 계산하는 방향도 맞다.
다만 **회복 발동 조건, 단계 사이의 순위 비교 기준, 시나리오 선택 레어의 사전 안내,
일괄 입력의 습득 이력 보존**은 보완해야 한다. 단독 주행 마신만으로 CM 전략 전체의
우선순위를 확정할 수도 없다. 이번 점검은 제품 계산 동작을 수정하지 않고 문제와 재현 자료를 기록한다.

## 1. 실제 게임과 맞춰 사용할 순서

| 시점 | 사용자가 하는 일 | 앱의 역할·현재 판정 |
| --- | --- | --- |
| 육성 전 | 목표 CM 조건, 육성마·각질·시나리오·편성을 정한다 | 현재 지원. 1차는 기본 시나리오 상한·적성A·최상 의욕의 비교값이며 예상 육성 성적이 아니다 |
| 육성 전 | 가속 목표·인자로 준비할 스킬·레어 선택 방향을 잡는다 | 가속 조합·서포트 레어 세트 지원. 시나리오 선택 레어 안내는 누락 가능 |
| 육성 중 | 이벤트 선택과 실제 힌트를 확보하고 목표 레이스에 필요한 스킬을 먼저 산다 | 추천은 목표이며 확보 확정이 아니다. 실제로 산 스킬은 `습득`, 아직 안 산 힌트는 Lv0~5로 구분해야 한다 |
| 최종 구매 전 | 마지막 보상 반영 후 실제 스탯·적성·남은 SP·할인·힌트·진화 가능 여부를 확인한다 | 현재 두 번째 탭의 실질적 사용 시점. 인게임 육성 완료를 확정하기 전에 사용한다 |
| 최종 구매·진화 | 원본 레어·하위 단계를 사고 육성 완료 시 가능한 진화를 선택한다 | 구매·각성 진화·시나리오 진화를 공동 탐색하는 현행 구조 유지. 화면의 영역 분리는 계산을 분리한다는 뜻이 아니다 |
| CM 출전 판단 | 실제 보유 스킬, 전개·팀 구성·룸매치 결과를 확인한다 | 앱은 자기 성능의 조건부 비교 도구다. 승률·블로킹·상대 편성까지 검증한 완성 전략으로 해석하지 않는다 |

공식 FAQ는 레어를 습득하고 진화 조건을 충족한 상태에서 육성을 완료해야 진화할 수 있으며,
진화가 원본 레어를 덮어쓴다고 안내한다. 따라서 UI의 `육성 후 추천`은
**`최종 구매·진화 계획` 또는 `육성 마무리`**로 바꾸는 편이 실제 사용 시점을 명확히 한다.
진화 조건 자동 판정은 기존 합의대로 추가하지 않고, 조건 미달 후보의 수동 해제를 유지한다.

## 2. 유지할 수 있는 부분

- 카드 이벤트는 레어 묶음 단위로 관리하고 배타 선택지를 제한한다. 각성·다른 카드 등 독립 경로가 있으면 그 경로도 인정한다.
- 후보 힌트는 구매 필수가 아니다. 실제 힌트·할인과 남은 SP로 최종 구매 비용을 다시 계산한다.
- 이미 산 단계는 매몰 비용으로 처리하고 상하위 효과 중복·구매 비용 중복을 막는다.
- 각성 진화 분기와 시나리오 최대2개를 구매 탐색에 함께 넣는다. 시나리오15의 진화 후보는6개이며 반드시2개를 채우지 않는다.
- 계승은 속도·가속 합계 최대6개다. 현재 가속 목표의 계승도 같은 한도를 쓴다. 최소6개 규칙은 없다.
  이 개수 검사는 실제 부모·조부모 개체의 조합이나 강화 계승의 보유/직접 부모 조건까지 검증했다는 뜻은 아니다.
  해당 조건은 현재 충족 가정이며 사용자 확인이 필요하다. 보류한 부모 검색 기능을 이번 점검에서 추가하지 않는다.
- 가속은 조합 전체 주행과 추가 SP를 비교하고 초반 전용 가속을 종반 목표에서 제외한다.
- 목표 가속 유지는 선택적 제약이다. 확보하지 못한 목표를 구매한 것으로 간주하지 않고, 실제 SP가 부족하면 해제 후 재비교하도록 안내한다.
- 추천 자체가 실제 습득 기록을 바꾸지 않으며 입력 변경 시 기존 계산을 무효화한다.

7000 SP 재검증은 [v3 최종 연결 기록](validation/cm-acceleration-v3-7000-20261117.json)에 보존했다.
실제 1차231행 → 목표13개 → 실제 능력치·각질S·모든 후보 Lv5 → 최종 구매의 연결을 실행했다.
6996 SP 사용·4 SP 잔여, 계승6개·시나리오 진화2개, 목표13개 유지와 모델상 HP 충족을 확인했다.
41.9370마신은 현재 최종 단계의 조건 충족 가정값이며 실전 기대 마신이나 승률이 아니다.
이 사례는 모두 Lv5인 통제 입력으로, 실제 육성에서 해당 힌트가 모두 확보됨을 보증하지 않는다.

## 3. 보완할 사항

### P1 — 실제 HP 조건까지 제거해 회복 발동이 출발로 당겨진다

`cm-chart.mjs`의 `ASSUME`에는 `hp_per`가 있고 최종 단계도 같은 `compileChartSkill`을 쓴다.
따라서 자기 주행에서 계산 가능한 잔여 HP 조건도 제거된다.

실제 장거리 스킬 `火事場のバ鹿力`(200761)와 `別腹タンク`(200762)는 HP30% 이하에서 발동한다.
중산2500m·시나리오15 기본 스탯·선행의 같은 단독 주행에서 다음을 재현했다.

| 실제 스킬 | 현재 발동 | HP 조건 유지 대조 | 현재 잔여 HP 차이 | 조건 유지 잔여 HP 차이 |
| --- | --- | --- | --- | --- |
| 火事場のバ鹿力 | 0초·출발점 | 107.2초 | 약-0.17 | 약+192.57 |
| 別腹タンク | 0초·출발점 | 107.2초 | 0 | 약+54.44 |

HP는 해당 스킬이 없는 대조 주행 대비 잔여량 차이로, 금색의 속도 효과에 따른 소비 변화도 포함한다.
HP가 가득 찬 출발점에서 회복을 사용해 낭비한다. 금색은 속도 효과의 시점도 달라진다.
이는 회복 효율·SP 배분을 왜곡하는 구체적 오류다. 표는 조건 한 가지의 영향을 분리한 대조 계산이며 실제 레이스 실측값은 아니다.

**수정 방향:** 상대 위치 같은 외부 조건 가정과, 자기 HP·보유 스킬·실제 발동 이력처럼
주행 중 계산할 수 있는 조건을 구분한다. 적어도 최종 구매의 HP 조건은 유지해야 한다.
발동 시점·회복 상한·고갈 이전/이후·다른 회복을 먼저 쓴 경우까지 회귀 검사한다.

### P1 — 가속 목표와 최종 구매가 다른 순위 기준을 사용한다

목표 가속과 레어 세트는 `createPositionComparison`으로 선행2~5위 등 고정 순위를 나눠 비교한다.
최종 구매는 일반 `simulateSolo`를 호출해 순위 조건을 모두 충족한다고 가정한다.
따라서 같은 시점에 서로 다른 순위가 필요한 스킬도 한 주행에서 동시에 발동할 수 있다.

[진단 JSON](validation/cm-workflow-20261117.json)의 통제 반례에서는 동일 최종반 시작에
`2위 이내`와 `5위 이하`인 두 속도기가 **91.49초·1833.55m에서 동시에 발동**했고 최종 추천에 모두 들어갔다.
현행 최종 점수는1.5122마신, 같은 선택을 목표 단계의2~5위 비교에 넣은 값은0.3870마신이다.
두 번째 값도 순위 확률을 측정한 기대값이 아니므로 실전 정답이나 실제 오차율로 해석하면 안 된다.
핵심은 단계가 바뀌면서 조건 평가 기준도 바뀐다는 점이다.

실제7000 SP 결과의 동일59개 적용 스킬도 비교했다. 현행 최종 점수41.9370마신에 대해
목표 단계의 순위 정책으로 같은 선택만 재평가한 값은40.8531마신이다.
이는 새로운 순위 정책으로 다시 최적화한 결과도, 게임 실측 대비 오차도 아니다.
통제 반례의 비율을 전체 실제 추천의 오차율로 일반화하지 않는다.

**수정 방향:** 최종 구매·회복 비교에도 같은 순위 민감도 정책을 연결하고 JSON·화면의 비교 기준을 통일한다.
순위 이동이나 9인 레이스 전체를 구현하는 확장과는 구분한다.

### P1 — 시나리오 선택형 레어가 육성 전 확보 안내에 없다

`EventConstraints`에는 시나리오 이벤트도 들어가지만 목표 추천의 `goldGroups`는 `card_id`가 있는 그룹만 비교한다.
즉 카드 레어 세트는 안내하되 시나리오 이벤트의 레어 선택은 같은 흐름에서 안내하지 않는다.

실제 예시 편성의 `15-link-skill`에는 마야노 링크의 `順風満帆`(204071), 아즈마 링크의
`螺旋のエキスパート`(204811)라는 두 유효 레어 선택이 있다.
가속 목표의 `eventChoices`에는 해당 이벤트 선택이 없고 `rewards`에도 표시되지 않았다.
7000 SP 최종 계산은 나중에6번을 선택하지만, 실제 사용자는 그 전에 육성 이벤트에서 선택해야 한다.
실제 체크리스트에 얻은 쪽만 기록하면 구매 가능성은 제한되지만 사전 의사결정 지원의 공백은 남는다.

**수정 방향:** 카드 레어 세트와 같은 목표 기준으로 시나리오의 선택형 레어도 비교하고,
시나리오 획득 세트·연결 가능한 진화 후보를 육성 전에 안내한다. 일회 선택 레어와 최대2개 진화는 다른 제약으로 유지한다.
상세 이벤트 문구 전수조사나 모든 선택지 수집으로 범위를 확대할 필요는 없다.

### P1 — 전체 할인 Lv5가 이미 산 스킬을 미습득으로 바꾼다

`bulkAcquisition(..., '5')`는 기존 `owned`도 `'5'`로 바꾸고 그 상태를 실제 기록으로 저장한다.
기존 테스트도 이를 현재 일괄 입력 계약으로 허용한다. 의도된 구현이지만 최종 구매 흐름에는 위험한 상호작용이다.

통제 사례에서 이미 산100 SP 단계를 포함하는 목록에 전체 Lv5를 누르면,
해당 단계의 남은 구매 비용이0에서60 SP로 바뀌었다. 실제 게임의 보유 SP는 이미 그 구매를 반영한 값이다.
사용자가 구매 이력을 다시 복원하지 않으면 구매 효과·남은 예산 비교가 달라진다.

**수정 방향:** 실제 기록 화면의 전체 Lv5는 `습득`을 보존하고 나머지 미습득 후보에만 적용한다.
`전체 미획득`처럼 기록 전체를 초기화하는 별도 동작과 역할을 분명히 한다.
실제 힌트 기록과 이상적인 Lv5 가정도 구별한다. 기존 습득 이력을 읽고 다시 추천하는 회귀 검사가 필요하다.

### P2 — 단독 마신과 CM 전략 우선순위 사이에 보완층이 필요하다

현재 주행에는 상대·포지션 킵·PDM·횡방향 블로킹·팀 구성 변화가 없다.
따라서 중반 위치 확보, 초반 위치 하락 방지, 추월·앞마 차단 조건을 통한 가치가 모두 숫자에 반영되지는 않는다.

예를 들어 직접 공략을 작성한 우마무스메 라보는 교토2200m와 중산2500m에서
비도주 각질의 `ウマ好み`를 PDM 해제용 핵심으로 설명한다.
현행 단독 마신은 교토 선행0.5150, 중산 선행0.5942·선입0.5872·추입0.6040으로 계산된다.
이 값은 직접 속도 효과만 포함하며 PDM 해제의 가치가 아니다.
이번7000 SP 결과에는 실제로 포함됐으므로 항상 누락된다고 주장하지 않는다.

**수정 방향:** 코스·각질별로 출처가 있는 전략 필수·보조 후보를 별도 표시하고
사용자가 확보 목표 또는 구매 고정으로 유지할 수 있게 한다. 측정하지 않은 가상 마신을 더하지 않는다.
디버프·상대 주행 모델이나 부모 조합/프렌드 검색은 보류된 범위로 유지한다.

### P2 — 단계 이름과 현행 기획 문서가 뒤처져 있다

- 두 번째 탭의 `육성 후`는 최종 확정 이후로 오해할 수 있다. 사용 시점은 최종 스킬 구매 전으로 안내해야 한다.
- 진화 후보는 기본적으로 조건 달성을 가정하며 실제 실패는 사용자가 해제한다. 이 합의는 유지하되 마무리 단계에서 확인하기 쉬워야 한다.
- 원래 `PROJECT_PLAN`은 육성 전 예상 총SP 입력과 자동 편성을 현행 제품 기준으로 적고 있지만 공개 CM 루트는 다르게 동작한다.
- 진행 문서에는 미병합 브랜치, v7, 철회된6990 SP 예시, 이미 바뀐 종료 스킬 기본 효과 정책이 남아 있었다.
- `verify_cm_target_final.mjs`가 v2 파일만 읽어 v3 감사 자료를 만든 뒤에도 해시 검사가 실패했다.
