# 최적화 알고리즘 v1 — 프론트엔드 연결 검수

검수일: **2026-11-18 Asia/Seoul** · 브랜치 `feat/cm-first-chart`

사용자 결정에 따라 현재 완성본의 공개 명칭을 **최적화 알고리즘 v1**으로 정했다.
마신표·후보 수집·조건/확률·구매 가격·조합 탐색의 계산 모듈30개는 원래 운영 커밋과 같다.
프론트엔드에서의 입력 전달·취소·결과 표시·저장 복원·내보내기를 검수하고, 확인한 연결 문제를 수정했다.

## 1. 명칭과 고정 계산 기준

| 항목 | 기준 |
| --- | --- |
| 사용자 표시 | 최적화 알고리즘 v1 |
| 공개 식별자 | `umaboard-optimization-v1` |
| 1차 마신표 모델 | `cm-first-chart-v11` 유지 |
| 최종 추천 모델 | `cm-post-training-v11` 유지 |
| 공통 단독 비교 모델 | `solo-comparison-v5` 유지 |
| 원래 운영 커밋 | `d3b40fddf28fb6eb28b045afd65583b0ae3b11f6` |
| 고정 계산 묶음 SHA256 | `b850f80fb6bbada03f3d03eb64af1baad91a465b2e5fb937a123cb93f465811c` |
| 활성 데이터 | `0b105741168200654ef4ef6523e1cb0bc0b7d9852107f3d478ea0fdcd6b7ad26` |

v1은 이미 확정한 계산의 공개 릴리스 명칭이다. 내부 모델 ID를 v1으로 바꾸어 과거 결과·캐시 의미를 섞지 않았다.
기존 브라우저 저장 키 `umaboard-cm-workspace-v1`, 계획 키, 힌트/습득 값과 `schemaVersion:1`도 유지했다.
마신표와 추천의 두 JSON 내보내기에 같은 `algorithm` 메타데이터를 추가했다.

[새 계산 기준 파일](validation/cm-optimization-v1-release-20261118.json)은 두 계산 진입점의
정적 의존 모듈30개를 원래 운영 커밋과 대조한 해시와 이전 완료 기준 파일의 해시를 기록한다.
[동일성 확인 도구](../scripts/check_cm_algorithm_v1.mjs)는 의존 모듈 목록·내용·모델·입력4개·기존 증거10개를 확인한다.
`--build`에서는 배포용30모듈도 확인하며, 빌드가 붙이는 모듈 캐시 버전만 제거해 원본과 대조한다.
CI에도 이 검사를 추가했다. 이전 전체 assets 기준 파일과 과거 증거는 덮어쓰지 않았다.

## 2. 확인한 문제와 수정

| 확인 내용 | 수정 결과 |
| --- | --- |
| 완성된 마신표가 있는 상태에서 레이스 설정을 바꾸면, 이전 결과의 목록 저장 버튼이 계속 활성화됨 | 설정 변경 시 저장 버튼을 비활성화하고, 내보내기 함수도 계산 중·이전 결과 상태를 거부 |
| 마신표 JSON의 개별 행에 계산 상태·표본 HP 결과가 빠짐 | `calculationState`, `hpSuccessRate`, `hpShortfall`을 원래 계산 결과에서 그대로 보존 |
| 화면·다운로드에서 공개 알고리즘 명칭을 공유하지 않음 | `cm-algorithm-version.mjs`를 공통 소유자로 사용해 화면 표시와 두 다운로드에 v1 연결 |

오류 필드의 `aria-describedby`와 첫 오류 초점은 실제 브라우저에서 기존 구현이 정상임을 확인했다.
그 부분은 추가로 변경하지 않았다. 색·레이아웃·계산 입력·작업 단계 구조도 유지했다.

## 3. 실제 브라우저 연결 검사

[재실행 도구](../scripts/audit_cm_v1_frontend.cjs)는 Pages 빌드와 실제 Chrome의 모듈 Worker를 사용한다.
별도 브라우저 프로필에 기존 저장 형식의 시험 기록을 넣고 UI에서 작업한다.
계산 결과 메시지는 관찰만 하며 후보·수식·표본 수·검색 옵션이나 반환값을 대체하지 않는다.
기본144표본·0.01초 계산의 결과를 JSON 내보내기와 대조한다.
JSON의 `-0`→`0` 변환과 `undefined` 생략은 저장 형식에 맞춰 정규화한다.

**브라우저13검사 전부 통과했으며, 페이지 실행 오류는0건이었다.**
표시 마신표190행과 전체 계승 후보를 포함한 다운로드456행을 구분해 확인했다.
다운로드456행의 점수·계산 상태·HP·발동/유효 가속 빈도·표본/문맥 정보를 실제 Worker 결과와 대조했다.

능력치 조건 복원 입력은 시나리오8·파인 모션·교토3000·스태미나1800·200SP다.
상한 기준 마신표에서 비활성인 `204142`의 할인Lv2 기록이 육성 후 입력까지 유지됐고,
기존 v11과 같은 **144SP·0.1481436749595168마신**, 선택 `100221 + 204142`, 표본 HP 충족1로 나왔다.
화면은 +0.15마신으로 반올림하며 JSON은 원래 정밀도를 보존했다.
최종 다운로드의 전체 계산 결과도 실제 추천 Worker와 일치했다.

확인 항목:

1. v1 명칭, 기존 설정 복원, 초기 빈 화면과 육성 후 단계 잠금.
2. 마신표 계산 취소·이전 요청 무효화.
3. 실제 마신표 Worker의 개별 점수·계산 상태·HP·발동/유효 가속 빈도와 다운로드 일치.
4. 실제 능력치·힌트 복원과 오류 안내·첫 오류 초점.
5. 최종 추천 취소 후 기록 보존·늦은 결과 차단.
6. 중복 제출 방지, 기존 추천과의 수치/선택 일치, 최종 JSON의 전체 계산 결과 보존.
7. 모바일 결과 전환, 키보드 탭 이동, 하나의 체크리스트 유지.
8. 검색/검색 해제·화면 전환·네이티브 선택창 닫기에서 기록 유지와 불필요한 재계산 방지.
9. 실제 입력 변경 시 이전 결과 저장 차단·재추천 필요 표시.
10. 새로고침 후 명시적 재생성에서 능력치·힌트 복원, 이전 추천 자동 복원/자동 실행 방지.
11. 레이스 설정 변경 후 이전 마신표 저장과 육성 후 단계 차단.
12. 데이터 로드 실패 시 계산 차단과 복구 안내.
13. 브라우저 저장 실패 시 오류 표시와 계산 가능 상태 유지.

브라우저 검사는 별도 터미널에서 로컬 빌드를 제공한 뒤 실행한다.
검수에 사용한 도구 버전은 Playwright1.65.1이며 앱의 운영 의존성에는 추가하지 않았다.

```powershell
npm install --prefix .cache/browser-check --no-save --package-lock=false playwright@1.65.1
python -m http.server 8177 --bind 127.0.0.1 --directory .cache/pages
# 별도 터미널
node scripts/audit_cm_v1_frontend.cjs
```

다른 실행 환경에서는 `PLAYWRIGHT_MODULE`로 설치 경로, `CM_BROWSER_URL`로 로컬 주소를 지정할 수 있다.
Chrome 설치가 필요하며 계산은 모의 값으로 바꾸지 않아 마신표 재생성에 시간이 걸린다.

7000SP 회귀도 같은 선택·6990SP·35.51974580473648마신·표본 HP 충족1로 재현됐다.
이는 일괄Lv5·검토한 이벤트 선택을 가정한 기존 스트레스 입력이며 실측 육성 자료는 아니다.
