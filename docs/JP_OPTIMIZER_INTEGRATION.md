## 발견한 통합 문제와 수정

`data/manifest.json`에서 충돌했다. 기능 브랜치는 구매 모델을 포함하는 `d06524e0…`를,
main은 구매 모델 이전 어댑터가 생성한 `e15e87d5…`를 가리켰다.
main 쪽을 그대로 채택하면 `purchase_stages`, `support_events`, `cost_policy`, `purchase_order`가 빠진다.
그 상태에서 기존 최적화 테스트 14개 중 3개가 실패했다. 비용 검증과 이벤트 배타성이 실패했지만
일반 데이터 검증은 통과했으므로 manifest 파일만 충돌 해결하는 것은 충분하지 않았다.

수정 내용:

1. `sync_data.py --rebuild-active`를 추가했다. 현재 manifest의 source commit·blob을 그대로 사용하고
   현재 어댑터와 curated 규칙으로 재생성한다. 최신 ref를 새로 조회하거나 입력 원본 버전을 움직이지 않는다.
   기존 blob 해시·크기 검증, 불변 묶음 보존, 검증 후 원자적 활성화 절차를 그대로 사용한다.
2. 공통 데이터 검증에서 위 네 구매 모델 필드를 필수로 검사한다.
   CI와 Pages 빌드가 구매 모델 없는 구형 묶음을 승인하지 않도록 했다.
3. main의 원본 commit·blob·입력 SHA-256을 그대로 유지하며 활성 묶음을 재생성했다.
   활성 묶음은 `7e89257fb6e783424faee206dfcefedc1d5c687d887a491d3df88ee352f31bf7`이다.
   구매 모델 추가 필드를 제외한 모든 필드는 main의 활성 묶음과 같다.
4. 기존 구매 단계 1,170개는 변경 없이 보존되고 새 단계 3개가 추가됐다.
   총 1,173개 중 검증된 단계 1,157개·기존 미검증 단계 16개다.
   기존 6장 이벤트 보상·힌트·가격 정책도 변경 없이 보존했다.

최적화·구매·이벤트·수동 선택·편성 추천 엔진은 다시 구현하거나 수정하지 않았다.

## 검증 결과

Python 3.12.14, Node.js 24.19.0에서 실행했다. 원래 기능 묶음은 Python 25개·JavaScript 79개가 통과했다.
통합 후 Python **29개**, JavaScript **84개**가 통과했다. JavaScript에는 기존 최적화 14개와
새 JP 데이터 회귀 5개가 포함된다.

```sh
python -m unittest discover -s tests -v
node --test tests/*.test.mjs
python scripts/validate_data.py
python scripts/build_pages.py
for script in assets/*.mjs; do node --check "$script"; done
node --check prototype/model.js
node --check prototype/app.js
```

추가 회귀 검증:

- 구형 묶음의 구매 모델 누락 차단, 원본 ref 고정 재생성, 반복 실행의 동일성, 실패 시 manifest 보존.
- 활성 데이터와 curated 이벤트·가격 정책의 일치 및 모든 검증된 이벤트 보상의 카드 획득 경로 연결.
- 새 의상의 본체·진화·이벤트 스킬 후보와 계승 제공 의상, 하위 단계·진화 구매 비용.
- 교토 2,200m 새 의상의 예산 내 최적화, 구매 목록 합계 일치, 반복 실행 재현성, 수동 고정·제외 보존.
- 한신 더트 2,000m 실제 카드 목록으로 6장 추천. 스피드 3·스태미나 1·파워 1·지능 1,
  고정 카드 2장·렌탈 1장·고정 스킬·제외 스킬·포에버 영 이벤트 1번 선택 보존.
- Pages 산출물의 버전이 붙은 모듈·Worker를 로드해 계산·수동 고정/제외·SP 변경 후 재계산 확인.
  Worker API 확인은 Node의 `self` 어댑터를 사용했으며 실제 브라우저 UI 종단 검증과 구분한다.

데이터 검증 경고 5개는 기존 범위다: 코스 `10613` 격리, 미국 코스 2개의 좌표 검토,
수동 보완 대기, 미지원 효과 코드 보존. 새 데이터가 추가한 계산 경고는 없다.
Pages 검증은 이미지 다운로드 없는 기본 빌드다. 포트레잇 전체 다운로드와 실제 Pages 배포는 실행하지 않았다.

## 병합 판단과 남은 검증

이 main 버전에 대한 **데이터·SP 최적화 호환성은 통과**했다. manifest 충돌과 구매 모델 누락 문제는 해결됐다.
기존 기능 브랜치의 역사를 보존한 통합 브랜치를 main에 병합할 수 있다.
원격 CI 성공과 병합 시점 main의 추가 데이터 커밋 유무를 확인한 뒤 병합한다.
main이 이후 갱신되면 해당 변경을 다시 통합하고 같은 검증을 실행해야 한다.

다음은 이번 통합의 회귀가 아닌 기존 제품·모델 제한이다. 기획서의 모든 완료 기준을 달성했다는 뜻은 아니다.
