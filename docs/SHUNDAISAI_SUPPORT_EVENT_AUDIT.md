`support_events.30322`는 두 선택지의 2회차 그룹, 세 선택지의 마지막 그룹,
두 선택지의 일반 이벤트 그룹으로 나눴다. 서로 다른 이벤트를 하나의 배타 그룹으로 합치지 않았다.
선택별 `rewards`에는 현재 엔진 정책인 대성공 보상을 넣었고, `outcomes`에 일반 성공도 보존했다.
`assumed_outcome`과 기본 보상이 일치하는지 검증한다. 결과별 보상을 합산하지 않는다.
확률·대성공 판정식·체인 발생률은 미확인으로 남겼다.

해금 이벤트 발생 확률·정확한 인연 임계값은 확인하지 못해 임의의 숫자를 넣지 않았다.

## 한글 이름과 별도 시나리오 보상

`curated/names-ko.json`에 `吾妻: 아즈마`를 추가했다. 사용자와 프로젝트에서 쓰는 한글 표기이며
공식 한국 서버 번역으로 확정한 것이 아니다. 캐릭터 단위 매핑이므로 R 10149에도 이름만 동일하게 적용한다.
R의 이벤트 보상은 이번에 검증하거나 추가하지 않았다. 일본어 카드명·스킬명과 ID는 유지한다.

[GameWith 시나리오 자료](https://gamewith.jp/uma-musume/article/show/578834)는 시니어 10월 전반 선택 보상으로
마야노의 順風満帆과 아즈마의 螺旋のエキスパート를 별도로 제시한다.
이것을 카드 고유 이벤트에서 항상 받는 금색으로 추가하면 안 된다.
정확한 시나리오 ID 연결·힌트 레벨·편성 조건·전체 선택지 배타를 이번 변경에서 확정하지 않았으며,
후속 [시나리오 검증·보완](SHUNDAISAI_SCENARIO_AUDIT.md)에서 공통 보상·링크 선택·진화 2개 제한을 함께 구현했다.

## 엔진 적용과 가격 예시

`events → choices → rewards[{skill_id, hint_level}]` 계약과 `PurchaseModel`을 그대로 사용한다.
두 카드 보상은 기존 이벤트 계약을 사용한다. 후속 시나리오 보완은 별도 기록에 설명한 획득·선택 로직을 확장한다. 원본 카드 획득 경로는 그대로다.
보완 메타데이터의 `source(s)`, `checked_at`, `condition_note`, `assumption`, `unverified`,
`outcomes`는 출처와 한계를 기록한다. `outcomes`는 현재 런타임에서 사용자가 전환하는 결과 모드가 아니다.

기존 가격 정책인 흰색 Lv5·금색 이벤트 힌트를 적용한 예시다.
흰색의 Lv5 가격은 표준 최적화 가정이며 실제 이벤트의 Lv1/Lv2/Lv3를 Lv5 보상이라고 주장하지 않는다.

| 선택 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 마야노의 英俊豪傑 + 선택 금색 하나 | 미검증 단일 금색 그룹으로 동시 구매 충돌 | 하위 스킬 포함 280 + 252 = 532SP |
| 아즈마의 神速 | 하위 快速 120 + 금색 Lv0 200 = 320SP | 하위 快速 120 + 금색 Lv3 140 = 260SP |
| 아즈마 해금 위 선택의 弧を描いて 경로 | 선택 조건 미기록 | 이 카드의 이벤트 경로 없음. 다른 출처가 없으면 흰 인자 준비 |

다른 카드·본체에서 같은 금색을 얻는 별도 경로는 엔진의 기존 규칙대로 허용한다.
이번 두 카드에만 검증된 그룹을 추가하며 다른 미검증 카드는 기존 보수적 처리와 Lv0 가격을 유지한다.

검증기는 이벤트 보상이 해당 카드의 `support_event` 획득 경로에 연결되어 있는지 확인한다.
원본 갱신으로 관계가 끊기거나 다른 결과 보상·중복 스킬·잘못된 힌트 레벨이 들어가면 활성화를 차단한다.

## 검증 결과

카드 보완의 신규 JS 테스트는 변경 전 데이터에서 첫 9개가 모두 실패했고,
보완 후 금색 쌍·배타·선택 고정·흰 인자 경로·이름·스킬 및 편성 최적화까지 통과했다.
다른 미검증 카드의 보수적 처리를 확인하는 테스트까지 신규 카드 JS 테스트는 10개다.

최종 활성 묶음과 전체 회귀 테스트 결과는 [통합 시나리오 검증 기록](SHUNDAISAI_SCENARIO_AUDIT.md#검증)에 기록한다.
카드·시나리오 보완은 사용자 승인에 따라 하나의 변경으로 커밋한다.
