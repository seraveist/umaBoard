# umaBoard 프로젝트 기획

기준일: 2026-10-08 / 일본 서버 전용 / 상태: feat/skill-budget-optimizer 브랜치에 1차 구현.

이 문서는 현재 프로젝트의 제품 기준이다. 과거 수집 설계의 SP 제외·이벤트 선택지 무시 정책보다 우선한다.
입력·출력의 목표 계약은 [MODEL_CONTRACT.md](MODEL_CONTRACT.md), 현재 엔진의 실제 지원 범위는
[ENGINE_VALIDATION.md](ENGINE_VALIDATION.md)를 따른다. 이 문서는 구현 브랜치 기준이며 main 공개 페이지 배포와는 별개다.

## 1. 프로젝트 정의

**육성 목표와 사용자가 입력한 예상 스탯·획득 SP에 따른 스킬 최적화 시뮬레이터.**

목표 레이스에서 유리한 스킬을 비교하고, 주어진 SP 안에서 속도·가속·회복·능력치 스킬을 조합한다.
본체·시나리오·서포트·계승의 습득 경로를 연결하여 서포트 이벤트 선택과 인자 준비 목록까지 정리한다.
육성 전 계획을 만드는 도구이며, 육성 결과의 스탯·획득 SP는 사용자가 정한 외부 입력이다.

서포트 편성은 스킬 후보와 이벤트 보상·힌트 경로를 결정하는 변수다.
서포트 추천도 입력한 스탯·SP를 공통 기준으로 하는 **스킬 확보 편성 추천**이다.
훈련 성능, 스탯 달성 확률, 실제 획득 SP를 추정하는 육성 모델은 개발 범위에 포함하지 않는다.

## 2. 입력과 고정 가정

| 구분 | 입력 또는 가정 |
| --- | --- |
| 레이스 | 경기장·코스·거리·노면·마장 상태·날씨·계절·시간 등 |
| 육성마 | 의상 ID, 개화 상태, 각질, 목표 적성, 의욕 |
| 예상 결과 | 스피드·스태미나·파워·근성·지능, 예상 획득 총 SP |
| 시나리오 | 스킬 획득 경로·진화 후보·선택 제한을 적용할 시나리오 |
| 직접 편성 | 사용자가 선택한 SSR 서포트 최대 6장 |
| 자동 편성 | 보유 SSR 목록, 렌탈 후보, 선택적인 타입별 장수·고정 카드 |
| 사용자 의도 | 선택 스킬, 반드시 구매할 스킬, 추천에서 제외할 스킬, 고정 이벤트 묶음 |

- 예상 획득 총 SP는 최종 스킬 구매 전체에 쓸 예산이다. 미리 구매할 스킬도 최종 목록과 비용에 포함한다.
  구매 후 남은 SP만 입력받는 모드와 혼용하지 않는다.
- 각성은 해당 의상에서 현재 공개된 MAX. 고유기는 개화에 따른 최종 레벨이며 레벨 상승 조건은 달성 가정이다.
- 본체·시나리오 진화는 조건 달성을 가정하되 실제 진화 분기와 선택 제한을 지킨다.
- 서포트 레벨·성능해방·훈련 성능은 입력하거나 평가하지 않는다. 보유 목록은 카드 ID와 보유 여부만 사용한다.
- 서포트 이벤트 완주·성공 확률은 계산하지 않는다. 선택한 묶음은 대성공한 것으로 가정한다.
  서로 다른 선택지의 보상을 동시에 얻을 수 있는지는 별도로 제한한다.
- 흰 인자는 일반 흰 스킬 ID로 취급하며 준비한 조건이 충족된 것으로 가정한다.
  실제 부모 개체, 별수, 인자 생성·계승 확률, 프렌드 검색은 입력하지 않는다.
- 훈련 인자·트레이너 어빌리티도 육성 성능 예측용 입력으로 요구하지 않는다.
  레이스 효과나 스킬 습득에 직접 필요한 조건이 있다면 그 조건만 별도로 검증한다.

육성마는 기본적으로 사용자가 선택한다. 여러 육성마의 비교 확장은 동일한 입력 스탯·SP에서의
고유기·보유 스킬 차이를 비교하는 기능으로 정의하며 편성별 육성 결과 예측으로 확대하지 않는다.

## 3. 최종 결과물

1. 레이스·각질·입력 스탯에 따른 속도·가속 마신표와 회복 HP 검토.
2. SP 예산 안에서 추천하는 구매 조합, 사용 SP·잔여 SP, 모델상 HP 충족 여부.
3. 본체·시나리오·서포트·이벤트 묶음별 확보 스킬과 이벤트 선택 경로.
4. 인자로 준비할 일반 흰 스킬 및 계승 고유기의 제공 육성마.
5. 자동 편성 사용 시 보유 카드·렌탈·타입 제한을 만족하는 편성 비교안.
6. 인게임 기본 스킬 획득 순서로 정렬한 최종 구매 목록. 마신표 순서와 구매 목록 순서는 별개다.

최종 구매 목록은 실제 구매할 항목 전체와 비용을 일치시킨다.
금색의 하위 흰색이나 ◎의 ○ 선행 비용을 누락하거나 중복 가산하지 않는다.
본체의 이미 보유한 고유기는 효과 계산에 적용하되 구매 비용은 0으로 구분한다.

## 4. 동작 흐름

1. 레이스·육성마·시나리오·예상 스탯·예상 획득 SP를 입력한다.
2. 직접 편성 또는 보유·렌탈 기준 자동 편성을 선택한다. 타입 비율은 선택적인 제한이며 자동도 허용한다.
3. 습득 경로와 유효 이벤트 묶음을 구성하고 계승·인자 보완 후보를 합친다.
4. 동일한 스탯·SP·발동 가정 아래에서 구매 조합을 평가하고 초기 추천을 제시한다.
5. 사용자가 스킬·이벤트·카드를 조정한다. 체크·경로·비용·예산 초과는 즉시 반영한다.
6. 버튼으로 현재 선택을 계산하거나 고정·제외 조건을 지키며 다시 최적화한다.
7. 확정한 상태의 편성·이벤트 선택·인자 준비·최종 구매 목록을 출력한다.

**습득 가능은 구매 필수가 아니다.** 확정 경로의 속도기 전체 고정 규칙은 폐기한다.
초기에는 예산 내 추천 조합을 선택하며 사용자가 원하는 항목만 고정할 수 있다.
속도 목록을 유지하고 싶으면 그 목록을 고정한 상태에서 가속·회복 후보를 최적화한다.

`선택 조합 계산`은 체크 상태를 유지하여 결과만 평가한다.
`스킬 최적화`는 고정·제외 조건을 지키며 나머지 구매 항목을 변경할 수 있다.
편성 고정 상태에서는 카드가 바뀌지 않는다. 편성까지 다시 추천하는 동작은 명시적으로 실행한다.
단순 토글이나 결과 표시 갱신으로 편성·체크 상태를 자동 변경하지 않는다.

## 5. 최적화 기준과 제약

### SP와 스킬 조합

- 모든 자동 추천은 총 구매 비용 <= 입력 SP를 만족한다. 수동 조합의 예산 초과는 표시한다.
- 고정 스킬만으로 예산을 넘기거나 조건이 충돌하면 원인을 반환한다. 자동으로 고정을 해제하지 않는다.
- 같은 레이스·입력 능력치·대조 조건에서 조합 전체를 비교한다. 개별 마신의 합이나 마신/SP 순으로만 구매하지 않는다.
- 속도·능력치 효과에 따른 진입속도·목표속도·체력 소비, 가속의 중복·연결, 복합 효과를 함께 반영한다.
- 하나의 후보 조합 안에서는 속도 상태를 고정하여 가속 효율을 계산한다.
  자동 추천 복합기를 다음 요청의 사용자 고정 스킬로 승격하지 않는다.
- 회복은 1인 최속 스퍼트 유지 HP 조건으로 평가하고 필요한 회복과 속도·가속의 SP 배분을 함께 비교한다.
  HP 부족을 실제 레이스 완주 불가능으로 단정하지 않는다. 적합 조합이 없으면 모델상 조건 미달을 표시한다.
- 최대는 예산 내 대표 발동의 조합 이득, 안전은 정의한 불리한 발동 표본의 조합 이득을 우선한다.
  동률은 낮은 비용을 우선한다. 예산 도입 이후 최대도 입력 예산을 넘기지 않는다.
- 효율은 최대에 가까운 이득과 낮은 비용의 절충 조합을 비교하는 확장으로 둔다.
  대표 조합의 손실 허용 기준을 검증한 뒤 추가하며 단일 마신/SP 비율의 최고값으로 정의하지 않는다.
- 큰 후보 집합은 후보 축소·근사 탐색·캐시를 사용하고 탐색 범위를 결과에 남긴다.
  검증되지 않은 전역 최적성을 주장하지 않는다.

### 관계와 발동

- 금색/하위 흰색, ○/◎, 원본/진화, 진화 분기는 비교 대안으로 보존한다. 같은 계열의 효과를 중첩 적용하지 않는다.
- ○와 ◎는 별도 비교 항목이며 ◎ 구매에는 ○ 선행 비용이 포함된다.
- 관계 그래프는 전체 DB에서 구성하고 후보 필터 이후에도 보존한다. 원본 금색이 숨겨져도 진화와 하위의 배타 관계를 잃지 않는다.
- 복합 스킬은 하나의 구매·효과 항목이다. 탭 양쪽에 있어도 비용·효과·계승 수를 한 번만 센다.
- 계승 고유기는 속도·가속 각각 TOP 10과 전체 선택 최대 6개를 유지한다. 후보 제한은 최적화 범위에도 명시한다.
- 마신표는 양수 이득을 표시하며 회복은 별도 HP 기여 기준을 사용한다. 미지원 효과를 0마신으로 취급하지 않는다.
- 조합의 연동 조건에 필요한 선행 스킬은 독립 이득만으로 지우지 않는다.
  표시·SP·최종 구매 목록 정책을 함께 검증하며 미검증 연동을 자동 추천의 근거로 사용하지 않는다.
- 地固め 같은 초반 가속의 전체 레이스 이득과 종반 가속 기여를 구분한다.
  종반에 영향을 주지 않는 초반 전용 가속을 종반 추천·상한·그래프의 근거로 사용하지 않는다.
  종반 전 발동이 종반 상태에 이어지는 접속 가속은 평가한다.

### 서포트와 이벤트

- 편성은 카드 자체 점수보다 해당 편성에서 구매 가능한 최종 스킬 조합을 기준으로 비교한다.
- 보유 카드와 최대 1장 렌탈을 합쳐 6장, 지정 타입 수·고정 카드와 검증된 인게임 편성 제한을 만족한다.
- 이벤트 묶음은 카드·이벤트 선택지 단위로 관리한다. 실제로 함께 받는 복수 금색을 허용한다.
- 묶음 배타는 획득 경로에 적용한다. 다른 카드·본체에서 같은 스킬을 얻을 수 있는 가능성까지 막지 않는다.
- 이벤트 묶음의 스킬 전부를 구매할 필요는 없다. 구매는 예산과 효과에 따라 별도로 결정한다.
- 모든 일반 흰 스킬을 인자로 준비하고 동일 할인으로 계산하면 직접 흰 힌트는 이득·가격 차이를 만들지 않을 수 있다.
  이 경우 인자 준비가 적은 편성을 보조 비교 기준으로 사용한다. 훈련 성능이 좋은 편성으로 해석하지 않는다.
- 스킬 획득상 의미가 없는 타입은 자동 장수 선택만으로 평가할 수 없다.
  시나리오별 편성 템플릿·필수 카드 또는 사용자 타입 제한으로 범위를 정한다.
- 이벤트 묶음이 미검증인 카드는 양립 불가능한 보상을 합쳐 추천하지 않는다. 미검증 경로는 분리하여 표시한다.

## 6. SP 계산 정책

| 항목 | 정책 |
| --- | --- |
| 일반 흰 스킬 | 최대 할인, 힌트 Lv5 기준 |
| 서포트 이벤트 금색 | 선택한 유효 묶음의 대성공 최대 힌트 Lv |
| 금색 전체 비용 | 하위 흰색 선행 비용 + 금색 단계 비용 |
| ◎ 전체 비용 | ○ 선행 비용 + ◎ 단계 비용 |
| 진화 | 원본 금색 구매 비용 적용, 별도 진화 SP를 임의 추가하지 않음 |
| 본체 고유기 | 이미 보유한 효과로 비용 0 |
| 본체·시나리오 금색, 계승형 | Lv0 표준 가격 가정. 실제 육성의 힌트 수준을 예측하지 않음 |

기본 힌트 할인은 Lv0~5 = 0/10/20/30/35/40%이며 단계별 할인 후 정수 내림으로 계산한다.
[UmaTools 가격 계산 문서](https://daftuyda.moe/guides/rating-system)의 할인·단계 가격을 대조하고 원본 데이터의 비용 의미를 검증한다.
切れ者 등 추가 할인은 초기 표준 가격에서 제외한다.
같은 단계·선행 스킬 비용은 한 번만 집계하며 선택한 유효 경로에서 누적 가능한 금색 힌트는 Lv5 상한을 적용한다.
원본 비용이 단계별인지 선행 포함인지부터 출처별로 검증한다.
금색을 선택했을 때 하위 흰색을 별도 구매 항목으로 다시 가산하지 않는다.
가격이나 힌트 정책이 없는 항목은 0 SP로 처리하지 않고 비용 미검증으로 반환한다.
필수 항목에 미검증 가격이 있으면 예산 충족을 확정하지 않으며 자동 최적화도 가격을 추정하여 통과시키지 않는다.

## 7. 화면 구성

현재 레이아웃과 간결한 결과 표시를 유지한다.

- 조건 입력에 예상 획득 총 SP를 추가한다. 직접 편성과 자동 편성 조건은 같은 영역의 모드로 구분한다.
- 속도·가속·스태미나 탭과 일반/계승 스크롤 프레임은 유지한다. 별도 흰 인자 탭은 만들지 않는다.
- 결과 상단에는 사용/잔여 SP, 계산·최적화 동작과 적용 상태를 요약한다.
- 하단 습득 경로에 선택 스킬, 레어도, 경로, 가격을 간결하게 보여준다.
- 필요한 이벤트 선택지와 인자 준비 목록을 최종 계획에 포함한다.
- 최종 구매 목록은 인게임 기본 순서로 정렬한다. 검증한 정렬 키가 없으면 기본 순서 일치를 주장하지 않는다.
- 체크·비용·경로는 즉시 갱신한다. 무거운 주행·조합·편성 비교는 버튼으로 Worker에서 실행한다.
- 수정한 선택과 마지막 계산 결과를 구분하며 미적용 변경이 남은 결과를 최종 확정으로 출력하지 않는다.
- 자동 편성의 비교안은 필요한 소수만 보여주고 육성 결과 예측 점수를 표시하지 않는다.

## 8. 데이터와 구현 순서

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1. 데이터 보완 | 단계별 비용·상하위/진화 관계·○/◎·이벤트 묶음·최대 힌트 | 중복·배타·출처·불명확 가격 검증 |
| 2. 구매 모델 | 총 SP 입력, 후보/구매/고정/제외 분리, 경로·가격·구매 순서 | 선택·가격 연결, 인게임 정렬 근거 확인 |
| 3. 스킬 최적화 | 고정 편성에서 예산 내 속도·가속·회복 조합 추천 | 예산·관계·HP·고정 조건 충족, 재현성 |
| 4. 편성 추천 | 보유 SSR·렌탈·타입 제한·고정 카드·이벤트 묶음 탐색 | 유효한 6장과 스킬 계획을 함께 반환 |

SP 없는 기존 가속 추천을 전체 스킬 최적화가 완성된 것으로 표시하지 않는다.
1~3단계만으로도 직접 편성 사용자가 최종 구매 계획을 만들 수 있어야 한다.
4단계도 입력 스탯·SP를 바꾸거나 육성 시뮬레이터를 추가하지 않는다.

현재 소스 동기화·포트레잇·서버·이름 정책은 유지한다.
이벤트 묶음·최대 힌트·구매 순서는 기존 공개 DB의 자동 연결 범위를 확인하고,
누락 관계만 출처가 있는 보완 데이터로 관리한다. 일일 동기화는 검증된 연결을 보존한다.

## 9. 1차 구현 상태

구현 브랜치: `feat/skill-budget-optimizer` / 2026-10-08.

- `PurchaseModel`: 단계별 할인·선행 비용·진화 원본 비용·이벤트 경로·예산 검증.
- `SkillOptimizer`: 입력 SP 안의 속도·가속·회복 조합, 사용자 고정·추천 제외, 수동 계산.
- `recommendDecks`: 보유 SSR·렌탈 최대 1장·타입 제한·고정 카드, 최대 6개 편성의 간이 조합 비교.
- UI: SP 잔량, 고정/제외, 이벤트 선택, 습득 경로·인자 준비, 최종 목록과 텍스트 저장.
- 기존 `PreparationEngine`은 이전 검증을 보존하기 위한 비교 엔진이다. Worker는 새 최적화 엔진을 사용한다.

미완료·제한:

1. 이벤트 묶음은 확인한 6장부터 적용한다. 전체 카드의 동시 금색 보상과 힌트 최대값을 검증하지 않았다.
   미검증 카드의 금색은 단일 보상 경로·Lv0으로 제한하여 묶음 동시 습득을 임의 허용하지 않는다.
2. 기본 구매 정렬 키는 미확보다. 최종 목록은 스킬명 순으로 표시하고 정렬 미검증 상태를 명시한다.
3. 큰 스킬 집합과 편성은 후보 축소·근사 탐색이다. 최대/안전의 전역 최적성을 주장하지 않는다.
4. 보유 목록은 브라우저 저장소에만 저장하며 서버·계정 간 동기화는 제공하지 않는다.
5. 기존 단독 주행 수식과 발동 성공 가정의 지원 제한을 유지한다. 스탯·SP 획득량이나 실제 육성 성공률을 예측하지 않는다.
6. 선택·고정한 항목은 표시 마신이 사라져도 실제 구매·예산·최종 목록에서 보존한다.

이벤트 보완은 `curated/planning.json`에 출처·확인 날짜를 기록하고 일일 정규화에 연결한다.
흰색 Lv5·그 외 금색/계승 Lv0은 표준 계획의 가정이며 실제 힌트 수준에 따른 인게임 비용 일치를 보증하지 않는다.
