# v8 알고리즘의 수동 예외·비중·새 CM 코스 독립 감사

검증일: **2026-11-18 Asia/Seoul**. 감사 대상은 `a21a0cc52624de95682b2f7be3755104949366ad`의 v8이다.
활성 데이터 `0b105741168200654ef4ef6523e1cb0bc0b7d9852107f3d478ea0fdcd6b7ad26`와 실행 자산을 고정했다.
시작/종료 시 정규화된 자산 해시 `a31b903c52d3a850e9ebcb7e6796d491e2fab10916a9668653c4112fe65f44de`를 확인했다.
**이번 감사에서 운영 엔진·스킬 데이터·코스 좌표·가중치를 수정하지 않았다.**

## 결론

**현재 시스템 전체를 ‘예외 없는 일반 알고리즘’ 또는 ‘실전 기대값 검증 완료’로 평가할 수 없다.**
스킬ID를 지정한 계승 추천 필터가 실제로 남아 있고, 새 코스의 공략과 모순되는 후보 제외를
재현했다. 경계 판정과 무작위 코너 추첨에도 일반 계산 결함 또는 기준 구현과의 불일치가 있다.
앞선 설명에서 공통 계산 개선을 전체 추천 파이프라인의 일반성으로 확대해 표현한 점을 바로잡는다.

v8 변경에서 왕수·군림만 별도로 깎는 계수나 도쿄·롱샹 외 금지 분기는 발견하지 못했다.
부진 구간25%는 수동으로 정한 위험 선호이며 실측 확률이 아니다. 이 설정이 특정 결과에
맞춰 조정됐다는 증거는 이번 새 코스 검사에서 나오지 않았다. **수동 정책의 존재와 고의적 결과 조작은
같은 판단이 아니다.** 코드에서 확인 가능한 정책·계산 편향을 아래에 구분한다.

## 감사 방법과 근거

- 기존 감사의5코스(교토2200, 도쿄1800/2400, 롱샹2400, 중산2500)와 겹치지 않는
  **새6개 CM 조건**을 자료에서 먼저 정했다. 결과에 맞춰 실패 코스를 바꾸거나 제외하지 않았다.
- 5개 코스는 계산 가능했고 **139개 코스×각질×스킬 검사**, 실제 1차 표의 계승 정책6건,
  위험 구간10/25/50/100%의 작은 후보군 전수 추천12건을 계산했다.
- 델마2000은 운영 엔진의 미국 코스 검증 제한으로 차단됐다. 이를0마신 또는 검증 성공으로 세지 않는다.
- 외부 조건의 결합 관계15건, 무관한 조건 경계 레코드 추가1건, 기준 추첨 방식 비교3건,
  경계 좌표 진단10건, 블로킹 조건0/1 비교6건, 별도seed·144/576표본 수렴8건,
  명시적인 순위 전개에서의 전수 재추천4건을 별도로 수행했다.
- 공략/공지/시뮬레이터 원문 **23개 근거 항목**을 [출처 기록](validation/cm-v8-holdout-sources-20261118.json)에 정리했다.
  같은 저자의 여러 글을 독립 저자 수로 세지 않는다. 공략 추천은 실측 발동률의 정답표가 아니다.
- 기존2024~2026년 공략의 코스·조건·발동 논리를 대조한다. 스킬 버전·환경이 달라졌을 수 있어
  당시 모든 캐릭터의 메타 순위·훈련 결과를 복원했다고 하지 않는다. 주 검사 스탯은
  `2100/2000/1700/1400/1500`, 거리S/마장A/각질A의 통제 입력이다.
  니가타 구매 검사만 출처의 목표 `1850/700/1700/1400/1200`을 썼다.
- 139개 단독 효과 검사는 무스킬 기준이다. 별도의 실제 1차 표6건은 파인 모션의 본체 고유기와
  시나리오12의 기본 상한을 기준으로 한다. 최종 구매 검사도 본체 고유기를 적용하며,
  통제된 인자/계승 후보 기록을 사용한다. 실제 최적 편성이나 한 번의 육성 재현은 아니다.

## 1. 실제로 남아 있는 ID별 예외 — 우선 수정

[cm-recommendation.mjs의 curated](../assets/cm-recommendation.mjs)는 아래 허용 각질을 직접 지정한다.
숫자1/2/3/4는 도주/선행/차시/추입이다.

| ID | 대상 | 허용 각질 |
| --- | --- | --- |
| 900271 | 아나볼릭 계승 | 3,4 |
| 900201 | 앵글링 계승 | 1 |
| 900511 | 꽃봉오리 계승 | 2 |
| 900591 | 저편 계승 | 3,4 |
| 900171 | 황제 계승 | 2,3,4 |

이 규칙은 v8 이전 기준 커밋에도 존재한다. v8 diff는 정렬 목적 함수를 바꿨고 이 목록을 제거하지 않았다.
초/중반과 종반의 각질별 허용 순위 범위도 수동으로 정해져 있다. 물리적인 발동 가능 조건과 다르다.

특히 꽃봉오리는 [니가타 차시 육성 공략](https://umamusumelabo.com/ikusei/chanmi-sasiikusei-202510)에서
우선 권장하고, [다른 작성자의 공략](https://note.com/umamusume_sui/n/n15e65900ca94)도 후방 채택을 설명한다.
[한신1600 공략](https://merci-splatoon.com/2503mile-1/)도 차시·추입의 유효 후보로 적는다.

실제 1차 표의 본체 고유기 기준 검사 결과:

| 코스 | 차시 마신 | 추입 마신 | 현재 추천 정책 |
| --- | --- | --- | --- |
| 니가타1200 | 0.26086 | 0.27218 | 둘 다 `eligible:false` |
| 한신1600 | 0.27472 | 0.28190 | 둘 다 `eligible:false` |

다른 계승 후보를 모두 없애고 이 스킬만 주어도 기본 추천에 들지 않는다. Top10 숫자 제한이나
마신 정렬 때문에 밀린 것이 아니다. 같은 조건·효과를 유지하고 ID만 바꿔 정책을 계산하면
후방도 허용된다. 이는 **스킬 이름에 의존한 후보 제외**를 직접 재현한 것이다.

전체 계승 후보에서 실제 확보를 기록하면 최종 최적화에는 들어갈 수 있다. 따라서 기본 추천의
누락을 최종 엔진의 절대 구매 금지로 확대해서 말하지 않는다. 사용자에게 보이는 기본 후보와
실제 최적화 후보가 어긋나는 문제다. 새로 각질 예외를 늘려 해결할 것이 아니라, 발동 조건과
명시 전개에서의 기여를 공통 평가하고 미관측 순위의 불확실성을 표시하는 방향이 필요하다.

## 2. 코너 추첨이 인용한 기준 구현과 다름

[현재 추첨](../assets/cm-chart.mjs)은 선택한 코너를 배열에서 삭제해 **중복 없는 두 코너**를 뽑는다.
근거로 삼은 [umasim SkillChecker](https://github.com/mee1080/umasim/blob/e9bb2939ba117ea93e556790c353ed3edec27eab/race/src/commonMain/kotlin/io/github/mee1080/umasim/race/calc2/SkillChecker.kt)의
`initAllCornerRandom`은 두 번 뽑으면서 선택된 코너를 삭제하지 않는다. 이전 고정 버전에서도 같다.

두 코너 코스에서 현재 구현은 앞 코너를 반드시 포함한다. 앞에서 발동하면 쿨다운 때문에
늦은 유효 위치에 다시 발동하지 못할 수 있다. 이는 특정 스킬에 붙인 감점은 아니지만
무작위 코너 가속 전체의 기대 효과를 바꾼다. 기존 테스트도 ‘서로 다른 코너’를 정답으로
강제해 이런 차이를 잡지 못했다([회귀 검사](../tests/cm-self-effects.test.mjs)).

576표본에서 **추첨의 중복 허용만 진단용으로 바꾼 비교**:

| 곡선의 소믈리에 | 현재 | 인용 기준과 같은 중복 허용 |
| --- | --- | --- |
| 니가타1200 차시 | 0.00000 | 0.22724 |
| 한신1600 차시 | 0.00000 | 0.18774 |
| 중경 더트1800 차시 | 0.34950 | 0.52523 |

대안 결과는 운영 코드에 적용하지 않았다. 공개 시뮬레이터와 다르다는 것을 재현한 것이며,
이 숫자가 게임 실측 정답이라는 뜻은 아니다. [니가타 Merci 공략](https://merci-splatoon.com/2510sprint-1/)은
소믈리에를 비추천하고 Labo는 상한을 노리는 선택지로 보므로, 공략 선호 자체를 이진 정답으로
강제하지 않았다. 현재의 ‘항상0’과 기준 추첨의 차이는 별도로 수정·검증할 가치가 있다.

## 3. 코스 경계에서 저편을 완전히 제거하는 문제

저편은 종반의 최종 코너 이전 코너 또는 중반의 최종 코너 조건을 가진다.
중경1800의 종반/최종 코너는 모두1200m, 한신2400은 모두1600m다. 현재 공간 구간 교집합은
이 경계에서 유효 구간을 없애고 `compiledStatus:inactive`로 만든다. 표본·적분 간격을
늘려도 컴파일 단계에서 사라진 조건은 복원되지 않는다.

[중경 후방 공략](https://merci-splatoon.com/2408-dir-2/)과
[독립된 중경 분석](https://note.com/herohero_3/n/n53da2125bb1c),
[한신2400 공략](https://merci-splatoon.com/2501-cla-1/)은 저편을 유효 후보로 제시한다.
코스ID를 잘못 골랐을 가능성은 [기준 코스 원문](https://github.com/mee1080/umasim/blob/e5d940ce8f73bbb756ae3cffd0a081c34b8124da/race/src/commonMain/kotlin/io/github/mee1080/umasim/race/data/rawData.kt)과
좌표를 대조해 제외했다. 기준 시뮬레이터의 [RaceState](https://github.com/mee1080/umasim/blob/e5d940ce8f73bbb756ae3cffd0a081c34b8124da/race/src/commonMain/kotlin/io/github/mee1080/umasim/race/calc2/RaceState.kt)는
phase에 프레임 시작 위치, 코너에 갱신 위치를 사용한다.
[프레임 진행 코드](https://github.com/mee1080/umasim/blob/e5d940ce8f73bbb756ae3cffd0a081c34b8124da/race/src/commonMain/kotlin/io/github/mee1080/umasim/race/calc2/RaceCalculator.kt)의
이동 후 발동 검사 순서도 확인했다. 현재의 단일 좌표 교집합과 다르다.

고정5위·걸림0이라는 **가상 조건**에서 최종 코너 경계만±5m 이동한 진단은 중경0→2.63/2.73,
한신0→2.91/2.97마신이다. 경계 이동은 해결책으로 적용하지 않았다. 원본 좌표를 스킬에
맞춰 옮겨서는 안 된다. **공통 프레임/상태 전이·경계 이벤트 의미를 검증한 뒤 공간 예약을 구현**해야 한다.

참고로 [2024년 공식 중경 경계 버그 공지](https://umamusume.jp/news/detail?id=2058)도 당시 경계 발동을
일부 횟수에 세지 않는 문제를 다룬다. 역사적 공지이며 해당 게임 버그가 현재도 남아 있다는
주장이나 이번 저편 판정의 직접 정답으로 사용하지 않는다.

## 4. 미관측 전개를 만드는 방식이 평균 추천을 좌우함

[race-scenarios.mjs](../assets/race-scenarios.mjs)의 기본9전개는 각질·레이스·편성과 무관하게 순위를
회전시킨다. 숫자 외부 조건은 전체 스킬 데이터의 경계값 목록에서 고르고, 필드명 문자 코드의
합으로 서로의 배치를 정한다. 실제 발동 빈도나 조건 간 물리적 관계를 학습한 결과가 아니다.

- 기본 니가타 차시의 논스톱 걸은 약3.456마신·발동 표본84.0%, 교토3200 차시는 약6.574마신이다.
  이는 실제 블로킹 빈도를 측정해서 나온 수치가 아니다. 앞 가까운 레인 유지 값을0/1로 고정한
  진단에서 니가타0↔3.856, 중경0↔5.044, 교토0↔7.335마신으로 변한다.
- 선택하지 않는 **가상의 조건 경계 레코드 하나**를 추가하면, 다른 주행 조건을 유지해도
  괴물의 기본 평가가3.28672→2.59474마신, 발동 표본52.78%→41.67%로 바뀐다.
  실제 신규 스킬을 발견했다는 뜻이 아니라, 전체 데이터의 경계 목록이 확률처럼 사용될 때의
  불안정성을 보여 주는 반례다. 순수 수식·소유 관계의 변화가 아니다.

## 완성도 평가와 수정 순서

| 영역 | 현재 판단 |
| --- | --- |
| 고정 조건·주력 중복·원본/진화 차이 | 유용한 공통 계산이 동작함. 교토3200·한신2400의 상반된 가속 조건을 구분 |
| 후보 선정의 일반성 | 미완성. 수동ID 목록이 실제 유효 계승을 제외 |
| 공간/시간 조건·무작위 모델 | 우선 수정 필요. 경계 비활성화와 기준 추첨 불일치 재현 |
| 실전 확률·기대 마신 | 검증되지 않음. 기본 전개를 실제 분포로 사용할 근거 부족 |
| 최종 최적화 | 주어진 후보·전개 안에서 비교하는 도구로는 유용. 입력 분포와 후보의 오류를 최적화가 교정하지 못함 |
| 전체 CM 적용 범위 | 일부 미지원. 델마2000을 포함해 미국 코스는 좌표 보정 검증 필요 |

1. **P0 — 조건의 프레임/경계 의미부터 확정.** 원본 상태 전이와 실제 발동 프레임을 대조해
   경계 이벤트를 공통 처리한다. 저편ID 예외나 코너 좌표 미세 이동으로 해결하지 않는다.
2. **P0 — ID별 추천 제외와 수동 순위 범위를 분리·대체.** 실제 조건의 가능성과 추천용
   전개를 같은 평가에 넣는다. 부적합 후보와 미관측 후보를 구분하고 유효 후보를 숨기지 않는다.
3. **P1 — 코너 추첨의 기준을 통일하고 분포 검사.** 서로 다른 코너를 강제하는 기존 회귀를
   근거로 정답 취급하지 말고, 공개 기준/실측에 맞는 추첨·쿨다운을 검증한다.
4. **P1 — 스트레스 값과 확률 분포를 분리.** 실제 로그가 없을 때는 조건부 값·전개 민감도를
   제공한다. 미관측 상대 조건을 거의 확실히 충족시키는 기본 평균으로 추천 확신을 만들지 않는다.
5. **P1 — 지원 코스의 좌표/출발 보정 검증.** 미국 코스 차단만 제거해 수치를 만드는 방식은 피한다.
6. **P2 — 위험 선호와 근사 계수의 정책 검증.** 여러 독립 경기로 미리 정한 평가를 수행한다.
   관측 빈도·모형 오차·사용자 위험 선호를 하나의 가중치로 섞지 않는다.

왕수·군림 문제를 계기로 공통 계산은 개선됐지만, **새 레이스에서도 안정적으로 합당한 추천을
보장할 단계에는 이르지 못했다.** 특히 후보 필터·경계·외부 전개 모델의 수정이 우선이다.
기존 자동검사261개 통과는 구현 내부의 회귀 결과다. 이번에 확인한 독립 자료와의 모순까지
검증됐다는 의미로 확대할 수 없다.
