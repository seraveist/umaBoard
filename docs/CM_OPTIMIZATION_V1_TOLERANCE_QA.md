# 최적화 알고리즘 v1 — 0.01마신 허용오차 개정3

작성일: **2026-11-18 Asia/Seoul** · 브랜치 `feat/cm-first-chart`

사용자가 지정한 **0.01마신**을 평균 기여의 허용 범위로 사용한다. HP 충족, HP 부족량,
부진 구간 보호 조건에는 이 허용오차를 적용하지 않는다. 최종 선택과 출력은 기존의
144표본·0.01초 조합 전체 평가 결과다. 스킬별 마신값을 반올림하거나 작은 기여의 스킬을 삭제하지 않는다.

## 변경 범위와 기준

공개 명칭은 `최적화 알고리즘 v1`, `revision:3`이다. 최종 추천 식별자는
`cm-post-training-v13`으로 갱신하고 마신표 `cm-first-chart-v11`, 단독 비교
`solo-comparison-v5`는 유지한다. 직전 비교 대상은 `dbbe246`의
[탐색 개정2](CM_OPTIMIZATION_V1_SEARCH_IMPROVEMENTS.md)다.

수정한 계산은 [추천 탐색](../assets/cm-final-plan.mjs)과 새
[조합 압축](../assets/cm-plan-compression.mjs)이다. 공통 물리·발동·획득·가격·목표 함수의
기존29모듈, 데이터 입력4개, 과거 감사 자료를 보존한다. 스킬명·코스ID별 분기나 점수 계수를 추가하지 않는다.
`RecordedPurchaseModel`의 구매 가격과 할인 산식도 유지한다.
새 [고정 기준](validation/cm-optimization-v1-tolerance-release-20261118.json)은
직전 릴리스·감사 증거의 해시를 연결하며 과거 고정 파일을 덮어쓰지 않는다.
현재32모듈의 SHA256은 `b00adbd3dd3f964aaaf55bdecc6bd9758a35d6e02cd67928999e4315ada987ee`이며,
활성 데이터는 `0b105741168200654ef4ef6523e1cb0bc0b7d9852107f3d478ea0fdcd6b7ad26`이다.

## 조합 압축과 정밀 평가 축소

### 누적되지 않는 허용 범위

완전히 평가한 모든 조합을 기존 목표 함수로 정렬해 최선의 기준 조합을 고정한다.
그 조합과 HP·위험도 우선순위가 같고 평균 기여가 기준보다 최대0.01마신 낮은 조합 중
SP가 가장 적은 조합을 선택한다. 같은 비용이면 기존 비교 순서를 따른다.
0.009씩 여러 번 양보해0.01을 초과하는 누적 손실이나, 비교 순서에 따라 결과가 달라지는
쌍별 허용오차 정렬을 사용하지 않는다.

`search.approximation`에 허용오차, 완전 평가한 최선의 평균 기여, 선택 조합과의 차이,
실제 완전 평가한 조합 수를 기록한다. **평가하지 않은 모든 조합까지 포함하는 전역 오차 보증은 아니다.**
이 의미를 출력의 `scope`에도 남기고 압축 모드의 `globalOptimal`·`closureComplete`를 `false`로 표시한다.

### 연계 구조를 보존하는 대표 조합

회복·패시브·가속·진화·계승과 발동 횟수에 의존하는 스킬의 실제 ID를 구조에 남긴다.
명시적인 보유/사용 스킬 참조는 상·하위 보유 관계를 포함하고, 원본 조건에 등장한
회복·발동·구간별·계승 개수의 잠재 기여자도 구분한다. 해석하지 못하는 개수 조건은 기여자ID를 보존한다.

동일 구조·동일 HP/위험 우선순위 안에서 전체 평균과 전개별 평균이 모두0.01마신 이내이고,
전개별 HP 충족률도 같은 완성 조합만 같은 구간으로 묶는다. 구간의 최고 기여와 최소 비용 대표를 남긴다.
구간마다 첫 기준을 유지하므로 근접 관계를 이어 붙여 점점 넓은 범위를 합치지 않는다.
이는 선별을 위한 보수적인 구조 분류이며, 미래의 모든 추가 구매에 대한 수학적 동등성 증명은 아니다.

다음 단계에는 전체 상위권, 구조별 최선, 기본 습득 조합, 두 완성 조합 구성의 끝점을 보존한다.
원본 후보와 복합 제안 생성기는 그대로 남겨 두며 대표에서 빠진 스킬 자체를 영구 제거하지 않는다.
처음 정밀 이웃 검사에서는 모든 직접 변경을 확인하고, 단독 개선을 묶은 제안도 전체 조합으로 다시 평가한다.
따라서0.01보다 작은 개별 변경이 여러 개 모여 유리해지는 경우를 개별 마신 기준으로 버리지 않는다.

### 단계별 평가

기본144표본에서는 모든 전개를 포함하는36표본을 예비 평가에 사용한다. 작은 구매 공간은
36→72→144표본으로 대표를 선별한다. 큰 제한 탐색은 기존 거친 탐색과 **모든 후보의144표본 단독 비교**를
유지하고, 비싼 완성 조합의 누적 구성만36표본에서 수행한 뒤 대표를144표본으로 직접 평가한다.
중복된72표본 선별 단계는 큰 문제에서 실행하지 않는다. 예비·중간 단계도0.01초 간격을 유지한다.
표본 수는 전개 수의 정수배로 올려, 일부 전개를 생략하지 않는다.

HP나 연계 구조가 바뀌는 개선은 계속 조사한다. 같은 구조·같은 HP/위험 우선순위에서
SP를 더 아끼지도 않는0.01미만의 후속 개선은 묶음 제안을 확인한 뒤 추가 반복을 종료할 수 있다.
완전 평가만 캐시에 저장하고 HP 실패로 중단한 부분 평가는 최종 기준으로 재사용하지 않는다.
최종 기여·HP·발동률·전개별 결과와 기여도 진단은 모두 선택된 전체 조합에서 계산한다.

첫 시제품은 단독 후보의 순위까지 예비 표본으로 정했으나 큰 입력에서0.01 목표를 충족하지 못해 채택하지 않았다.
현재 구현은 단독 순위를 최종 정밀도로 유지한다. 점수·확률 계수나 비교 기준을 바꿔 실패를 통과시키지 않았다.
`gainTolerance:0`은 압축과 새 선택 정책을 끈 정밀 비교 경로로 유지한다.

## 재검증 범위

직전 개정2와 같은 입력·능력치·획득 기록·SP·데이터·표본·시간 간격으로 비교한다.
마일·중거리·장거리 HP 부족·더트·습득 하위 변경의5템플릿×2예산,
강제 제한 탐색2템플릿×2예산과7000SP·220후보를 포함한다.
이전 조합도 현재 공통 평가기로 재계산해 과거 평균 기여를 재현한 뒤 비교한다.
작은 문제는 과거의 별도 합법 상태 전수 기준도 함께 읽는다.
구매 비용은 운영 가격 클래스를 호출하지 않는 정수 단계 산식으로 따로 확인한다.

7000SP 입력은 검토한 이벤트의 첫 선택과 가상 힌트Lv5를 사용한 재현 가능한 입력이다.
실제 육성 기록이나 실전 발동률 측정이 아니다. 계산 시간은 마신표 생성·진단을 제외한
추천 탐색 한 번의 관찰값이며 전용 환경의 반복 평균이나 모든 기기의 성능 보증이 아니다.

## 표본 민감도와 회귀 검증

고정된 새 추천과 직전 추천을 마일 두 예산·습득 하위 변경 두 예산·7000SP에서 비교했다.

각 대안 설정으로 다시 최적화한 결과나 실전 확률 검증은 아니다.

마일470SP의 직전 대비 평균 차이는 기본−0.008726, 시간 간격 절반−0.009943,

20대조 모두 표본HP 충족률1이고 부진 구간 보호를 통과했다.
**2대조는0.01을 초과하므로 다른 표본까지 포함한0.01마신 보증으로 해석하면 안 된다.**
선택 허용 범위와 시뮬레이션의 표본 민감도는 별개다. 이 차이를 줄였다고 설명하거나0.01로 반올림하지 않는다.
향후 여러 표본에서도 오차를 제한하려면 근접 후보의 추가 표본 비교와 평가 불확실성을 다루는 별도 정책이 필요하다.
현재 요청의 동일 조건 비교와 최종144표본 계약은 유지한다.
[민감도 원자료](validation/cm-optimization-v1-tolerance-sensitivity-20261118.json).

검증 결과는 고유 **Node311개·Python51개**다. 최초 전체 실행은310통과·1실패였고,
실패한 검사는 효과가 같은 상위 스킬을 반드시80SP에 구매한다고 가정한 기존 계약이었다.
가격 검사는 `gainTolerance:0`에서 그대로 유지하고 기본 모드의0SP 습득 하위 유지도 추가로 검사했다.
수정한 현재 일반 회귀309개는 모두 통과했다. 최초 전체 실행에서 같은 운영 소스의 통합2개도 통과했으며,
이를 합한311개를 고유 검사 수로 센다. 중복 실행을 추가 검사 수로 세거나 최초 전체 실행을 전부 통과했다고 기록하지 않는다.

전체 흐름의 마신표 생성·진단 포함7000SP 결과는 별도 시간 계측과 ID·기여·비용이 같다.
데이터 검증은 기존 경고5개와 함께 통과했고, 빌드32모듈이 고정한 계산 내용과 일치했다.
새6검사는 고정 최선 기준, 비추이적 허용오차 방지, HP/부진 보호, 전개별 차이, 보유/개수 연계, 구성 끝점 보존을 확인한다.
