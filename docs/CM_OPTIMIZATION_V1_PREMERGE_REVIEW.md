# 최적화 알고리즘 v1 — 병합 전 검수

검수일: **2026-11-18 Asia/Seoul**

**판정: 현재 상태의 병합은 보류한다.** 고정 v1 자체의 가격·유한 후보 최적화 검사에서는 새 오류를 발견하지 않았다.
그러나 최신 `main`과13개 파일이 충돌하고, 충돌을 v1 쪽으로 일괄 선택하는 방식에서도 Worker 연결 오류가 재현됐다.
목표 가속/전략 유지 API, 데이터 기준, 저장 기록 복원도 함께 통합해야 한다.
현재 브랜치 단독 통과를 최신 `main`과 합쳐진 결과의 통과로 대신할 수 없다.

기존 PR#3은 이미 병합된 과거 PR이다. 이번 판정은 현재 작업 커밋과 위 main 커밋의 조합에 관한 것이다.
수식·가중치·후보·데이터·프론트엔드 운영 코드는 변경하지 않았다.

## 2. 우선순위별 병합 차단 사항

### P1 — 충돌을 일괄 해결하면 Worker 모듈이 연결되지 않음

충돌13개는 `cm-app`, `cm-chart`, `cm-final-plan`, `cm-final-ui`, `cm-state`, `cm.css`,
`index.html`, 계약 문서4개와 테스트2개다. 실제 목록은 원시 결과에 보존했다.

별도로 **모든 충돌에서 현재 v1 파일을 선택하고 나머지는 자동 병합 결과를 사용하는 가상 조합**을 만들었다.
파일을 작업 트리에 덮어쓰지 않고 메모리의 ES 모듈 연결 단계만 검사했다.
현재 브랜치 Worker는 연결됐지만, 가상 조합은 다음 오류로 실패했다.

```text
The requested module './cm-state.mjs' does not provide an export named 'retainedInheritanceCandidates'
```

[main Worker](https://github.com/seraveist/umaBoard/blob/4f9e6f3c665e619fa8c5c7a4a0a4752d004803d4/assets/cm-worker.mjs#L3)는
새 함수를 가져오지만 v1의 상태 모듈에는 해당 내보내기가 없다. 따라서 충돌 표시만 없애는 방식으로는 안전하지 않다.
반대로 main 파일을 모두 선택하면 고정한 v1 계산의 유지 검사를 만족한다는 근거가 없다.
통합 후 실제 Worker 의존 관계와 실행 경로를 다시 검사해야 한다.

### P1 — main의 목표 가속·전략 유지 입력을 v1 추천기가 반영하지 않음

main에는 `maintainTargetAcceleration`과 `maintainStrategicSkills`가 있다.
[main의 최종 추천](https://github.com/seraveist/umaBoard/blob/4f9e6f3c665e619fa8c5c7a4a0a4752d004803d4/assets/cm-final-plan.mjs#L99)은
이를 목표 가속/전략 필수 효과, 예산, 유지 제약에 반영한다.

같은 정상 입력에 두 값을 모두 켠 경우와 끈 경우를 현재 v1의 `createFinalSetup`에 전달했다.
두 정규화 결과는 같았고 해당 필드는 결과에 남지 않았다.
현재 v1 화면에는 이 main 전용 기능이 없으므로 v1 단독 오류로 분류하지 않는다.
다만 main 화면·준비 결과와 v1 추천기를 그대로 섞으면 사용자가 요청한 유지 조건을 무시할 수 있다.

목표 가속과 PDM 같은 전략 정책을 유지할지, 어떻게 명시적 제약으로 전달할지 통합 계약을 먼저 정해야 한다.
조건부 스킬에 임의 마신 보너스나 감점을 붙이는 방식으로 차이를 맞추지 않는다.
main의 별도 위치 비교/가속 추천 경로도 같은 계산·샘플링 기준으로 검증해야 한다.

### P1 — 자동 병합되는 데이터가 v1의 고정 검증 범위와 다름

모의 병합에서 `data/manifest.json`은 충돌 없이 main의 `59fd…` 데이터로 바뀐다.
v1의 계산 기준과 검사 자료는 `0b105…`를 고정하므로, 계산 파일만 v1로 유지해도 동일 완성본 검사를 통과할 수 없다.

차이는 버전 문자열뿐이 아니다. 스킬 레코드7종, 구매 단계5항목, 획득 경로 수10474→10486과
서포트 이벤트 레코드 수8→74 등의 차이를 확인했다. 스킬/구매 단계 차이에는 데어링 택트 관련 항목이 포함된다.
최신 main의 데이터가 틀렸다고 판정한 것은 아니다. 별도 검증 없이 이전 데이터의 증거를 새 데이터에 적용할 수 없다는 뜻이다.

어느 데이터를 통합 기준으로 삼을지 정한 뒤 조건·효과·가격·획득·진화를 대조해야 한다.
검사를 통과시키기 위해 과거 해시나 증거를 덮어쓰지 않는다.

### P2 — 데이터 전환 시 같은 입력의 기존 기록이 자동 복원되지 않음

양쪽 `checklist_data_sha256`가 다르고, 현재 인식하는 호환 버전 선언으로 연결되지 않는다.
같은 입력·힌트/습득·실제 능력치 기록으로 양방향 복원을 시험했으며 둘 다 새 계획에서 복원되지 않았다.
이 검사는 메모리의 시험 기록에 대한 것으로 실제 저장 기록을 삭제한 것은 아니다.
기존 기록이 이전 키에 남아 있어도 새 화면에서 읽지 못하는 상황을 구분해야 한다.

호환성을 증명한 범위의 기록 이관과 키 정규화를 함께 검증해야 한다.
가격·효과·이벤트 제약이 달라진 데이터를 단순 호환 목록에 넣는 것으로 해결하지 않는다.

## 4. 병합을 다시 판단할 조건

1. 최신 main과의 충돌을 실제 기능 단위로 통합하고 두 Worker가 정상 연결/실행됨.
2. 목표 가속·전략 유지의 켜기/끄기, 예산 부족, 습득/진화 대체를 통합 추천기로 검사함.
3. 사용할 데이터의 조건·가격·획득 차이와 기존 기록 이관을 검증하고 새 검증 기준을 명시함.
4. 합쳐진 트리에서 전체 회귀·작은 후보 열거·7000SP·기존 레이스 조건·실제 화면 검사를 통과함.
5. 해당 통합 커밋의 원격 CI가 성공함. 검수한 작업 커밋 `3986ce8`의 원격 CI는 최종 확인에서 성공했다.
   이는 현재 main과 통합한 코드의 검사 결과를 뜻하지 않는다.
