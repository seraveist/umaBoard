### 추천 목표

기존 스킬 조합의 각 표본 완주 시간과 후보 조합의 완주 시간을 각각 계산한다. 가중 분포에서
가장 느린25%의 평균 완주 시간을 부진 구간으로 삼으며, 경계 표본은 필요한 비중만 포함한다.
후보의 부진 구간 시간이 기준보다 길어지지 않는 조합을 우선하고 그 안에서 평균 마신을 비교한다.
따라서 유리한 전개에서 추가 효과가0인 가속도 불리한 주행을 개선하면 추천될 수 있다.
반대로 평균이 커도 기준의 부진 구간을 악화시키는 조합은 뒤로 보낸다. HP 충족 기준은 먼저 적용한다.

상위 꼬리 평균의 방법은 [Rockafellar·Uryasev의 CVaR 연구](https://sites.math.washington.edu/~rtr/papers/rtr179-CVaR1.pdf)를
참고했다. 여기서 `tailMass=.25`, 허용 지연 `maxTailDelay=0초`는 **명시적인 위험 선호 정책**이며
게임의 관측 확률이나 왕수·군림에 맞춘 계수가 아니다. API에서 변경 가능하다. 본 검증의 세 선택에
10/25/50% 구간을 적용했을 때 모두 기준보다 개선됐다. 이는 같은 선택의 민감도 검사이며 각 설정으로
다시 최적화했다는 뜻은 아니다. 기본9전개의 실제 빈도는 여전히 없다.

전개별 최소 추가 기여와 범위는 진단값으로 남긴다. 표본 분산·반별 평균 차이를 신뢰구간으로
부르지 않는다. 유한한 양의 가중치들의 합이 넘치는 경우도 공통 배율을 정규화하여 같은 결과를 유지한다.

### 획득 경로와 기여의 기준

각 레어는 활성 서포트/시나리오 이벤트의 가능한 선택들 중 하나로 얻으면 된다. 여러 카드나
본체 각성·별도 힌트 경로가 있으면 그 대안을 유지한다. 공통 보상과 같은 선택의 분기 보상은
함께 가능하다. 진화는 원본 레어의 경로를 요구한다. 단순한 두 스킬 금지표가 아니므로
모든 쌍은 가능하지만 세 개 전체는 불가능한 경우도 잡는다. 임의 ID의 합성 사례로 확인했다.

기록 전체가 불가능하면 시뮬레이션 전에 최소 충돌 묶음을 안내한다. 힌트도 실제 확보 기록이므로
구매되지 않았다는 이유로 충돌을 무시하지 않는다. 자동으로 어느 기록을 버리지는 않는다.
자료가 없는 대체 이벤트 경로는 불가능하다고 단정하지 않고 `coverage:partial` 및 누락ID로 남긴다.
이 검사는 검토한 획득 경로의 일관성이며 모든 육성 조건·보상 성공률·이벤트 도달을 보장하지 않는다.

상위 스킬 제거 시 실제 습득한 하위를 `restoredIds`로 복원한다. 최종 선택에서 하위 효과가
숨겨졌어도 소유 이력을 사용한다. 미습득 하위를 무료로 부여하지 않는다. 이로써 업그레이드의
추가 기여를 전체 계열의 기여와 구분한다. 개별 제거 기여 합계는 조합 마신과 같지 않을 수 있다.

### 7000SP 스트레스 입력의 정정

과거 v7의 동시 선택 금스킬 묶음은 새 경로 검사에서 거부된다. 최소 충돌 묶음 중 하나는
`204731/204751`이며, 외부 감사에서 발견한 FF/CB 선택 분기도 실제 데이터 회귀 검사에 포함했다.
[FF 선택 자료](https://gamewith.jp/uma-musume/article/show/573288),
[CB 선택 자료](https://gamewith.jp/uma-musume/article/show/573289)를 근거로 한 기존 이벤트 자료를 쓴다.

대체 스트레스 입력은 **각 검토된 이벤트의 첫 선택을 명시적으로 고정**하고 그와 충돌하는 레어
힌트를 제거했다. 남은 후보의Lv5는 여전히 가정이다. 사용6990/7000SP, 잔여10SP,
144표본36.79461마신, HP144/144, 제한 탐색의 최종 추가/삭제 검사 완료를 확인했다.
전역 최적성은 보장하지 않는다. 이벤트 정보가 없는 `203121/204331` 경로는 `partial`로 남는다.
왕수·군림이 없는 편성이므로 그 두 스킬의 검증 근거로 쓰지 않는다. 과거 불가능한 조합의
35.87460과 새 수치를 실전 성능 향상률로 비교하지 않는다.

최종 브랜치 CI는 Node 전체261항목과 Python51항목, 데이터·빌드·모듈 검사를 실행한다.
CI 링크와 실제 커밋은 전달 시점 결과를 참조한다. 대규모 공략 대조 JSON은 위 단위검사 수와 별도다.

브라우저의 실제 Worker로390×844 및 기본1280×720에서 다음을 확인했다.
일괄Lv5의 이벤트 충돌 → 기록 화면 복귀/2개 항목 표시/초점/하단 오류 → 기록 수정 →
3개 일반 스킬 추천 성공(216/300SP, 잔여84,1.37마신) → SP 변경 시 저장 차단 → 재추천 성공.
기록/실제 입력은 보존됐고 가로 넘침과 브라우저 콘솔 오류는 없었다. 임시 화면 크기 설정은 복원했다.
실제 모바일 기기·다른 브라우저 엔진·화면낭독기 검수까지 완료한 의미는 아니다.

## 남은 한계와 다음 근거

1. 기본9전개와 숫자 경계 스트레스 값에는 실측 빈도가 없다. 1차의 약0.96마신이나
   약75% 발동 표본을 실제 왕수/군림 기대값·발동률로 읽을 수 없다. 신뢰구간·승률을 제공하지 않는다.
2. `scenarioEvidence`는 사용자가 선언한 횟수를 검사한다. 원본 리플레이 진위·표집 편향은 검증하지 않는다.
   실제 각질/편성별 거리순 순위·추월·간격·발동 시점 로그가 있어야 경험적 보정과 별도 경기 검증이 가능하다.
3. 일반 화면의 1차 표는 본체 고유기 기준 단독 표다. 주력 조합 기준은 명시 API와 검증에서 지원한다.
   실제 획득 기록과 스탯을 반영한 판단은 최종 추천을 사용한다. 기록 수정으로 1차를 자동 재계산하지 않는다.
4. 기존 계승 적합성의 일부 제품 정책, 상대/레인 상호 작용의 근사,2000초과 전개 스퍼트 상한,
   종료 보너스 근사, 미검토 획득 경로는 남아 있다. 이번 공통 목표 수정으로 모두 해결됐다고 하지 않는다.

다음 우선 작업은 추가 감점 계수보다 **출처가 있는 실전 로그와 미검토 보상 경로 확보**다.
같은 로그를 보정/검증에 중복 사용하지 않고 별도 경기·코스에서 오차와 추천 안정성을 보고해야 한다.

재현: `node scripts/validate_cm_v8.mjs --matrix-only`, `--plans-only`를 실행하고
`node --test tests/cm-joint-evolution.test.mjs`의7000SP 결과 생성 후 `--collect`로 모은다.
결과 수집기는32개 선택을 현재 코드로 재검사하고 자산 해시를 남긴다. 대규모 재검증은 일반 단위검사와 별도다.
