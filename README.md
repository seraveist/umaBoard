# umaBoard

일본 서버의 **육성 목표와 사용자가 입력한 예상 스탯·획득 SP에 따른 스킬 최적화 시뮬레이터**입니다.

목표는 SP 예산 안에서 속도·가속·회복 스킬을 조합하고, 필요한 서포트 이벤트 선택과 계승·흰 인자 준비,
인게임 기본 순서의 최종 구매 목록을 제공하는 것입니다. 스탯·획득 SP는 사용자 입력이며
서포트 레벨·성능해방·훈련 효과로 육성 결과를 예측하지 않습니다.
직접 편성을 기본으로 하고 보유 SSR·렌탈 최대 1장·타입 제한에 따른 스킬 확보 편성 추천을 확장합니다.

**2026-10-08 구현 브랜치:** `feat/skill-budget-optimizer`.
[프로젝트 기획](docs/PROJECT_PLAN.md) · [엔진 계약](docs/MODEL_CONTRACT.md) · [검증 범위](docs/ENGINE_VALIDATION.md).

예상 총 SP 입력, 단계별 구매 가격, 예산 내 스킬 추천, 고정·추천 제외, 이벤트 선택,
최종 구매 목록의 텍스트 저장, 보유 SSR·렌탈·타입 제한·고정 카드에 따른 편성 비교를 구현했습니다.
계산은 Worker에서 버튼으로 실행하며 토글은 선택·비용·경로만 즉시 바꿉니다.

이벤트 묶음과 대성공 힌트는 출처를 확인한 6장의 카드부터 적용합니다.
미검증 카드의 금색 보상은 보수적으로 단일 보상 경로로 제한하고 Lv0으로 계산합니다.
금색 여러 개를 동시에 얻는 실제 경로가 빠질 수 있으므로 `미검증`으로 표시합니다.
인게임 기본 정렬 키는 아직 확보하지 못해 최종 목록은 **스킬명 순 · 기본 순서 검증 중**입니다.
실전 발동 확률·상대 행동을 재현하는 레이스 모델은 아닙니다.

## 실행

테스트 페이지: **[https://seraveist.github.io/umaBoard/](https://seraveist.github.io/umaBoard/)**

최초 공개에는 저장소의 [Settings → Pages](https://github.com/seraveist/umaBoard/settings/pages)에서
`Build and deployment → Source → GitHub Actions`를 선택해야 합니다.
이후 **Deploy GitHub Pages**가 성공하면 위 주소에서 사용할 수 있습니다.

Python 3.12 이상과 Node.js 24를 검증에 사용합니다. 외부 Python/JavaScript 패키지는 필요하지 않습니다.

```sh
python scripts/build_pages.py --fetch-portraits
python -m http.server 8000 --directory .cache/pages
```

- `http://localhost:8000/`: 실제 JP 데이터로 의상·개화·각질·코스·서포트·목표 능력치·적성·총 SP를 선택해 비교합니다.
- `http://localhost:8000/prototype/`: 합의한 결과 화면과 토글 동작을 확인하는 예시 모드입니다. 수치는 실제 게임 계산 결과가 아닙니다.

## 구현된 데이터 동기화

```sh
python scripts/sync_data.py
python scripts/sync_portraits.py
python scripts/validate_data.py
```

UmaTools와 umasim 두 저장소의 대상 파일을 매일 확인합니다. alpha 상세 코스는 첫 수집의 고정 버전을 유지합니다.

```sh
python scripts/sync_data.py --refresh-courses
```

위 명령 또는 Actions의 `refresh_courses` 입력으로 alpha 코스도 최신 자료를 검사할 수 있습니다.
GitHub API 한도에 도달했다면 로컬 환경에 `GITHUB_TOKEN`을 설정하거나 한도 초기화 후 실행합니다. 토큰을 저장소에 넣지 않습니다.

코스 `10613`은 원본의 마지막 코너가 결승선을 초과하여 선택에서 제외합니다. 원본 좌표는 보존합니다.
현재 공개 소스의 수록 수이며 게임 전체 커버리지를 보증하는 숫자는 아닙니다.

포트레잇은 **UmaTools만** 사용합니다. 활성 데이터의 의상·SSR ID와 이미지 경로를 기준으로
UmaTools 최신 commit의 파일을 확인하고 `data/portraits.json`에 이미지 경로와 Git blob을 기록합니다.
계산 데이터가 그대로인 상태에서 이미지만 추가·수정되어도 다음 동기화에 반영합니다.
WebP를 우선 사용하고 없으면 같은 소스의 PNG를 사용합니다.
현재 의상 266종·SSR 311장에 이미지가 있으며, 누락된 의상 4종·SSR 5장은 이미지 없이 이름으로 선택할 수 있습니다.
GameTora 등 다른 이미지 소스로 보완하지 않습니다.
Pages 빌드가 필요한 이미지만 받아 Git blob·크기·형식을 검사하고 자체 정적 경로로 배포합니다.
다운로드 파일은 Actions 캐시에 보관하므로 변경되지 않은 이미지를 매번 다시 받지 않습니다.
다운로드에 실패한 이미지도 배포 목록에서 제외하여 계산 화면에 깨진 이미지 주소를 만들지 않습니다.

## GitHub Actions

- **CI**: push/PR에서 정규화·실패 복구, 실제 후보와 계산 엔진 테스트, 활성 데이터 검증과 JS 구문 검사를 수행합니다.
- **Sync JP data**: `Asia/Seoul` **매일 00:00**, 수동 실행, 수집 코드·설정 변경 시 실행합니다.
- **Deploy GitHub Pages**: main 변경·수동 실행·데이터 동기화 성공 후, 최신 main을 검증하여 테스트 페이지에 배포합니다.
- 검증된 변경이 있을 때만 `github-actions[bot]`이 데이터 commit을 만듭니다. force push는 없습니다.
- 실패하면 이전 활성 묶음을 유지하고 실행을 실패 상태로 반환합니다. 실행 상태는 Actions summary와 artifact로 남깁니다.
- 예약 실행은 기본 브랜치에서 동작하며 GitHub 부하에 따라 지연될 수 있습니다. 공개 저장소의 장기 비활성으로 일정이 중지될 수도 있습니다.
- 상위 UmaTools 정기 수집은 한국/일본 시간 08:00입니다. 자정 실행 성공과 최신 게임 반영은 구분합니다.
- `GITHUB_TOKEN`으로 만든 데이터 push가 후속 CI/배포를 자동 실행한다고 가정하지 않습니다. 동기화 workflow에서도 후보·엔진 호환 테스트를 수행한 뒤 commit합니다.
- Pages는 `workflow_run`으로 동기화 성공을 받아 bot의 데이터 commit도 배포합니다. 동기화가 실패하면 해당 실행은 배포하지 않습니다.
- 배포 파일은 화면·JS/CSS·활성 데이터 묶음·출처/라이선스만 포함합니다. 이전 데이터 묶음, 수집 원본과 테스트 코드는 제외합니다.
- 화면·모듈·Worker·CSS는 같은 내용 기반 버전으로 배포해 이전 브라우저 캐시와 새로운 계산 결과 형식이 섞이지 않도록 합니다.
- 최초 Pages 활성화 전에 배포가 실패했다면, 설정 후 Actions에서 **Deploy GitHub Pages → Run workflow** 또는 실패 실행의 **Re-run failed jobs**를 선택합니다.

## 현재 구현의 데이터 적용 정책

이벤트 완주·성공은 가정하고, 선택지별 보상 배타와 SP 구매 비용은 별도로 적용합니다.

원본의 저장소 commit과 파일 blob을 고정한 뒤 캐시 또는 다운로드 바이트가 그 blob과 일치하는지 확인합니다.
전체 참조·개수·좌표·스키마 검증을 통과한 묶음을 불변 경로에 기록하고, `data/manifest.json`을 원자적으로 교체합니다.
매일의 확인 시각은 `.cache/sync-status.json`과 Actions에 남기며 마스터 데이터에 불필요한 일일 변경을 만들지 않습니다.

- 각성은 현재 공개된 MAX. 서포트의 레벨·성능 해방은 입력하지 않습니다. 이벤트 완주·대성공을 가정하고 보상 선택은 자동 탐색 또는 사용자 고정으로 결정합니다.
- 캐릭터명은 `curated/names-ko.json`의 한글 이름을 적용합니다. 의상명·그룹/카드 명칭·스킬명은 일본어를 유지합니다. 한글 이름은 정기 동기화에서도 보존하며, 새 이름의 매핑 누락은 검증 경고와 일본어 fallback으로 남깁니다.
- 육성 우마무스메와 SSR 서포트 선택창은 한글 이름·띄어쓰기 없는 이름·일본어 이름으로 검색할 수 있습니다. 검색 입력만으로 편성은 바뀌지 않으며 목록에서 선택해야 적용됩니다. 같은 이름/타입의 카드도 내부 ID로 구분합니다.
- SSR 서포트는 **포트레잇 · 타입 아이콘 · 캐릭터명**만 표시합니다. 타입 텍스트·카드 번호·카드 제목은 표시하지 않습니다. 타입 이름과 ID로 검색은 가능합니다.
- 7종 타입 아이콘은 GameTora의 공통 게임 아이콘을 한 번 가져와 정적 파일로 포함합니다. 출처와 해시는 `curated/support-type-icons.json`에 기록하며, 일일 포트레잇 동기화는 UmaTools만 사용합니다.
- 서포트 선택 목록은 SSR만 표시합니다. SR/R 원본 데이터와 획득 관계는 DB에 보존합니다.
- 선택한 계승 고유기의 제공 우마무스메와 의상명은 하단 습득 경로에 표시합니다.
- 육성 우마무스메·SSR 서포트 선택창에는 해당 의상·카드의 포트레잇을 표시합니다. 이미지가 없어도 선택·계산은 가능합니다.
- 개화에 따라 저레어 의상의 원본/승격 고유기 ID와 최종 고유 Lv4~6을 구분하고 효과별 배율을 반영합니다.
- 진화 분기와 원본 관계를 보존합니다. 획득 가능한 원본에 적용되는 진화 후보를 구성하고 금색 원본은 중복 표시하지 않습니다.
- 흰 인자 후보는 일반 흰 스킬 ID로 구성합니다. 별도 인자 마스터·인자 ID·부모 개체·프렌드 검색은 필요하지 않습니다.
- 원본의 `unreleased` 지역 배열에 `en`/`ko`가 있다는 이유로 JP 스킬을 제외하지 않습니다.
- 효과의 대상·스케일·추가 발동과 조건·시간 단위를 원본에 맞춰 보존합니다. 서로 다른 소스의 raw 단위를 임의로 혼합하지 않습니다.
- 흰색 Lv5, 검증된 이벤트 금색의 대성공 힌트, 그 외 금색·계승 Lv0의 표준 가격으로 계산합니다. 진화는 원본 금색 비용이며 ◎·금색은 선행 단계 비용을 포함합니다. 단계마다 정수 내림합니다.
- 알 수 없는 효과·동적 발동 조건은 계산 미검증으로 유지합니다. 현재속도/목표속도/가속의 실전 이득을 임의의 0마신으로 반환하지 않습니다.

## 스킬 최적화 사용

1. 레이스·육성마·시나리오·예상 스탯·총 SP와 편성을 입력하고 `계산하기`를 누릅니다.
2. 본체 고유기는 이미 보유한 효과로 고정됩니다. 나머지는 예산 안의 추천 구매 조합입니다.
3. 속도·가속·스태미나 탭에서 선택을 조정합니다. 체크 해제는 이후 추천 제외이며 `제외 초기화`로 복구합니다.
4. 유지할 스킬의 `고정`을 누릅니다. 고정한 속도 상태에서 나머지 가속·회복을 최적화할 수 있습니다.
5. `선택 조합 계산`은 체크를 유지해 평가하고, `스킬 최적화`는 고정·제외·예산·이벤트 조건을 지켜 다시 추천합니다.
6. 습득 경로에서 카드·인자·계승 제공 육성마와 구매 비용을 확인합니다. 이벤트 선택지 고정은 조건 계산으로 적용합니다.
7. 최종 목록을 확인하고 `텍스트 저장`으로 구매·인자·계승·이벤트 계획을 저장합니다. 변경 미계산 상태에서는 저장할 수 없습니다.

보유·렌탈 추천 모드는 보유 SSR을 이 브라우저에 저장합니다. 렌탈 최대 1장, 타입 장수 합계 6,
고정 카드를 지키며 소수 편성을 실제 스킬 조합으로 비교합니다. `타입 장수 제한 없음`도 지원합니다.
현재 6개 편성을 비교하고 적용 후 더 넓은 스킬 탐색을 수행하므로 간이 비교와 적용 결과가 다를 수 있습니다.
편성 추천은 같은 입력 스탯·SP에서의 스킬 확보 비교이며 훈련 성능을 평가하지 않습니다.

마신은 같은 발동 표본의 추가·제외 주행 비교이며 복합 스킬의 효과·비용은 한 번만 적용합니다.
본체·일반과 계승 TOP 10의 스크롤 프레임, 펼친 가속 표·그래프·HP 검토는 유지합니다.
계승은 속도·가속 각각 TOP 10 후보, 실제 구매 합계 6개입니다. 회복은 HP 기여 기준입니다.
표시에서 이득이 사라져도 사용자가 선택·고정한 구매 항목은 가격·최종 목록에서 숨기지 않습니다.
단계 선행 비용과 연동 선행 스킬도 실제 구매 비용에서 보존합니다.

최대는 예산 내 중앙 발동 이득, 안전은 5개 표본의 최저 이득을 비교하며 HP 충족 조합을 우선합니다.
후보가 작으면 완전 탐색, 큰 집합은 후보 축소·beam 탐색입니다. 전역 최댓값을 보장하지 않습니다.
고정만으로 예산을 넘거나 이벤트가 충돌하면 고정을 해제하지 않고 원인을 표시합니다.
종반 기여가 없는 초반 전용 가속은 종반 가속 추천에서 제외합니다.

## 지원 범위와 남은 검증

공식 챔미 프리셋, 시나리오의 링크·특수 획득 경로·진화 선택 제한, JP 사전 수록 스킬의 출시/해방,
반복/가변 스킬, 최신 전개스퍼트, HP 부족 시 스퍼트 재선택은 추가 검증이 필요합니다.
순위·추월·게이트 등은 조건 성공 가정이며, 발동 가능한 거리 구간에서 5개 위치 표본을 사용합니다.
계산 미지원 스킬은 0마신으로 표시하지 않고 제외된 효과 수와 이유를 제공합니다.
목표 능력치는 1~3000 정수로 입력할 수 있습니다. 스피드 2000 초과도 입력값을 자르지 않고 일반 속도·스퍼트·HP 식에 반영합니다.
추가 전개 스퍼트는 미검증이므로 제외하며 해당 입력의 마신과 HP는 **전개 스퍼트 제외 추정**으로 표시합니다.
미국 코스 출발 좌표는 계속 계산을 차단합니다.
의욕 반영 원본 지능과 시작 능력치 효과에 따른 금색·진화·본체 고유기의 목표속도/자연 감속형 현재속도 보정을 발동 구간별로 반영합니다. 흰색·계승형은 제외합니다.
지능 구간 난수·내리막 모드·포지션 킵·몸싸움·경쟁·디버프는 미반영입니다.
스태미나는 최속 스퍼트 유지에 필요한 HP를 검토하며, HP 부족을 실제 완주 불가로 단정하지 않습니다.
순수 회복 흰 스킬도 회복 목록에서 선택하고 하단 인자 준비 경로를 확인할 수 있습니다.

[수식·출처·표본·검증 명세](docs/ENGINE_VALIDATION.md)에 지원 범위와 검증된 사례를 기록했습니다.
DB 전체의 `calculation_status`는 아직 `unvalidated`이며, 엔진 결과별로 지원/성공 가정/미지원 상태를 별도로 판정합니다.

## 검증 명령

```sh
python -m unittest discover -s tests -v
node --test tests/*.test.mjs
python scripts/validate_data.py
python scripts/build_pages.py
```

Pages 배포 파일은 `.cache/pages/`에 생성됩니다. 상대 경로를 사용하므로 `/umaBoard/` 하위에서도 데이터와 계산 worker가 로드됩니다.
`build_pages.py` 기본 검증은 캐시에 있는 이미지만 포함합니다. 최초 다운로드와 실제 배포에는 `--fetch-portraits`를 사용합니다.

## 구조

| 경로 | 내용 |
| --- | --- |
| `assets/` | 실제 후보·조건/획득 경로·단독 비교 엔진·worker·결과 화면 |
| `prototype/` | 결과 레이아웃과 fixture 엔진 |
| `scripts/umaboard/` | 수집, 소스 어댑터, 검증, 활성 묶음 교체 |
| `sync-config.json` | 정기/고정 소스와 검증 기준 |
| `curated/rules.json` | 출처를 명시한 보완 관계와 검증 대기 목록 |
| `data/manifest.json` | 현재 활성 묶음, 출처 commit/blob, 해시와 어댑터 버전 |
| `data/bundles/` | 정규화 데이터와 동일 버전의 검증 결과 |
| `data/portraits.json` | UmaTools 전용 의상·SSR 이미지 목록, 출처 commit/blob, 누락 ID |
| `docs/` | 수집 설계, 조사 기록, 엔진 연결 계약 |
| `tests/` | 정규화·실패 복구·실제 후보·속도/가속/HP·추천 정책 검증 |
